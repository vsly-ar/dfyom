# Research: alignment between setups, tiling and split parts

Status: draft (2026-11-23; research for the user's request of 2026-11-23, Telegram) · Proposal: [plans/proposal-multi-setup-alignment.md](../plans/proposal-multi-setup-alignment.md) · Base: [plan-v0.2.md § Setups](../modes/plan-v0.2.md#setups-from-face-directions), [workholding.md](../modes/workholding.md), [run.md § Safety](../modes/run.md#safety) · Terms: [glossary.md](../glossary.md)

The user asked for a plan for (1) repositioning a stock larger than the working area, (2) cutting one part from several stocks, and alignment and zeroing tools between setups that also help classical parts turned or flipped on one stock. The user's own idea: a new setup names its work zero plus **alignment points** (edges, corners, points cut before); after zeroing, DFYOM moves the spindle above each point at safe Z, the operator adjusts the stock, jogs Z, steps previous/next and confirms; probing when available; and **plan-only alignment cuts** (holes, side notches, cuts into the supporting material, V-bit marks – a V-bit last in setup N and first in setup N+1 needs no extra tool change). Splitting one part across stocks is a design concern (margins, joint placement).

This note collects what controllers, senders and CAM programs offer, what hobby users do, and the accuracy to expect; [§ E](#e-a-unifying-model-for-dfyom) maps it onto DFYOM and [§ Recommendation](#recommendation) ranks the options. Facts carry their source; "not verified" marks claims no primary source confirmed.

## Where DFYOM is today

- A plan has one setup per approach direction, each with its own WCS: `G54` at the **front-left corner of the up-facing stock face**, Z0 on that face, rotation 0/90/180/270° ([plan-v0.2.md](../modes/plan-v0.2.md#setups-from-face-directions)). Each setup exports its own program; Run shows a setup-change prompt where the operator re-fixtures and sets the zero by jogging to that corner ([§ Implementation (task E2)](../modes/plan-v0.2.md#implementation-task-e2)).
- So every setup's zero comes from the **stock's own corner**, not from anything the earlier setup cut: a sawn or uneven stock edge, a stock not square to the axes, or a flip about an axis that is not exactly where the operator assumes, all show up as a step between the sides. There is no in-process stock ([plan-v0.2.md decision 1](../modes/plan-v0.2.md#decisions)).
- `run.workZero.set { axes, values? }` already writes `G10 L20 P1` with given work coordinates at the current position ([run-v0.1.md](../modes/run-v0.1.md#commands-and-queries)): "set the zero so that **this** point is (x, y)" exists as a primitive.
- The real-machine lane (hardening, branch `machine-lane`, `modes/run-machine.md` draft) adds a serial GRBL connection, a Z touch-plate probe (`run.machine.probeZ`, `G38.2`, `plateThickness` as a machine field) and the rule that machine-moving commands on a real connection come **from the UI only** (Q50, [run.md § Safety](../modes/run.md#safety)).
- Workholding per setup (draft, [workholding.md](../modes/workholding.md)) has a `base` item (`spoilboard`, sacrificial, or `fixturePlate`) – what cuts into the supporting material need.
- Snap and measure exist in the Shape Editor and the viewport (stock corners and edges, shape points, [design-v0.3.md § Measure and snap](../modes/design-v0.3.md#measure-and-snap)): the picking a reference needs.

DFYOM's own emulator implements exactly GRBL's subset ([grbl.md](../architecture/grbl.md)).

Senders:

- **bCNC "Orient"** – the closest existing design to what DFYOM needs: N ≥ 2 marker pairs (machine position ↔ G-code position, typically found with a camera), a least-squares fit of `[x −y 1 0; y x 0 1]·[c s xo yo]ᵀ = [xm ym]`, the fit refused when `|√(c²+s²) − 1| > 0.1` ("too skew"), φ = atan2(s, c), min/average/max residual per marker, then the G-code is transformed. It deliberately solves rotation and offset only, not skew, because arcs would turn into ellipses ([bCNC `GCode.py` class `Orient`](https://github.com/vlachoudis/bCNC/blob/master/bCNC/GCode.py), [bCNC wiki: orientation of gcode](https://github.com/vlachoudis/bCNC/wiki/Tutorials:-Orientation-of-gcode)).
- **ioSender** (grblHAL's sender) rotates the program in the sender from a probed angle; an open request with known artefacts on arcs ([issue #94](https://github.com/terjeio/ioSender/issues/94)).
- **UGS** has a `RotateProcessor` for any angle (arcs expanded into lines first), but the UI exposes only 90°/270° turns; its probe module has XYZ corner, outside XY, Z and hole centre ([`RotateProcessor.java`](https://github.com/winder/Universal-G-Code-Sender/blob/master/ugs-core/src/com/willwinder/universalgcodesender/gcode/processors/RotateProcessor.java), [UGS usage](https://github.com/winder/Universal-G-Code-Sender/wiki/Usage)).
- **gSender** probes X/Y/Z/XY/XYZ with a touch block, AutoZero or a 3D probe; no stock-angle measurement or program rotation in its source; "Squaring" calibrates the machine, not the stock ([gSender source](https://github.com/Sienci-Labs/gsender)).
- **CNCjs** (`cncjs-kt-ext`) does Z auto-levelling only ([kt-ext](https://github.com/kreso-t/cncjs-kt-ext)).
- **Carvera Community Controller** probes an angle and sets a WCS rotation ([WCS rotation](https://carvera-community.gitbook.io/docs/controller/features/wcs-rotation)).
- **Fusion** has WCS probing operations (Z surface, X wall, XY outer corner, "Angle along Y" with a point spacing, boss, hole) that update the WCS on controllers whose post supports it and can stop when the measured angle is out of tolerance; Part Alignment fits a transform from probed points ([Probe WCS](https://help.autodesk.com/cloudhelp/ENU/Fusion-CAM/files/MFG-PROBE-WCS-OVERVIEW.htm), [probe types](https://help.autodesk.com/cloudhelp/ENU/Fusion-CAM/files/GUID-61123A95-8828-4214-A8FE-5A4DD1C2EE4F.htm), [Part Alignment](https://help.autodesk.com/cloudhelp/ENU/Fusion-CAM/files/MFG-PART-ALIGNMENT.htm)). It relies on `G68` or controller-side rotation; GRBL posts cannot use it.

**Gap:** no hobby CAM found plans alignment references or aids as part of the job; senders that compensate do it from markers the user picks at run time. DFYOM is both CAM and sender, so it can do what neither side does alone: know in Plan which already-cut geometry is a good reference, cut aids on purpose, and use them in Run.

### Error sources

- **Machine squareness** dominates: a gantry or frame out of square by ~3 mm made tiling impossible; a tile ~3 mm off in X was traced to a parallelogram frame or a fence not parallel to the axis ([Onefinity forum](https://forum.onefinitycnc.com/t/is-your-router-frame-a-parallelogram-mine-was/6086), [Onefinity tiled cut](https://forum.onefinitycnc.com/t/tiled-cut-issues/6298)). A fence parallel to a non-square axis still turns the stock.
- **Stock**: bowed or cupped stock, edges not straight ([Inventables](https://inventableshardwaresupport.zendesk.com/hc/en-us/article_attachments/36382878655764)).
- **Pin fit**: play in the hole shows as a step ([Carbide forum](https://community.carbide3d.com/t/improving-results-when-two-sided-machining-using-locating-pins/27012)); industrial ground pins repeat to ±0.0005″ ([WOODWEB](https://woodweb.com/knowledge_base/Pin_Indexing_for_TwoSided_Drilling.html)), hobby fits in MDF much less (not measured).
- **Z**: each tile is re-zeroed on the (uneven) stock top; seams in V-carving show depth differences.

### Splitting toolpaths by tile

- **Ownership:** every region of the part is cut by exactly one tile. Vectric clips at the tile edge plus the overlap; to avoid cutting twice DFYOM should put an **ownership boundary** in the middle of the overlap and give the overlap only to the alignment aids and to the reach margin.
- **Regions** (pocket, facing): clipped to the owned region, overlapping the seam by a fraction of a millimetre so no ridge remains.
- **Profiles:** split at the boundary; the lead-in and lead-out of each piece go inside the overlap (where the other tile already cut or will cut), never on the part edge. Containment that disables leads (Fusion workaround) leaves plunge marks.
- **Holes and tabs:** a hole belongs to the tile holding its centre; tabs never on a boundary; a through profile's last tile holds the part.
- **Travel:** each tile's program must fit the travel at its own zero; the window is the travel minus a margin.

### The user's proposed flow, checked

1. **Pick the work zero** (as today) **plus alignment points** that exist already (cut in an earlier setup or a stock feature) – feasible: Plan knows which operations ran in earlier setups (machining order) and where their vertices, edges and holes are in the new setup's frame (`setupFrame`, [plan-v0.2.md § Implementation (task C3)](../modes/plan-v0.2.md#implementation-task-c3)). No in-process stock is needed.
2. **After zeroing, DFYOM moves to the first point at safe Z** – feasible with the existing jog/move machinery; it is motion, so on a real machine it is UI-only (Q50) and should run with the spindle off.
3. **The operator adjusts the stock** so the point lies under the tip, **jogs Z** to look closely, steps previous/next, confirms – good for a V-bit tip and a V mark (self-centring to the eye). Two refinements: (a) show the **measured error** when the operator instead jogs to the point and presses "Record" – reading the error is often easier than nudging a clamped stock by 0.1 mm; (b) **zero from a reference** (`G10 L20` at the point) so a mark replaces the stock corner as the XY datum.
4. **Probing when available** – edge, corner and hole cycles with `G38.2`; a Z touch plate is the common hobby probe (hardening M4), XYZ corner plates and 3D probes are less common.

### Rotation compensation by two (or more) points

With expected points `P₁, P₂` (setup frame) and measured `M₁, M₂` (work or machine coordinates):

- θ = atan2(M₂ − M₁) − atan2(P₂ − P₁); offset `O = M₁ − R(θ)·P₁`. The difference `|M₂ − M₁| − |P₂ − P₁|` is a consistency check (the machine has no scale error to fix; a large value is a wrong point or a mis-jog).
- Angle resolution ≈ point error / spacing: two points 200 mm apart measured to ±0.1 mm give ±0.03°; 50 mm apart, ±0.11° (≈ 0.4 mm over 200 mm). **Space the points as far apart as the stock allows.**
- With ≥ 3 points: least-squares rigid fit (2D Kabsch/Procrustes, or bCNC's linearised similarity fit with the scale checked) and the worst residual as the gate.
- **Applying it on GRBL:** no `G68`, so the program is turned about the work zero before streaming: positions and `I`/`J` arc offsets rotate, Z, feeds and arc senses stay (a rotation keeps arcs arcs; only a skew would make ellipses). DFYOM already turns toolpaths by quarter turns this way (`turnToolpath`, [plan-v0.2.md § C3](../modes/plan-v0.2.md#implementation-task-c3)); an arbitrary angle is the same transform. The soft-limit and collision checks must run on the turned program.
- **Without compensation**, the operator physically turns the stock until both points read within tolerance – workable for small, light stock; painful for clamped sheets.

### Accuracy to expect (estimates, not measured)

Published machine figures are sparse: Shapeoko 5 Pro ballscrews ±50 µm per 300 mm ([specs](https://carbide3d.com/shapeoko/shapeoko5pro-specs/)); LongMill MK2 about ±0.1–0.2 mm (Sienci FAQ, seen in a search snippet only); no manufacturer publishes a homing repeatability or a touch-plate / hobby 3D-probe accuracy (reseller claims of 0.01 mm are not verified). The figures below are therefore engineering estimates to be measured in the phase 1 exit.

| Method                                      | Expected XY error on a hobby router        | Basis                                                                        |
| ------------------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------- |
| Jog to a sawn stock corner by eye           | 0.3–1 mm                                   | stock edge quality, parallax; Onefinity/Easel reports of mm-level seams      |
| V-bit tip lowered into a V witness mark     | 0.05–0.2 mm                                | a 90° V mark 0.5 mm deep is 1 mm wide; the eye centres a cone in a cone well |
| Dowel pins in CNC-drilled holes             | 0.05–0.3 mm                                | hole fit in MDF/plywood; pin play reported as steps (Carbide forum)          |
| Edge finder / touch plate on an edge        | 0.02–0.1 mm                                | probe repeatability plus machine backlash                                    |
| 3D probe, hole centre                       | 0.01–0.05 mm                               | probe repeatability; frame flex dominates                                    |
| Any method, if the machine is out of square | errors grow with distance (mm over a tile) | Onefinity parallelogram thread                                               |

## C. Plan-only alignment operations (alignment aids)

| Aid                                                       | Cut in setup N                                                                                                            | Used in setup N+1                                                        | Notes                                                                                                                           |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **V-bit witness mark** (spot or short line)               | V-bit plunge (a cone of Ø = 2·d·tan(α/2)) or a short line across an edge, in waste or on an edge that is chamfered anyway | The same V-bit (still in the spindle) lowered into it by jog             | Cheapest; no extra tool change when the V-bit is last in N and the pointer in N+1 (the first tool change of N+1 happens anyway) |
| **Edge mark** (a notch across the edge between two faces) | V-bit or end mill notch on the edge shared by the two setups' up faces                                                    | Visible from the turned setup as a notch in its edge                     | The only mark both setups of a 90° turn see                                                                                     |
| **Registration hole** (through, into the spoilboard)      | Drilling or helical bore through the waste, depth = stock + spoilboard depth, Ø for a dowel                               | Dowels through stock into the spoilboard hole; or visited as a reference | Needs a sacrificial `base`; symmetric about the flip axis or on it; 3 holes or an asymmetric pattern prevent a wrong flip       |
| **Side notch / step**                                     | A pocket or profile cut into the stock side (waste)                                                                       | Probed or touched as an X or Y edge                                      | Good for probing; the notch's wall is a machined, square edge                                                                   |
| **Spoilboard pocket / fence**                             | A shallow pocket or fence cut into the spoilboard (no stock), the stock pushed into it                                    | The stock's datum edges sit against the cut fence                        | A fixture operation: it cuts only the base; needs the base's top as its Z reference                                             |
| **Datum edges**                                           | A profile or facing that squares two stock sides                                                                          | Pushed against a fence or vise; or referenced as edges                   | Often already in the design (the part's own outline); a reference, not an aid                                                   |

Sequencing and safety:

- **Order:** an aid must run in a setup **before** every setup that references it; marks for the next setup run last in their setup (with the V-bit), registration holes early (before the part is cut free).
- **Into the supporting material:** only with a sacrificial base, with a capped depth; never into a fixture plate (collision check, [workholding.md WH-E](../modes/workholding.md#decisions)).
- **Waste only:** aids outside the part outline (or on edges the design chamfers anyway); a DFM-style finding when an aid cuts the part.
- **Tool:** a V-bit mark needs a pointed V-bit (tip Ø 0); a flat-tipped one marks a ring.
- **Presentation:** aids are plan operations of their own kind and colour, named for what they are for ("Witness mark for Bottom").

## D. Splitting one part across several stocks

- **No hobby CAM found** splits a part into jointed pieces automatically; Vectric tiling splits toolpaths only, puzzle shapes come from external generators ([Vectric case study](https://vectric.com/vectric-community/case-study/ToddDPuzzleFun)); Fusion's Slicer (interlocking slices) is deprecated ([Autodesk](https://knowledge.autodesk.com/support/fusion-360/troubleshooting/caas/downloads/content/slicer-for-fusion-360.html)).
- **Joints for flat pieces:** butt with dowels (dowel holes are registration holes for assembly), puzzle / dovetail key, butterfly (bow-tie) inlay, half-lap; finger joints and tenons for perpendicular pieces need **dogbone or T-bone** reliefs in router-cut inside corners ([Make: CNC panel joinery](https://makezine.com/article/workshop/cnc-panel-joinery-notebook/), [dogbones](https://fablab.ruc.dk/more-elegant-cnc-dogbones)). Puzzle joints need a test-cut fit clearance (practitioner reports).
- **Margins:** each piece's stock needs a margin per side for uneven raw material and for holding (the user's point); the margin is waste, so screws and aids can go there.
- **Joint placement** is the user's design decision; DFYOM can help with a DFM check: features cut by or near a split line, small slivers, joints crossing thin walls.
- **Layer splits** (a thick part as glued layers) align with dowel holes through each layer – registration holes again.
- **Nesting** the pieces onto stocks (rotation, spacing for the tool) is a separate, later concern.

No Run-mode alignment is needed: each piece is an ordinary part.

## E. A unifying model for DFYOM

| Concept              | Proposal                                                                                                                                                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Alignment reference  | On a setup: `{ id, kind: point \| hole \| edge, source, probe? }`; `source` = stock corner/edge, a surface vertex/edge/hole of an operation in an earlier setup, or an aid. The expected position in the setup frame is derived. |
| Validity             | "Already cut" from the machining order; "reachable" from the setup's direction (on the up face or one of its edges); inside the travel at the setup's zero                                                                       |
| Alignment aid        | A plan operation with `source: 'aid'` (witness mark, registration hole, notch; later fixture cuts), in a setup before the references to it, kept across rebuilds                                                                 |
| Run alignment step   | In the setup-change prompt after (or instead of) the zero: visit each reference at clearance height, jog Z, previous/next, "Record" shows the error, tolerance gate, confirm; "Set zero from this point" (`G10 L20`)             |
| Compensation (later) | Fit (1 point: shift; 2: shift + angle; ≥ 3: least squares + residual); G54 from the fit; angle by turning the program in the post; checks rerun; a run artefact, not a plan change                                               |
| Probing (later)      | Machine `probe.kind` (Z plate today; XYZ plate geometry; 3D probe tip Ø); edge, corner and hole cycles with `G38.2`                                                                                                              |
| Tiling (later)       | Setups of one direction with a stock `shift` and a `window`; ownership boundary in the overlap; toolpaths split; overlap aids added automatically                                                                                |
| Split parts (later)  | A design feature; pieces as parts with their own stocks and margins; joints; DFM near split lines                                                                                                                                |
| Agent API            | Plan commands for references and aids for every source; the step's motion is UI-only on a real machine (Q50), agents read its state and errors and run it fully on the virtual machine                                           |

Safety notes: the step moves the spindle to where the operator's hands are about to be – **spindle off** (checked like Probe Z), motion only on a click, at clearance height, Z only by jog, Stop always available; aids into the spoilboard only with a sacrificial base; a turned program re-checked against travel and workholding.

## Comparison of methods

| Method                                      | Accuracy (hobby router)   | Effort for the user                           | Needs a probe    | Needs spoilboard holes | Fit with DFYOM's model                               |
| ------------------------------------------- | ------------------------- | --------------------------------------------- | ---------------- | ---------------------- | ---------------------------------------------------- |
| Zero on the stock corner each setup (today) | low (0.3–1 mm)            | low                                           | no               | no                     | exists                                               |
| V-bit witness marks + visit step            | good (0.05–0.2 mm)        | low; no extra tool change with the V-bit rule | no               | no                     | high: an aid + a reference + the Run step            |
| Registration holes + dowels                 | good (0.05–0.3 mm)        | medium (dowels, holes in the spoilboard)      | no               | yes                    | high: drilling exists; needs `base` from workholding |
| Zero from a reference (`G10 L20` at a mark) | as the mark               | lowest of the precise ones                    | no               | no                     | primitive exists (`run.workZero.set { values }`)     |

## Recommendation

1. **Alignment references + V-bit witness marks + the visit step + zero from a reference** (phase 1). Best accuracy per effort, no new hardware, no new toolpath geometry, and it is the user's own flow. Add "Record" with the measured error so the operator can read it instead of nudging.
2. **Registration holes** in the same phase (drilling exists), gated on a sacrificial base – the most common hobby practice for flips and tiling.
3. **Measured compensation** (phase 2): translation and rotation from two or more points, the program turned in the post, as bCNC's Orient does, with DFYOM's checks rerun.
4. **Probing** (phase 3) once the touch-plate work is merged; most valuable for side notches and holes.
5. **Tiling** (phase 4) on top of 1–3: a setup shift, an ownership boundary and automatic overlap aids – no hobby CAM offers alignment help here, so this is where DFYOM can stand out.
6. **Split parts** (phase 5), a design feature independent of the alignment work; until then the user designs the pieces as separate parts.

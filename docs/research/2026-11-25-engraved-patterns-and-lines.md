# Engraved patterns and variable-depth lines

Status: draft (research and spike report, 2026-11-25; hardening [DF112, DF113](../plans/hardening.md#intake-user-feedback-goes-here), user TG #352) · Design: [engraved-patterns.md](../modes/engraved-patterns.md) · Builds on: [patterns.md](../modes/patterns.md) (lattices), [edge-chamfers.md](../modes/edge-chamfers.md) (V-bit toolpaths), [shapes.md § SVG import](../architecture/shapes.md#svg-import) · Terms: [glossary.md](../glossary.md)

Question: how do CAM tools cut a curved line whose depth changes along its path, how can an SVG carry that depth so users can author it, and what does DFYOM need to cut it? The user asked for "an engraved pattern and an operation it will need: a Line. The Line may be curved and have different depth across its path … by SVGs (where depth is encoded in color or brightness)", with typical presets and "a few circular ones (for a round surface)".

## Summary

- **No mainstream hobby CAM reads depth from an SVG stroke.** Vectric, Carbide Create and Estlcam set one depth per toolpath. Users split artwork by depth into layers or groups with one toolpath each, or model a 3D surface and project the lines onto it ([Carbide 3D forum](https://community.carbide3d.com/t/carving-smooth-lines-with-varying-depth/58703), [V1 Engineering forum](https://forum.v1e.com/t/estlcam-feature-request-auto-gen-engraving-depth-based-on-svg-stroke-width-thickness/41477)). Colour → depth exists in laser software ("engrave by colour", raster depth maps). For CNC it is a gap, and DFYOM can fill it simply.
- **Two CAM ideas carry over directly.** Vectric's **Fluting** toolpath ramps depth along a vector, start → end, linear or smooth ([Vectric docs](https://docs.vectric.com/docs/V12.5/Aspire/ENU/Help/form/Fluting%20Toolpath/index.html)). Fusion's **Trace** follows a 3D curve with an axial offset and multiple depth passes ([Autodesk help](https://help.autodesk.com/cloudhelp/ENU/Fusion-CAM/files/2D-TRACE-READ.htm)). A Line operation is Trace along a 2D path with Z taken from a depth profile.
- **The SVG encoding that survives editors is a per-element level.** Stroke darkness (black = deepest) for drawing, a `data-level` attribute for exact values and start → end stops. Inkscape 1.4.4 keeps `data-level` in both its own and plain-SVG output (checked in this spike). SVG has no colour gradient _along_ a path; a linear or radial gradient is a spatial ramp, usable later.
- **Spike E0 works end to end on the existing importer.** Three differently coloured pieces chained into one line, mapped to 1.5 / 0.85 / 0.52 mm, cut in two passes with a 10° ramp-back entry and helical blends at the colour changes. The GRBL post gives 36 lines. 13 preset SVGs import cleanly.

## How CAM tools engrave lines

| Tool / mode                                                                                                          | Depth along a line                                                                                                                                                                                             | Notes for DFYOM                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Vectric Quick Engrave / Profile "on"                                                                                 | One depth per toolpath                                                                                                                                                                                         | DFYOM's profile `side: 'on'` with a blind depth is this ([design-v0.3.md](../modes/design-v0.3.md#cut-side-and-open-shapes)) |
| Vectric **Fluting** ([docs](https://docs.vectric.com/docs/V12.5/Aspire/ENU/Help/form/Fluting%20Toolpath/index.html)) | Ramp at start, or at start and end; ramp length as a distance or a percentage; Linear or Smooth profile; ball or V tool                                                                                        | The start → end depth profile, and ramps that _are_ the design rather than an entry move                                     |
| Carveco Fluting ([help](https://support.carveco.com/hc/en-gb/articles/19606618394524))                               | Start and end flute: Linear, Curve or Custom Curve                                                                                                                                                             | Same idea; a custom curve is what a level profile generalises                                                                |
| Fusion **Trace** ([help](https://help.autodesk.com/cloudhelp/ENU/Fusion-CAM/files/2D-TRACE-STEPS.htm))               | Follows a 3D curve's Z; negative axial offset to go below the sketch; multiple depth passes                                                                                                                    | Z from geometry; passes by max stepdown                                                                                      |
| Fusion Project                                                                                                       | Lines projected onto a surface with an axial offset                                                                                                                                                            | The "displacement surface" workaround users build in Blender (Carbide forum thread above)                                    |
| V-carve (Vectric, Carbide Create, F-Engrave)                                                                         | Depth from the _width_ of a closed region (medial axis); a flat-depth limit with a pocket in the middle (Carbide "Advanced V-carve")                                                                           | Different input (closed regions). Stroke width → V-bit depth is the open-line analogue: d = w / (2 tan(α/2))                 |
| Estlcam, Carbide Create, Easel                                                                                       | One depth per toolpath; a feature request for depth from stroke width exists ([V1E forum](https://forum.v1e.com/t/estlcam-feature-request-auto-gen-engraving-depth-based-on-svg-stroke-width-thickness/41477)) | Users group artwork by depth and make one toolpath per group                                                                 |

V-bit geometry (60° → d = 0.866 w, 90° → 0.5 w, 30° → 1.866 w; [Easel forum](https://forum.easel.com/t/v-carve-depth-control/80333)) is the cone rule DFYOM's chamfer mill already uses ([edge-chamfers.md § Toolpath](../modes/edge-chamfers.md#toolpath-plan)).

## Encoding depth in an SVG

| Encoding                                                  | Parser feasibility                                                                                                                                                                                   | Authoring                                                                                                               | Verdict                                                                                                       |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Stroke colour → luminance** (black = deepest)           | Easy: `stroke` attribute or `style`, inherited from groups; `#rgb`, `#rrggbb`, `rgb()`, names. The importer reads `style` already                                                                    | The natural "darker = deeper" mental model; works in every editor; the file previews as what it cuts                    | **Default.** Level = 1 − Rec. 709 luma                                                                        |
| **Distinct colours → a palette** (red = 1 mm, blue = 0.3) | Same parse; group by exact colour                                                                                                                                                                    | The laser "cut by colour" habit (LightBurn layers); robust when users pick colours by meaning, not brightness           | **Legend at import:** each distinct colour gets a level, defaulted from its luminance, editable               |
| **`data-level`** (0..1, one value or stops start → end)   | Trivial; a custom attribute                                                                                                                                                                          | Exact. Inkscape 1.4.4 keeps it on save and in plain-SVG export (checked with the spike sample); its XML editor edits it | **Override** for exact values and tapers (`data-level="0 1 0"` fades in and out)                              |
| **Per-segment colour**                                    | Not in SVG: one stroke paint per element                                                                                                                                                             | Draw a line as several elements whose ends meet, each its own colour                                                    | **Chaining:** elements whose ends meet (≤ 0.01 mm) form one line; level steps are blended over a short length |
| **Stroke width** → V-bit depth                            | Easy (`stroke-width`, inherited; scaled by the transform)                                                                                                                                            | Matches a V-carve habit (wide = deep). Breaks with non-uniform scaling and with editors that set a hairline width       | **Option** (`levels: 'width'` at import), off by default                                                      |
| Gradient along a path                                     | Not in SVG ([W3C issue, 2024](https://lists.w3.org/Archives/Public/public-svg-issues/2024Jul/0000.html)); workarounds cut the path into pieces ([bostock](https://gist.github.com/mbostock/4163057)) | Illustrator only                                                                                                        | Not supported; use stops or chained pieces                                                                    |
| `linearGradient` / `radialGradient` on the stroke         | Feasible: the level at a point = the gradient evaluated at its projection (linear) or radius (radial); stops and units to parse                                                                      | Inkscape's gradient tool. A radial ramp suits round parts                                                               | **Later (E5)**; warn `strokeGradientIgnored` until then                                                       |
| `stroke-opacity` / `opacity`                              | Easy                                                                                                                                                                                                 | Ambiguous: it blends with the background. Users expect "fainter = shallower" only sometimes                             | **Ignored** with a warning; luminance is read from the opaque colour                                          |
| Inkscape Power Stroke / Taper Stroke                      | The output is a _filled_ outline, not a stroke                                                                                                                                                       | Popular for calligraphic lines                                                                                          | Out of scope (a closed region; V-carve of regions later)                                                      |

Robust for users: **darker = deeper with a legend**, plus `data-level` for exact values, plus chaining for per-segment changes. The import report lists the colours found and the level each got, so a surprise shows before anything is cut.

## Tools, entries and passes

| Tool                           | Groove width at depth d                | Use                                                                                                                          |
| ------------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| V-bit (chamfer mill α, tip dt) | w = dt + 2 d tan(α/2)                  | **The default.** Depth changes read as width changes, which is the visual effect the user wants. Reach = cutting-edge height |
| Ball end mill (D)              | w = 2 √(d (D − d)) for d < D/2, else D | Soft, rounded grooves (fluting); width saturates at D                                                                        |
| Flat end mill (D)              | w = D                                  | Constant width, depth reads only as shadow; tiny Ø 0.5–1 mm engravers                                                        |

- **Entry.** A pointed V-bit plunges well; a ball or flat end mill should not plunge into hardwood at full depth. Every slope must stay within the ramp angle. **Ramp-back:** go a ramp length _ahead_ along the line at the current floor, then ramp back down to the pass start, then cut the pass over the ramp. This leaves no shallow stretch at the start and needs no extra lead-in geometry (spike: 4.54 mm at 10° for a 0.8 mm first pass). A plunge is allowed for V-bits as an option.
- **Max depth per pass.** Pass k cuts z_k(s) = max(z(s), −k · stepdown). The last pass is the profile. Open lines alternate direction between passes, so there is no return rapid; loops keep one direction. A pass whose start is already at depth needs no ramp (spike pass 2).
- **Slopes in the profile.** The profile itself may be steeper than the ramp angle where a level steps. A **blend** (±1 mm by default) turns a step into a slope. On arcs that gives helical `G2`/`G3` moves with Z, which GRBL supports.
- **Sharp corners.** Path corners stay sharp. A V-bit leaves a mitred corner of the groove's outer edge. GRBL's junction deviation slows the corner. Nothing special is needed. The V-carve "corner flick" is for closed regions (edge-chamfers Q121) and is not needed for lines.
- **Crossings and overlaps.** At a crossing, the second line cuts through the first one's groove. Most of that is air, and the deeper groove wins. No CAM tool avoids this for engraving, so DFYOM doesn't either; the read-out counts crossings. **Coincident** segments (tiles sharing an edge, a motif drawn twice) would cut twice and are removed when a pattern resolves (the deeper one is kept).
- **Surfaces.** Engraving here is 2.5D on flat faces. The user's "circular ones (for a round surface)" reads as **round flat parts** (coaster, lid, box top), not a cylinder: a 3-axis GRBL machine cannot follow a curved surface without a 4th axis or surface probing. Decided by delegation (D70) in the design.
- **Tiling.** Pattern's lattices (square, staggered, hex, polar) and its boundary, margin and whole/clip rules apply unchanged to line motifs, so the engraved pattern reuses them rather than inventing a layout. Two things differ: tiles may touch or overlap (gap ≥ 0, no `patternOverlap`), and lines that meet across tiles are chained so waves run continuously.

## Spike E0

Throwaway code in [`spikes/engrave/`](../../spikes/engrave/), against `src/core` (no app code changed). Run: `npx vitest run -c spikes/engrave/vitest.config.mts --silent=false`; typecheck `npx tsc -p spikes/engrave`; presets `node spikes/engrave/make-presets.mjs`.

- [`sample.svg`](../../spikes/engrave/sample.svg): a black Bézier wave, three pieces `#000` / `#808080` / `rgb(192,192,192)` whose ends meet (a line, an arc, a line), a `data-level="0.1 1"` ramp, and a `#404040` circle given in `style`.
- [`line.ts`](../../spikes/engrave/line.ts): stroke info per element (`#id`, else `tag[n]` as the importer names shapes; `stroke`/`stroke-width` inherited, `data-level` stops), level from luminance, open paths chained end to end, the piecewise-linear depth profile with blends, depth passes, and the ramp-back entry. It emits `G1` and helical `G2`/`G3` blocks for the existing GRBL post.
- [`engrave.test.ts`](../../spikes/engrave/engrave.test.ts): the sample, the presets, and `tools/list` measured.

**The existing importer is enough for geometry.** `importSvg(text, { split: 'element' })` gave 6 shapes (5 open paths, 1 loop). Its 2 Béziers were fitted with 43 arcs (max deviation 0.0071 mm), and every shape's `source.element` (`#seg2`) maps back to its element. It drops paint, so the spike re-reads the XML (`parseXml`) for strokes. E2 carries the stroke on the import result instead.

| Line                   | Levels (min 0.2, max 1.5 mm) | Depth mm      |
| ---------------------- | ---------------------------- | ------------- |
| `#wave` (40 arcs)      | 1                            | 1.500         |
| `#seg1+#seg2+#seg3`    | 1 / 0.498 / 0.247            | 1.500 … 0.521 |
| `#ramp` (`data-level`) | 0.1 → 1                      | 0.330 … 1.500 |
| `#ring` (closed)       | 0.749                        | 1.174         |

**gCode** for the chained line: [`variable-depth-line.nc`](../../spikes/engrave/variable-depth-line.nc), 60° V-bit, stepdown 0.8, ramp 10°, feed 1200, plunge 300. The line is 91.42 mm long. It takes 2 passes: pass 1 ramps back 4.54 mm from Z0 to −0.8 at 10°, and pass 2 runs in reverse from the shallow end, already at depth, with no ramp. Z min is −1.500, the groove is 1.73 mm wide at its deepest, the cut length is 188.6 mm (0.16 min at feed), and the program is 36 lines. The blends come out as helical arcs, e.g. `G2 X54.95 Y24.002 Z-0.847 I-10 J0` and `X35 Y25 Z-1.174 I9.95 J0.998`. Not run on the virtual machine (left for E1's exit).

**Presets:** the 13 files in [`src/core/design/engraving/presets/`](../../src/core/design/engraving/presets/) all import with no warnings and are levelled (table in [engraved-patterns.md § Presets](../modes/engraved-patterns.md#presets)). They were rendered to PNG with Inkscape (tiles repeated 3 × 3, staggered where the preset says) and looked at. One finding came out of that: the wood grain needed periodic curves so its rows join at the tile seams.

**`tools/list`:** 114,720 chars, 141 tools (5.3 K headroom); `design_pattern_add` 3,175, `design_pattern_update` 1,712, `design_profile_add` 3,567.

# Roughing passes: a bigger tool clears the bulk, the operation's tool cleans the rest

Status: accepted (hardening DF122, the user's TG #401 "please plan attaching a roughing operation to most other operations and features that removes bulk of the material that's possible with a selected tool (minus a configurable margin) and main operation's tool only cleans what remains"; accepted 2026-11-26 by delegation D76: [Q139–Q146](#questions-for-the-user) take their recommendations) · Plan of record: [plans/hardening.md](../plans/hardening.md) DF122 · Generalises: [patterns.md § Roughing (DF108)](patterns.md#roughing-df108) (the pattern's `<id>_roughing` pocket and rest machining, built) · Builds on: [plan-v0.3.md § Pocket](plan-v0.3.md#pocket-offset-clearing-of-a-region) and [s4-offset-clearing.md](../research/s4-offset-clearing.md) (rest = region − opening), [plan-v0.1.md § Pass strategies](plan-v0.1.md#pass-strategies-v01) (finishing allowance, finish stepdown), [design-v0.2.md § Auto choice](design-v0.2.md#auto-choice) (tool field), [plan-v0.4.md § Machining order v2](plan-v0.4.md#machining-order-v2) (tool runs), [feeds-speeds.md § Finishing pass feed](../architecture/feeds-speeds.md#finishing-pass-feed-hardening-df74) (DF74) · UI: [inspector-layout.md](../conventions/inspector-layout.md) · Agent API budget: [llm-api.md](../architecture/llm-api.md) · Terms: [glossary.md](../glossary.md)

Today an operation's tool does all of its work. A pocket with R 1.5 corners gets a Ø 3 end mill (the auto choice ranks "leaves no rest material" first), and that Ø 3 then clears the whole pocket in small stepdowns and stepovers. A profile round an outline with tight inside corners is cut level by level with the same small tool. Patterns already solve this for their cells (DF108: an optional roughing pocket with a bigger tool, then the pattern's pocket cuts only the rest, −20 % on a 10 mm honeycomb). This doc makes that pass available to the operations that remove bulk material, with its own tool and a configurable margin on walls and floor.

## Goals

- **Faster programs for the same part:** the bulk goes with the biggest tool that fits (bigger stepdown, stepover and feed), the operation's tool cuts only what the bigger tool could not reach plus the margin.
- **Same part, same walls:** the operation's finishing pass, its tool and its feeds are unchanged; the finished geometry is identical with and without roughing.
- **Off by default, byte-equal goldens:** no program changes unless roughing is turned on.
- **One model** for patterns, pockets and profiles, so the pattern's DF108 code becomes the shared code, not a second copy.
- **Tiny agent API:** one field on existing tools; the roughing tool is set with the existing `design.operation.tool.*`.

## Which operations get a roughing pass

Decided per kind, by where the bulk is and whether a bigger tool can reach it ([Q139](#questions-for-the-user) picks the first version's set):

| Kind / feature                                      | Roughing | Why                                                                                                                                                                                                                                                                      |
| --------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Pocket** (plain, any shape, blind or Through)     | yes      | The main case: area × depth of material, and the tool is often small because of the corners or a floor fillet. Rest = the corners and narrow necks the bigger tool cannot enter, plus the margin.                                                                        |
| **Pattern** (feature)                               | yes      | Built (DF108); moves onto this model with margins ([§ Patterns](#patterns)).                                                                                                                                                                                             |
| **Profile, `inside` / `outside`** (through or step) | yes      | Deep profiles with a small tool (tight inside corners of the outline) are cut level by level; a bigger tool takes the levels, the small tool the corners and its finishing pass. Needs path clipping to pay off ([§ Rest by the operation](#rest-by-the-operation), R3). |
| Profile, `on` (groove along a path)                 | no       | The groove is the tool's width (or `slotWidth`): no bulk beyond the slot, and a bigger tool would widen the groove.                                                                                                                                                      |
| Facing                                              | no       | Already the biggest tool and a thin layer; a separate floor finish is a different topic (finishing passes for facings, later).                                                                                                                                           |
| Drilling (drill or helix)                           | no       | A drill removes its hole in one plunge cycle; a helix bore's tool is already chosen to the bore. A large round opening is better a circle pocket, which gets roughing.                                                                                                   |
| Chamfer (circular or edge chamfer)                  | no       | A V-bit or chamfer mill takes a small triangle of material; there is no bulk and a flat tool cannot make the bevel.                                                                                                                                                      |
| Line, Engraving (feature)                           | no       | Centreline grooves whose width is the cutter's; clearing wide V-carve areas with a flat end mill first is a V-carve strategy of its own (later, with the carving work).                                                                                                  |
| Bolt hole (feature) recess / counterbore pockets    | later    | Owned pockets of a feature, usually Ø 8–20: the drill and end mill are close in size, so a roughing tool rarely pays. Comes when asked ([Q146](#questions-for-the-user)).                                                                                                |
| Clones (feature), split pieces                      | follow   | A Clones instance and a split piece repeat their source's operations, so they repeat its roughing too (R5).                                                                                                                                                              |

Pockets and profiles carry nearly all bulk volume of the parts DFYOM makes today, so "most operations" in volume is these two plus patterns.

## Model

**A roughing setting on the operation that owns a roughing operation** ([Q140](#questions-for-the-user)), the pattern's model generalised:

- **Setting:** `roughing?: { wall?: Quantity; floor?: Quantity }` on a pocket or an `inside`/`outside` profile, stored only when on (absent = off, so no existing record changes; no `schemaVersion` bump, pre-alpha rule). `wall` and `floor` are the **stock to leave** of the roughing pass (absent = the defaults below).
- **Owned operation:** while on, the operation owns **`<id>_roughing`** (`pocket1_roughing`), a design operation of the same kind with `roughing: true` (the DF108 flag, now set by any roughing owner) and `roughingOf: '<id>'`. Its `on`, shape, depth, Through, floor radius, side and tabs are the owner's, kept in sync by the owner's add/update and by recalculation (as a feature's owned operations and a chamfer's `on`); it is edited only through its owner, except its **tool field** (A4: own auto choice, lock, `design.operation.tool.*`). Turning roughing off or removing the owner removes it (one undo step).
- **Geometry:** it removes nothing of its own (its region is the owner's), its floor is no face target, material bands, through depths and construction surfaces ignore it (DF108).
- **Why an owned operation, not a second toolpath inside the owner's plan operation:** it gets everything an operation has for free: its own tool field and auto choice, its own plan operation with strategy, feeds and checks, its place in a tool run, its row in the navigator and the setup list, plan-only edits, labels and program comments ("Pocket 1 · roughing"). A second toolpath per plan operation would need a second tool per plan operation everywhere (tool changes, feeds, checks, Run's tool list).

### Tool: automatic, or the user's choice

[Q141](#questions-for-the-user). The roughing operation's tool field works as every tool field ([design-v0.2.md § Auto choice](design-v0.2.md#auto-choice)): **Auto** by default, locked by any user choice.

- **Fit** (`toolFit`, DF108's rules generalised): a flat or bull-nose end mill (bull nose with RE = the owner's floor radius, as pockets); it must enter the region somewhere (rule `width`; a profile: the slot or opening), and its Ø is at most **0.6 × the region's narrowest width** (rule `roughingWidth`; a profile: no width rule beyond the opening, an outside profile has none): a tool that only just fits clears a thin centre line and saves nothing. No corner rule; rest material is expected, so `dfm.restMaterial`, `dfm.cornerTooSmall`, `dfm.pocketNoToolFits` and `plan.restMaterial` are reported for the owner only.
- **Auto choice:** the **largest** fitting end mill, library first (the existing ranking minus "leaves no rest material", which roughing never meets), else the largest generalized tool of the standard series, as today.
- **No gain:** a roughing tool not larger than the owner's tool skips nothing; `dfm.roughingNoGain` (warning on the roughing operation, field `tool`: "The roughing tool (Ø 3) is not larger than the pocket's (Ø 3): the pocket still cuts everything. Choose a larger tool or turn Roughing off."). The DF108 "Later" note, now built in R1.

### Stock to leave: wall and floor

[Q142](#questions-for-the-user).

| Margin          | Default                                                                                                                                                         | Range                                                                                                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wall` (radial) | the owner's resolved **finishing allowance** (0.2 mm / 0.008″, wood 0.5 mm / 0.02″; [plan-v0.1.md](plan-v0.1.md#pass-strategies-v01))                           | ≥ 0; ≥ the owner's finishing allowance (warning `plan.roughingWallThin` below it: the owner's finishing pass would cut the roughing's scallops at its allowance, not the allowance) |
| `floor` (axial) | **0** for pockets and profile steps (a flat end mill cuts the floor to size, as DF108); **0.5 mm / 0.02″** skin above the stock bottom for **through profiles** | ≥ 0; < the depth                                                                                                                                                                    |

- **Walls:** following the owner's allowance makes the owner's own clearing rings at that allowance cut air, so they are skipped and the owner's finishing ring takes the margin, as with DF108.
- **Floor:** with `floor` > 0 the roughing stops that much above the floor; the owner then clears its whole region at the levels below the roughing floor (nothing is cleared there) and only the rest above it. A cleaner floor from the finishing tool, at the cost of a full-area last level.
- **Through profiles keep a skin:** the roughing never cuts through, so nothing comes loose before the owner's tabs exist and the owner's tabs stay the only tabs. The owner cuts the skin and the walls with its tabs as today. Through pockets clear their whole region and leave no slug, so their roughing goes through (floor 0, DF108).
- **Where it lives:** in the design (the owner's `roughing`), because it is part of the operation's intent and the user edits it in the operation inspector. The roughing plan operation takes no `finishAllowance` / `finishStepdown` strategy keys (rule `notForRoughing`, `input.malformed`); its other pocket/profile keys (direction, entry, helix, ramp, breakthrough) work as usual. The pattern's DF108 roughing used the roughing operation's strategy `finishAllowance`; R1 moves that to the design margin with the same default, so its golden stays byte-equal.

## What the roughing operation cuts

- **Pocket:** offset clearing of every piece of the region its tool enters, down to `depth − floor`, leaving `wall` on the walls, **no finishing ring** (DF108). Pieces its tool cannot enter are skipped.
- **Profile:** the owner's slot passes with its own tool at the part-side distance R + `wall`, to `depth − floor` (through: to the skin), **no finishing pass and no tabs** (the skin holds through profiles; a step stops above the floor margin). Its slot is its own tool's width (`slotWidth` of the owner applies to the owner).
- Stepdown, stepover and feeds come from its own tool's cutting preset and the calculator, as any operation.

## Rest by the operation

[Q143](#questions-for-the-user), [Q144](#questions-for-the-user). The owner keeps its generator and skips what the roughing already removed, computed **from the roughing tool's reach**, not from a stock simulation:

- **Input (generalised `restAfter`):** when the owner's roughing comes earlier in the machining order, the owner's toolpath input carries `restAfter = { radius, cornerRadius, wall, floorDepth }` of the roughing's tool and margins (today `{ radius, cornerRadius, allowance }`; `floorDepth` = depth − floor). Without an earlier roughing (off, or the owner moved before it) nothing is skipped, as DF108.
- **Cleared region** (as DF108, plan-v0.3's rest = region − opening): `cleared` = the region shrunk by radius + wall and grown back by the flat radius (radius − corner radius); `inside` = `cleared` shrunk by the owner's tool radius (+ 0.01 mm). At levels **above `floorDepth`** the owner skips what lies in `inside`; at and below it nothing is skipped.
- **R1, ring skipping (built for patterns):** a node of the pocket's ring tree whose tool-centre region lies in `inside` is skipped with its children. Simple and safe, but a ring that touches one uncleared corner is kept whole, which is why DF108 saved about a fifth.
- **R3, path clipping:** each clearing ring or profile level pass is clipped to the **rest region** (the tool-centre positions whose disc is not wholly in `cleared`), keeping runs longer than a tool radius, joined by the existing linking (a feed link inside the cleared region where the straight link stays in it, else retract over the in-process stock, [safe-links.md](safe-links.md)). Each kept run enters at a corner of cleared air: a plunge or a short ramp into air, no helix (rule as the entry of an open region, [plan-v0.3.md](plan-v0.3.md#pocket-offset-clearing-of-a-region)). The finishing ring or pass is never clipped. Profiles need R3: their part-side level pass touches every inside corner of the outline, so without clipping they skip nothing.
- **Never cuts less than needed:** the cleared region is a lower bound of what the roughing removed (exact discs of its tool along its own rings, no credit for scallops between rings); a test oracle sweeps both toolpaths on a heightmap and checks that the finished region equals the owner's alone (no material left) and that the owner's moves in cleared air are only links and entries.
- **Why not a stock model:** an in-process stock heightmap (the cut map of [deviation.md](deviation.md), DF64's stock heights) would also credit facings and earlier operations, but it is sampled (0.1 mm cells), slower in the toolpath job, and makes every toolpath depend on every earlier one's moves; the reach rule is exact, cheap and keyed only on the roughing's tool and margins. The stock model stays the roadmap's "in-process stock across setups".

## Order and tool changes

[Q145](#questions-for-the-user).

- **Dependency:** an owner after its roughing, like `on` and `edgeOf` ([plan-v0.4.md](plan-v0.4.md#machining-order-v2)); the default order, rebuild placement and `repairOrder` keep it. Moving the owner before its roughing by hand is allowed (`plan.order` reports nothing): the owner then cuts everything, as DF108.
- **Tool runs across the setup:** machining order v2 already takes every ready operation of a tool into its run. So the Ø 8 roughs every pocket and profile of the setup in one run, then the Ø 3 cleans them all: one extra tool change per roughing tool, not per operation. The run order inside the setup is unchanged otherwise (facing, drilling, pockets, chamfers, lines, profiles; the roughing of a profile is a profile and runs with the profiles, before its owner).
- **Several setups:** the roughing is milled in its owner's setup (same `on`, same direction).

## Feeds

- **Roughing operation:** its tool's preset and the calculator, at its own stepover and stepdown, like any pocket/profile; no finishing pass, so no DF74 finishing feed.
- **Owner:** unchanged: its clearing rings at its feed, its finishing pass at the DF74 finishing feed. **Later:** the owner's rest runs engage at most the wall margin radially plus the corners, so radial chip thinning would allow a faster feed there (as DF74 for the finishing pass); measured after R3.
- **Time estimate:** the plan's time comes from the toolpaths, so it drops with the skipped or clipped moves; a plan with roughing shows both operations' times.

## Patterns

The pattern's `roughing: boolean` stays (DF108) and also takes the margins: `roughing: true | { wall?, floor? }`, the same object as the operations'. Its owned pocket `<id>_roughing` becomes an instance of this model (the owner is the pattern's pocket; `roughingOf: '<id>_pocket'`). Its tool rules, DFM and rest machining are the shared code. R1 keeps `pattern-honeycomb-roughing.nc` byte-equal; R3 (clipping) changes it, which is allowed (roughing on) and re-measured.

- **Viewport (Plan):** the roughing toolpath draws like any toolpath; selecting the owner shades its **rest region** (the uncleared corners and margin band) faintly in the accent, so the user sees what the small tool will cut. Design viewport: nothing new (no geometry of its own).

## Agent API

Budget: `tools/list` is at **115,956** chars of 120 K ([llm-api.md](../architecture/llm-api.md#implementation-task-310)). No new tool.

- **`roughing`** on `design.pocket.add` / `.update` (R1) and `design.profile.add` / `.update` (R4): `true | false | { wall?, floor? }` (`false` and `null` remove it; `true` = defaults). One description on the add tools, "Bigger tool first (op `<id>_roughing`, tool via design.operation.tool.*); {wall, floor} stock to leave, default finishAllowance, 0", the update tools sketch it ("As design.pocket.add"), as the engraving tools do.

- **Tool:** `design.operation.tool.set` / `.unlock` on `<id>_roughing`, as the chamfer's and the pattern's roughing. Results list the roughing operation in `operationIds`; `design.operation.get` shows `roughingOf`.
- **Estimate:** ≈ +0.25 K in R1 (pocket and pattern), ≈ +0.15 K in R4 (profile): **≈ 116.4 K** after both, measured in each slice's implementation notes and in llm-api.md's list.

## Questions for the user

Numbering continues after [workholding-library.md](workholding-library.md#questions-for-the-user)'s Q138. "Q139 ok" takes the recommendation; "all ok" takes every one.

1. **Q139 – Which operations first.** (1) **Pockets and patterns first, then inside/outside profiles** once rest clipping is in (R3, R4); bolt hole recesses later. (2) Pockets, profiles and bolt hole recesses at once. (3) Pockets only. _Recommendation: (1)._ Pockets reuse DF108 almost as is; profiles only pay off with clipping, so they come right after it.
2. **Q140 – Model.** (1) **A `roughing` setting on the operation that owns a roughing operation `<id>_roughing`** (the pattern's model). (2) A plan-only setting that adds a second toolpath to the operation's plan operation. (3) No setting: the user adds a second pocket and marks it as roughing. _Recommendation: (1)._ Its own tool field, plan operation, tool run, feeds, checks and labels come for free; (2) needs two tools per plan operation everywhere; (3) leaves the user to keep two shapes in sync.
3. **Q141 – Roughing tool.** (1) **Auto: the largest end mill within 0.6 × the narrowest width, library first, then the standard series; any user choice locks it;** a warning when it is not larger than the operation's tool. (2) Library tools only (no generalized tool). (3) Always the user's choice, no auto. _Recommendation: (1)._ Same rules as every tool field and as DF108; the warning catches a pass that saves nothing.
4. **Q142 – Margin defaults.** (1) **Walls = the operation's finishing allowance (0.2 mm, wood 0.5 mm), floor 0, through profiles a 0.5 mm skin.** (2) 0.5 mm on walls and floor everywhere. (3) Walls 2 × the finishing allowance, floor 0.2 mm. _Recommendation: (1)._ Equal to the allowance, the operation's own clearing at the allowance cuts air and is skipped; floor 0 matches flat end mills and DF108; the skin keeps through profiles held until the operation's tabs exist.
5. **Q143 – How the operation knows what remains.** (1) **From the roughing tool's reach** (cleared = region opened by the roughing tool minus the margin; exact and cheap). (2) An in-process stock heightmap simulated from the roughing's toolpath. (3) Not at all: the operation cuts everything again (roughing only saves tool wear). _Recommendation: (1)._ It is the DF108 rule, needs no simulation in the toolpath job and never skips uncut material; the stock model stays the roadmap's in-process stock across setups.
6. **Q144 – How finely the operation skips.** (1) **Whole rings first (built for patterns), then clip each ring and level pass to the rest region** (R3). (2) Clip from the start. _Recommendation: (1)._ R1 ships pockets on the built code with goldens unchanged; R3 is the bigger saving and what profiles need.
7. **Q145 – Order and tool changes.** (1) **Tool runs as today:** every roughing of a setup joins its tool's run, each before its operation (one extra tool change per roughing tool). (2) Each roughing directly before its operation (a tool change per pair). _Recommendation: (1)._ Machining order v2 already does it; (2) multiplies tool changes.
8. **Q146 – Features.** (1) **Clones instances and split pieces copy their source's roughing (R5); bolt hole recesses and counterbores later, on request.** (2) Also bolt hole recesses now. _Recommendation: (1)._ Repeats must match their source; hole recesses are small enough that a bigger tool rarely fits and pays.

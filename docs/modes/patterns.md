# Patterns: shapes laid out over an area, with an optional chamfer

Status: accepted (proposal, 2026-11-25; user TG #333 "we need something like [cnc-code's patterns helper] as a feature, but with shape support, also with optional chamfering"; the user took every recommendation of [Q124–Q129](#questions-for-the-user), TG #336 "go"; scheduled after edge chamfers; P0 spike S8 run 2026-11-25, [report](../research/2026-11-25-spike-s8-patterns.md); P1–P4 built provisionally, [Implementation (P1)](#implementation-p1), [(P2)](#implementation-p2), [(P3)](#implementation-p3), [(P4)](#implementation-p4); P5's open items (flip and Triangles, viewport ghosts and web ring, the bottom chamfer of through cells, `throughDepth` of through pockets) built provisionally, [(P5)](#implementation-p5); hardening DF107–DF109 (Presets dialog, roughing, icon) built provisionally, [(DF107–DF109)](#implementation-df107df109)) · Research: [cnc-code's pattern helper](../research/2026-11-25-cnc-code-patterns-helper.md) · Replaces the parked placeholder [features.md § Patterns](features.md#patterns) (D28, D30) · Builds on: [features.md](features.md) (feature model A1–A6), [design-v0.3.md](design-v0.3.md) (shapes), [edge-chamfers.md](edge-chamfers.md) (chamfers along any loop, E1–E3 built), [split-parts.md](split-parts.md) (region clipping) · Budgets: [S6](../research/s6-clone-budgets.md), [S7](../research/2026-11-25-spike-s7-edge-chamfers.md) · Terms: [glossary.md](../glossary.md)

A **pattern** covers an area of a face with many copies of a **cell**, cut as recesses or left standing as islands, and optionally chamfered. Uses include decorative surfaces (honeycomb, diamonds, scales), lightening and ventilation holes, grip textures, and speaker or vent grilles. It is cnc-code's pattern helper ([research](../research/2026-11-25-cnc-code-patterns-helper.md#summary)) with three changes:

- **The cell is any shape:** a named shape of the part or a primitive ([design-v0.3.md § Shape definition](design-v0.3.md#shape-definition)), not a fixed catalogue.
- **The area is any boundary:** a named shape or the face, less a margin. It is not limited to the whole stock top.
- **One pocket cuts all cells.** The chamfer is the existing edge chamfer on that pocket.

## Patterns and Clones

|             | Clones ([features.md § Clones](features.md#clones))                               | Pattern (this doc)                                                 |
| ----------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Repeats     | Operations or one feature (a counterbored hole), each instance its own operations | A shape: every cell is a loop of one region                        |
| Positions   | Path rows (grid, offset, polar, arc, along, point), skips, stable numbering       | A lattice filling a boundary; cells are not numbered or referenced |
| Count       | ≤ 100 instances (S6: evaluation per instance)                                     | Hundreds to ≈ 2 000 cells (one prism; limit set by [P0](#slices))  |
| Surfaces    | Each instance has floors usable as `on` targets                                   | One floor: `<id>_pocket.floor`                                     |
| Tool        | Each source operation's tool, one tool change per source operation                | One tool for all cells (the pocket's tool field)                   |

- **Neither nests the other's role.** A Clones may nest a pattern feature as its source (A6: one non-Clones feature), for example the same grille on several panels. A pattern's cell is a shape, never a feature or an operation.
- **The grid repetition question is settled:** Q30 (D34) gave linear, grid and circular repetition to Clones rows and kept "pattern" for this feature. Nothing here changes Clones.

## Model

`design.pattern.add` creates a feature of kind `pattern` (A1–A6 unchanged):

| Field       | Kind / values                                                                                                                                                                              | Default                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------- |
| `on`        | Face target ([design-v0.2.md § Face targets](design-v0.2.md#face-targets-generalised-on)), as a pocket                                                                                     | Last facing's floor, else `stock.top`               |
| `cell`      | `{ shapeId, rotation?, scale? }` (a named closed shape of the part; its bounding-box centre sits on the node) or a primitive without `center`: `circle`, `rectangle`, `obround`, `polygon` | `circle { diameter: 8 mm }`                         |
| `lattice`   | `square`, `staggered` (odd rows shifted half a pitch), `hex` (60° rows: the densest packing for circles and hexagons) or `polar` (rings about a centre). Plus `angle`, `origin [u, v]`     | `staggered`, angle 0, origin at the boundary centre |
| `spacing`   | `{ gap }`: the web between the cells' bounding boxes along each lattice direction, so the pitch = cell extent + gap. Or `{ pitch: [a, b] }` given directly                                 | `{ gap: 2 mm }`                                     |
| `alternate` | `none` or `flip`: every other cell turned 180° (triangles, fish scales)                                                                                                                    | `none`                                              |
| `boundary`  | `face` (the `on` face's extent) or `{ shapeId, center, rotation? }` (placed like a pocket's named shape)                                                                                   | `face`                                              |
| `margin`    | Length ≥ 0, the uncut border inside the boundary                                                                                                                                           | 5 mm / 3/16″                                        |
| `fit`       | `whole` (only cells wholly inside the boundary less the margin) or `clip` (cells cut to it)                                                                                                | `whole` (Q128)                                      |
| `invert`    | Boolean: pocket the boundary less the margin, minus the cells                                                                                                                              | `false`                                             |
| `depth`     | Length > 0, floor above `stock.bottom` (the pocket rule; through is Q126)                                                                                                                  | 1 mm / 1/32″                                        |
| `through`   | Boolean (P4, Q126): every cell cut through the stock (`depth` kept but unused); refused with `invert`                                                                                      | `false`                                             |
| `chamfer`   | `{ width, angle }` or absent ([Chamfer](#chamfer))                                                                                                                                         | absent                                              |
| `name`      | Default "Pattern 1"                                                                                                                                                                        |                                                     |

- Every length and angle is a quantity and may be an expression, as on operations.
- **For hex and staggered lattices the gap is exact** for circles and for hexagons across their flats: the web is the gap. For other cells the web is at least the gap. [DFM](#dfm) reports the narrowest real web.
- **Polar:** rings at `pitch[1]` apart radially, and cells on each ring at the chord pitch `pitch[0]` (or the circumscribed diameter + gap; [P2](#implementation-p2)). Every ring starts at `angle`. Cells keep their orientation unless `rotation: 'radial'` (later, as with Clones rotation).
- **Invariants** (`model.invariant`, rule names in code): the cell resolves to a closed region (`patternCellOpen`). Pitch > 0 and ≥ the cell extent along each direction, so cells never overlap (`patternOverlap`; an intended overlap would make one cell). The resolved cell count is at most the limit (`patternTooMany`, working value 2 000, set by [P0](#slices)). The boundary shape is closed. No pattern cell of itself (`shapeCycle`).

### Owned shape and operations

- **Owned shape** `<id>_cells` (A1 extended from operations to shapes): one item, `pattern { …the fields above that make geometry… }`, read-only in the Shape Editor. It is edited through the feature, and removed with the feature (A5). It resolves in the 2D layer ([shapes.md](../architecture/shapes.md)) as follows:
  1. Resolve the cell. Lay out the lattice over the boundary's bounding box, plus one pitch all round. Place the cell at each node (with the flip on alternate nodes).
  2. Shrink the boundary by the margin. Keep the cells inside it (`whole`), or intersect them with it (`clip`). Drop the empty ones.
  3. With `invert`, take the shrunk boundary minus the cells.

  Resolution is cached by the item's hash plus the referenced shapes' definition hashes, as the [offset item](design-llm-first.md#offset-item) does. Editing the cell or boundary shape restales the pattern.

- **Owned pocket** `<id>_pocket`: `shape: named { shapeId: '<id>_cells' }`, the feature's `on` and `depth`. It has its own tool field (A4), `generalTolerance` and name. Surfaces: `<id>_pocket.floor`. The walls are numbered for display only (S-J).
- **Owned chamfer** `<id>_chamfer` when `chamfer` is set: `edgeOf: '<id>_pocket'`, `width`, `angle`, and its own tool field. Removing the chamfer field removes the operation. Its id is stable by role (A3).
- **The `pattern` item is feature-only in the first version.** `design.shape.*` refuses it (`ownedShape`). That keeps the shape tools' schema and the Shape Editor unchanged. Exposing it as an ordinary item ("pattern inside my own shape") is later.

### Boundary and clipping

- **`whole`** keeps only cells wholly inside the boundary less the margin. This is the clean, default look, and it leaves no sliver at the edge (cnc-code's inlay made the same choice).
- **`clip`** cuts the cells with the boundary less the margin through the 2D port's intersection. This is the same operation the split parts use to clip a pocket to a piece ([split-parts.md § Mapping](split-parts.md#mapping-the-source-into-a-piece)). Clipped fragments narrower than the smallest library end mill are dropped and counted in the read-out ("14 slivers dropped"). They would only make rest material.
- **Keep-outs** (a solid patch for a logo, mounting bosses): a boundary shape with `subtract` items. There is no per-cell skip list in the first version.
- **Margin 0 at a stock edge** is allowed. Cells there open to the edge, like cnc-code's run-off. With `clip`, the boundary edge becomes a pocket wall, exactly as a pocket that reaches the edge does today.

### Stacking

cnc-code's layers (a fine lace standing on a coarse grid) become two features (Q127): pattern 2 `on: pattern1_pocket.floor`. Pattern 2's cells then exist only where pattern 1 cleared, from its floor down. P4 decided that the `on` alone says it: the face of a pattern's floor is that pattern's cells, so no boundary argument is needed ([Implementation (P4)](#implementation-p4)); an own boundary shape narrows it further.

### Chamfer

- **The existing edge chamfer** ([edge-chamfers.md](edge-chamfers.md)), unchanged in model, toolpath and tool fit. It runs round every loop of the pocket: every cell's rim, or every island's foot when inverted. Width and angle are the chamfer's own (default 0.5 mm × 90°). **Off by default**, as for every chamfer ([edge-chamfers.md § Decided here](edge-chamfers.md#decided-here-not-questions): no automatic chamfers).
- **One width for all cells.** cnc-code's per-pattern width shares (half-width on small holes) existed because its patterns were code. With user shapes, two widths means two patterns.
- **Solid cost**, from the spike ([S7 § Cost](../research/2026-11-25-spike-s7-edge-chamfers.md#cost)): the loft costs ≈ 15–30 ms per 1 000 edge elements. Cells are disjoint loops, so the loft is built and **checked per loop**. Bevels of neighbouring cells that meet over a thin web make overlapping lofts, unioned in the kernel, not a topology change. This keeps the fast path where a whole-region check would send every cell to the sweep-union fallback, which grows superlinearly (1 000 elements ≈ 3.4 s). E1's check must run per loop before patterns ship ([P3](#slices)). S8 confirmed it: with bevels meeting over a 2 mm web the whole-region check sent 103 cells to the fallback (16 s, one step); per loop every cell lofted and the evaluation took 0.47 s. Checking per group of cells is not enough (a group of 50 neighbours falls back together). Per-cell meshes still cost ≈ 6–8 ms per cell; P3 puts the non-meeting loops in one mesh ([S8 § Recommendations](../research/2026-11-25-spike-s8-patterns.md#recommendations)). The fallback stays for a single cell whose own offset changes topology (a notch shorter than the width).

## Plan

- **The pocket** is cleared by the existing offset clearing ([plan-v0.3.md](plan-v0.3.md)) loop by loop. Cells are visited nearest-neighbour from the front-left. Each cell uses the pocket's entry rules: a helix where it fits, else a ramp. Travel between cells uses [safe links](safe-links.md) (minimum retraction over the in-process stock), which matters with hundreds of cells. P0 checks that the generator orders many disjoint loops well. If it doesn't, ordering is a fix in the pocket generator, not pattern logic.
- **The chamfer** is the edge-chamfer generator, one ring per cell in nearest-neighbour order, after the pocket.
- **Cost:** toolpaths and the program are linear in the cells (S6: ≈ 17–146 lines per instance for holes and slots). 2 000 small cells give a program of the order of 10⁵ lines, which a GRBL stream handles.

## Performance

- **Evaluation:** one prism of N loops in one subtraction, not N operations. S6's per-operation layer cost does not apply. The floor is the boolean cost per chord, ≈ 8 µs per chord ([S3](../../spikes/prisms/results.md), [S6 § Levers](../research/s6-clone-budgets.md#levers)). A Ø 8 mm circle is ≈ 40 chords at 0.01 mm, so 300 cells ≈ 12 000 chords ≈ 100 ms: over the 50 ms budget, like 100 clones, and the reason for `dfm.patternHeavy`. The output passes the 20 000-triangle budget at ≈ 100–150 round cells. A large pattern is therefore a "heavy part", which is fine as long as the evaluation stays abortable between steps. A step bigger than ≈ 100 ms would split the region into subtraction layers of disjoint cell groups (the S6 clone-layer idea).
- **Resolution:** the lattice and the containment test are linear with a spatial index on the boundary. The `clip` intersections run per cell that crosses the boundary only.
- **Chamfer:** per-loop lofts, see [Chamfer](#chamfer).
- **Cache:** the resolved region and the pocket's solid are cached by the item hash. Edits elsewhere in the part don't rebuild the pattern.
- **Measured in P0** ([S8](../research/2026-11-25-spike-s8-patterns.md)): evaluation is linear (57 / 235 / 961 ms, 13 k / 64 k / 257 k triangles at 103 / 503 / 2 009 rounded hexagons; one subtraction step, splitting the region into layers did not help), so `patternTooMany` = 2 000 and `dfm.patternHeavy` at ≈ 150 cells (≈ 5 000 chords). Quadratic, to fix in P1: the region built by booleans (a named shape's fold of N items took 258 s at 2 009; direct pieces ≤ 1 ms, so the `pattern` item emits pieces without a boolean), the 2D port's offset checks on many-piece regions (`regionContains` per loop), the pocket generator's ordering (11.5 s at 2 009) and the Z-reference spot search. Without those fixes the limit is 500.
- **Originally to measure in P0** (spike S8): evaluation, triangles, toolpath, program size and the chamfer loft for 100 / 500 / 2 000 cells (circles, rounded hexagons, a named star), `whole` and `clip`, normal and inverted. These set the cell limit and the heavy threshold.

## Split parts and Clones

- **Split parts:** the owned pocket crosses a split line like any pocket, and gets an `intersect` item with the piece region. With `whole` the piece then holds partial cells at the split. That is correct (the seam runs through the pattern), and the existing `cutsFeature` finding names the pattern. The chamfer uses E2's `sourceEdge` rule, so the split line is never chamfered.
- **Clones:** a pattern feature may be a Clones source (A6). `dfm.clonesHeavy` and `dfm.patternHeavy` both apply.

## UI

Follows [ui.md § Features (v0.4)](../conventions/ui.md#features-v04). The L-review comes with P2.

- **Add → Pattern**, next to Hole and Clones, opens the inspector with the defaults, on the selected face. A "Decorate" submenu can come when a third decorative feature (engraving, text) arrives.
- **Navigator:** a feature row ("Pattern 1", icon, "312 cells", rolled-up badge) nesting its owned shape, pocket and chamfer rows. The owned rows are read-only except for the tool fields.
- **Inspector groups:**
  - **Cell:** a picker with the part's closed shapes as thumbnails, plus the primitives with their size fields, and rotation and scale.
  - **Layout:** lattice tiles (square, staggered, hex, polar), Gap or Pitch, angle, origin, Flip alternate.
  - **Area:** boundary (Face, or a shape `Select` with a pick button), margin, Whole cells or Clip.
  - **Cut:** depth, Invert.
  - **Chamfer:** a toggle, then width and angle.
  - **Read-out:** "312 cells · web 2.0 mm · 14 slivers dropped".
- **Presets…** in the inspector header opens the Presets dialog (DF107, [below](#presets-dialog-and-more-presets-df107)): Staggered holes, Honeycomb, Rounded squares, Diamonds, Triangles (flip), Slots (obround), Grille (hex of small circles), and since DF107 Circle grid, Waffle, Octagons, Louvres, Speaker grille (polar) and Lightening holes. Picking a preset sets cell, lattice, gap and (P5) `alternate`, and nothing else. These are cnc-code's lattice-plus-cell entries, without its special generators (Q125).
- **Viewport:** while editing, the boundary less the margin is dashed and dropped or clipped cells show as ghosts. The thinnest web and finding markers are drawn. Clicking a cell selects the pattern.
- **Later:** a scale and gap sample at real size with the tool drawn (cnc-code's active (i)), once the Field info views framework exists.

## Agent API

- **Two new tools:**
  - `design.pattern.add { partId, on?, cell, lattice?, spacing?, alternate?, boundary?, margin?, fit?, invert?, depth, chamfer?, roughing?, name? }` (DF108: `roughing`), ≈ 1.2 K with shared `$ref`s to the shape primitives.
  - `design.pattern.update { featureId, …same fields }`, as a listed sketch ([llm-api.md § Schemas](../architecture/llm-api.md#schemas), `listedArgs`), ≈ 0.4 K.
- **Shared tools:** `design.feature.remove`, `.move`, `.list` and `.get` are shared. The owned pocket and chamfer show in `design.operation.list` and take `design.tool.*` as other owned operations do.
- **Results** carry `{ featureId, operationIds, cells, dropped, narrowestWeb, warnings }`, so an agent sees the count and the web without a preview tool. A `dryRun: true` on add/update returns the same without changing the part, for agents trying a gap. This costs one boolean, not a third tool.
- **Budget:** `tools/list` measured **107.4 K** of 120 K (139 tools, [edge-chamfers.md § Agent API](edge-chamfers.md#agent-api)). Patterns add ≈ 1.6 K, to ≈ 109 K. The `pattern` item is not added to the `design.shape.*` unions (PT-B), which saves ≈ 0.3 K × 3.

## Implementation (P1)

Built 2026-11-25 (provisional, on a branch until the user tries the honeycomb lid). Code: `src/core/design/pattern/` (`layout.ts` the lattice, `pattern.ts` the feature kind, `commands.ts` the tools), the owned shape in `shape.dto.ts` / `shape.ts` / `placement.ts`, the hooks in `feature.ts` / `feature-commands.ts`, the inspector `src/renderer/src/modes/design/PatternInspector.tsx`.

- **Scope as P1 in [Slices](#slices):** square, staggered and hex lattices; cell = primitive (circle, rectangle, obround, polygon) or a named closed shape of the part, with a rotation (no `scale` yet); `spacing` `{ gap }` or `{ pitch: [a, b] }`; `angle`; `origin` (a node; default the centre of the face less the margin); boundary = the `on` face's rectangle (the stock face of `on`'s direction) less `margin`; `whole` cells only. Not yet (P2+): `boundary` shapes, `fit: clip`, `invert`, `alternate`, `polar`, `chamfer`, presets, `dryRun`, the `dropped` and `narrowestWeb` result fields, `dfm.patternThinWeb`.
- **Owned shape** `<id>_cells`: a `ShapeDTO` with `owner: <featureId>`, `items: []` and a `pattern` record of numbers (cell items or `shapeId`, rotation, lattice, angle, origin, spacing, boundary, margin), written by the feature at add/update (`FeatureKindSpec.ownedShapes`), not one `pattern` item as [Owned shape and operations](#owned-shape-and-operations) proposed: keeping it out of the item union leaves `design.shape.*` and the Shape Editor untouched (PT-B). Expressions are evaluated at add/update only, like a hole's owned operations. `design.shape.*` cannot name it (its id is not `shapeN`), the shape list and pickers hide owned shapes, `design.feature.remove` removes it, and `checkFeatures` refuses an owned shape without its feature (`unknownFeature`) or a pattern without its shape (`featureShape`).
- **Resolution** (`resolvePattern`): the cell must be a closed region (`patternCellOpen`), turned and centred by its box. Pitch a = box width + gap, b = hex ? a·√3/2 : box height + gap (or the pitch given); neighbouring cells must not overlap (`patternOverlap`, checked through the 2D port, web ≥ 0.001 mm). Nodes are enumerated in rows over the area less the margin (odd rows shifted a/2 for staggered and hex), turned by `angle` about the origin; a node is kept when the turned cell box lies inside. More than 2 000 cells → `patternTooMany` at `spacing`. The cells are translated copies emitted as region pieces with no boolean (S8's 258 s fold). Placement anchors the shape by its frame (the face rectangle), so cells keep face coordinates: the owned pocket uses the named shape at `[0, 0]`, anchor min/min.
- **Owned pocket** `<id>_pocket` only (no chamfer yet), with the feature's `on` and `depth` and its own tool field.
- **Split parts:** a pattern's owned pocket crossing a split line was refused (`patternSplit`, `model.invariant`); P2 lifts it ([Implementation (P2)](#implementation-p2)).
- **DFM:** `dfm.patternEmpty` (warning, at Margin) when no cell fits; `dfm.patternHeavy` (info, at Spacing) at ≥ 5 000 chords of the cells' outlines (`PATTERN_HEAVY_CHORDS`), with the cell count for primitive cells.
- **Tools:** `design.pattern.add` / `.update` (`update`'s `cell` a listed sketch). The cell is one flat object (`kind` plus the sizes, required per kind by a refinement) rather than a per-kind union, as workholding does: `tools/list` 108,545 → **112,270** chars (+3.7 K, 141 tools; estimate ≈ 1.6 K: the flat cell and the layout descriptions repeat in `update`). Results carry `cells`.
- **Performance fixes** (S8's quadratic steps): a bounding-box prefilter in `closestOnChains` and `regionContains` (`geometry/2d/measure.ts`); the pocket generator orders pieces and loops by a nearest-neighbour search on a grid index with an abort point every 64 (`toolpath/region-pocket.ts`); the touch-off spot search uses a bucket grid over the loops when there are more than 32 (`spotIndex`, `geometry/flat-patch.ts`). Existing goldens are byte-equal.
- **Measured** (`pattern.perf.ts`, `npm run perf`; 1 957 rounded hexagons 3 mm across flats on a 190 × 160 board): resolve 4 ms, `design.pattern.add` 919 ms (≈ 970 ms of it is the tool-fit DFM: offset and rest material per standard tool size on many tiny cells), geometry input 3 ms, evaluation 945 ms (longest step 553 ms), toolpath generation 2.3 s (S8: 11.5 s), export 1.0 s, 220 360 lines; touch-off spot over 1 913 holes 212 ms (was 1.8 s).
- **UI (minimal):** Add → Features → Pattern (the selected face, else the default `on`; since DF98 also "Add pattern" in the empty list and "Add pattern here" on a selected face, [ui.md § Add lists](../conventions/ui.md#add-lists-df98)), a navigator row "Pattern 1 · hex · polygon", and `PatternInspector` with Cell (kind, sizes, Across, Rotation; Shape with the part's closed shapes), Layout (Lattice, Spacing Gap/Pitch, Angle), Area (On, "Boundary: the whole face", Margin), Cut (Depth, the pocket's tool) and the cell count read-out. ## Implementation (P2)

Built 2026-11-25 (provisional, on a branch like P1). Code: `pattern/layout.ts` (area, fit, invert, polar), `pattern/web.ts` (`dfm.patternThinWeb`), `pattern/presets.ts`, the record fields in `shape.dto.ts`, the piece mapping in `split/pieces.ts`, the grouped tool-fit measure in `geometry/shape-measure.ts`, and `PatternInspector.tsx`.

- **Boundary shape:** `boundary: { shapeId, center, rotation? }` (or `null` = the face), placed like a pocket's named shape: the shape's box centre at `center` in the `on` face frame, turned by `rotation` about it. The **area** is the boundary less the margin (`port.offset` by the margin), so a keep-out (a `subtract` item of the boundary shape) grows by the margin too. The cells keep face-frame coordinates (the owned shape's frame stays the face rectangle) and `origin` defaults to the centre of the area's box. The boundary shape must be a closed named shape of the part (`patternBoundaryOpen`, `unknownShape`); an owned pattern shape as the boundary (stacking, Q127) waits for P4. Editing the boundary shape restales the pattern (the record names it; the definition carries its items as the cell does).
- **Containment** (`whole`): a node's cell box is tested against a bucket grid of the area's boundary elements. A box that meets no boundary element is wholly in or out (one point test); only cells whose box meets the boundary take a boolean (`intersect`, then area against the cell's). The face rectangle keeps P1's pure box test, so P1 records resolve byte-identically.
- **`fit: 'clip'`:** cells crossing the area are cut to it. A fragment narrower than 1 mm (`PATTERN_SLIVER`: it vanishes when shrunk by 0.5 mm) is dropped and counted in `dropped` ("14 slivers dropped"). The fragments kept are **opened** by 0.5 mm (shrunk, then grown back), so the sharp corners where a cell meets the boundary become R 0.5 and a Ø 1 mm end mill fits them: without it every clipped pattern was `dfm.noFittingTool` (corner radius 0). The tool chosen for the cells still leaves its radius in those corners, so a clipped pattern carries `dfm.cornerTooSmall` (an honest warning). Decided: a fixed 1 mm (the web limit) rather than the smallest library end mill, since the 2D layer has no library; `dfm.pocketNoToolFits` and `dfm.restMaterial` still judge what is left against the tools.
- **`invert`:** the pocket clears the area minus the cells, so the cells stand as islands. Built without a fold: the clipped fragments are subtracted from the area (few booleans) and the result opened by 0.5 mm when it has corners of its own (fragments, or the face rectangle less a margin: R 0.5 corners), then each whole cell goes in as a hole of the area piece holding it. Margin and keep-outs work as for normal patterns (the keep-outs stay uncut).
- **Polar lattice:** rings about `origin` (default the area's centre); ring 0 is one cell at the origin. With `{ gap }` the ring spacing and the chord between neighbours on a ring are both the cell's **circumscribed diameter** about its box centre plus the gap (exact for circles, at least the gap for any cell in any orientation). With `{ pitch: [a, b] }`, `a` is the chord along a ring and `b` the ring spacing (the same order as the other lattices: along rows, between rows; the doc's Model line said radial first and changes here). Ring `k` holds ⌊π / asin(a / 2r)⌋ cells starting at `angle`; cells keep their orientation (only the cell's rotation turns them). `patternOverlap` is checked conservatively: both pitches at least the circumscribed diameter.
- **`alternate: flip`** was not built here: nesting flipped triangles needs a pitch rule of its own. Built in [P5](#implementation-p5) with the Triangles preset.
- **Presets** (Q125, UI only, `PATTERN_PRESETS`): Staggered holes (Ø 6, staggered, gap 3), Honeycomb (hexagon 10 across flats, R 1, hex, gap 2), Rounded squares (10 × 10 R 2, square, gap 3), Diamonds (square 8 × 8 R 0.5 turned 45°, staggered, gap 2), Slots (obround 16 × 5 turned 90°, staggered, gap 3), Grille (Ø 3, hex, gap 1.5). A preset sets `cell`, `lattice` and `spacing` in one `design.pattern.update`, nothing else. Not an agent arg: an agent sets those three fields directly (budget).
- **`dfm.patternThinWeb`** (warning, at Spacing; inverted at Cell): the cells are copies of one cell, so the web between two cells depends only on their offset. Candidate offsets are the lattice offsets (polar: the real neighbour pairs, at most 64, closest first) whose centres are nearer than the circumscribed diameter + 1 mm; for each, the cell grown by 1 mm is intersected with the moved cell, and a hit's web is bisected to 0.01 mm. Inverted, the islands are the cells: the cell's rest material for a disc of radius 0.5 mm (`findRestMaterial`, as `chamferMeets`), its width bisected. The marker sits between a real pair of cells (inverted: on a real cell), with the measured web; the suggestion is the gap that brings the web to 1 mm. The check runs with the resolution (cached with it) and costs nothing when every centre distance is ≥ the circumscribed diameter + 1 mm.
- **Results:** `design.pattern.add` / `update` also return `dropped` (clip) and `narrowestWeb` (mm, when under 1 mm). `dryRun` and the result's web when ≥ 1 mm are not built.
- **Split parts (lifts P1's `patternSplit`):** a piece keeps the source's owned shape record (with its `owner`, so it stays hidden from the shape list and `design.shape.*`) and the pocket's placement shifted into the piece; a pocket crossing the piece's cell adds `clip: { min, max }` (the cell rectangle grown by the tool Ø, as other pockets' `intersect` item) to the piece's copy of the record. The cells are laid out as in the source, then cut by that rectangle, so the seam runs through the pattern and `whole` cells stay where the source has them. A piece is derived and has no features, so an owned shape without its feature is allowed in a piece only (`checkFeatures`). Before P2 the owned shape was copied into every piece and refused there; now an unused one is left out.
- **Tool fit near the limit:** `shapeMeasure` groups a region of ≥ 8 pieces by translated geometry (each piece moved to its box corner, coordinates rounded to 10⁻⁶ mm) and measures one piece per group: `fits` is any group's, `narrowest` the widest group's, `rest` each group's pieces moved to every member (largest first, as before). Erosion and opening act on disjoint pieces one by one, so the answers are the same; regions under 8 pieces keep the whole-region path (no test changes).
- **Agent API:** `design.pattern.add` gains `boundary`, `fit` and `invert` and `polar` in `lattice` (2.1 K → 2.6 K); `update` lists `cell`, `spacing`, `origin` and `boundary` as sketches ("As design.pattern.add cell"), which pays for the new args (1.6 K → 1.4 K): +0.24 K in all, 112.5 K. Measured in [llm-api.md](../architecture/llm-api.md#implementation-task-310).
- **Measured** (`pattern.perf.ts`, the P1 board of 1 957 cells): `design.pattern.add` 149 ms (P1: 919 ms; the grouped tool fit), resolve 5 ms, geometry input 3 ms, evaluation 953 ms, generation 2.4 s, export 1.0 s.
- **Exit test** (`plan/pattern-toolpaths.test.ts`, golden `pattern-grille-keepout.nc`): Ø 4 hex cells, gap 1.5, clipped to a 70 × 40 R 8 boundary with a Ø 16 keep-out on an 80 × 50 lid, margin 2: removed volume, plan with no error, no cut within the grown keep-out, GRBL export streamed through the virtual machine. The P1 golden is byte-equal.
- **UI:** see [ui.md § Pattern inspector](../conventions/ui.md#pattern-inspector-p1). The inspector gains Presets (header menu), Polar, Origin (u, v; empty = the centre), Boundary (Face or a closed shape with thumbnails, its Center and Rotation), Whole cells / Clip, Invert, the cell picker's thumbnails, and the read-out "312 cells · web 0.6 mm · 14 slivers dropped". The viewport draws, while the pattern is selected, its pocket's outline (the cells) and the area (boundary less margin) dashed. Ghosts of dropped cells and markers of thin webs in the viewport were not drawn here (built in [P5](#implementation-p5)); the inspector L-review is left for the user.

## Implementation (P3)

Built 2026-11-25 (provisional, on a branch like P1 and P2). Code: the `chamfer` field in `pattern/pattern.ts` and `pattern/commands.ts`, the per-piece loft in `geometry/chamfer-solids.ts` (`pieceMeshes`), `edge.pattern` in `geometry/model.ts` / `design/geometry-input.ts` / `geometry/dfm.ts`, the limit argument of `pattern/web.ts`, `NearestStarts` in `toolpath/edge-chamfer.ts`, and the Chamfer group of `PatternInspector.tsx`.

- **Model.** `chamfer: { width, angle }` on the feature (stored only when on; absent = off, PT-C). It expands to the owned `<id>_chamfer` after `<id>_pocket`: a general-edge chamfer (E1) with `edgeOf` = the owned pocket, every loop, no `loops`, no corner lift, its own tool field (A4). Width > 0 is the pattern's rule (`chamfer.width`); the angle's range and the other chamfer rules are the owned chamfer's, mapped by `fieldOf` to `chamfer.width` / `chamfer.angle`. Corner lift and Side (bottom edges, for through patterns in P4) are not offered: decided, a pattern's cells are milled with corner radii, where the lift does nothing, and bottom edges need through cells.
- **Removal solid, piece by piece** (S8 § Recommendations). An inside edge of several pieces is no longer lofted and checked as one region. Per piece: the pieces are grouped by their geometry less their box corner (a pattern's cells are translated copies, so 2 000 cells are one group), and each group is lofted and checked against the 2D port once, its caps triangulated once. A group whose offset changes structure is swept chord by chord, piece by piece (the fallback stays for that cell alone; S8's group-of-50 fallback, 76 s at 503, cannot happen). Bevels of two pieces **meet** when their paths come nearer than twice the radius at the face (a bucket grid of the grown boxes, then the flattened paths' distance, cached per pair of groups and offset). Pieces are coloured greedily over that graph: every piece that meets none goes into the first mesh, and each further mesh holds pieces that are pairwise apart, so no mesh self-intersects; the evaluation unions the meshes in the kernel. Decided: colouring rather than one mesh per meeting cell (S8: per-cell meshes ≈ 6–8 ms each); a hex lattice needs 3 meshes. This is generic: any pocket of several pieces takes it (existing results unchanged, goldens byte-equal). An inverted pattern is one piece with many islands and keeps the whole-piece loft; an island narrower than 2 × width sends it to the fallback (a known gap, slow on hundreds of islands; `dfm.chamferMeets` says so first).
- **`dfm.chamferMeets` on a pattern** is measured as `dfm.patternThinWeb` with the limit at 2 × width (`patternWeb(port, input, limit)`, the layout's `webInput` kept in the facts and the result cached per limit): the narrowest web between two cells, or an island's width when inverted, exact for the lattice, with a marker between a real pair. It is the owned chamfer's warning (`operation` = `<id>_chamfer`, parameter `width`, shown at the pattern's Chamfer width), params `wall`, `width`, `at`, suggestion "at most" half the web. The edge chamfer's region-wide check (rest material of a band round every cell, bisected) is skipped for a pattern's own chamfer (`edge.pattern`): it took 306 s at 515 cells, and it overestimates a web between convex cells (1.69 for a 1.5 mm web between Ø 6 circles). A separate chamfer added to the pocket with `design.chamfer.add` keeps the region-wide check.
- **Toolpath:** the edge-chamfer generator unchanged; a level of more than 64 loops is ordered nearest-neighbour through a bucket grid of the start points (`NearestStarts`; same order as the linear scan, ties to the lower index). One plunge in the air per cell, one ring, after the pocket.
- **Agent API:** `chamfer: { width?, angle? } | null` on `design.pattern.add` / `.update` (`{}` = on with the defaults 0.5 mm / 1/64″ × 90°; a field not given keeps its value; `null` = off). `tools/list` 112,512 → **112,880** chars (+0.37 K, 141 tools), [llm-api.md](../architecture/llm-api.md#implementation-task-310).

## Implementation (P4)

Built 2026-11-25 (provisional, on a branch like P1–P3). Code: the `through` field in `pattern/pattern.ts` / `pattern/commands.ts`, `floor` and `through` of the owned shape record (`shape.dto.ts`, `placement.ts`, `pattern/layout.ts`), the through pocket (`Pocket.through` in `operation.ts` / `part.dto.ts`, `surfaces.ts`, `validate.ts`, `geometry-input.ts`, `geometry/shape-solids.ts` / `operations.ts`, the pocket strategy's `breakthrough` in `plan/strategy.ts`, `plan/checks.ts`, `toolpath/inputs.ts`), and `PatternInspector.tsx`.

- **Stacking (Q127): picked by `on`.** A pattern whose `on` is another pattern's pocket floor (`pattern1_pocket.floor`) is **stacked**: its boundary "face" is the lower pattern's cleared region (its cells; inverted, the web between its islands), each piece shrunk by the margin, so its cells are cut only inside what the lower one cleared, from that floor down (`depth` below it, the pocket rule unchanged). A boundary shape, when given, is intersected with that region (a keep-out on the stack). Decided against the doc's earlier `boundary: { shapeId: 'pattern1_cells' }`: the `on` already says "on pattern 1's floor", a pattern's floor exists only inside its cells, and it needs no new argument (budget). The record carries `floor: '<lower>_cells'`; the placement nests the lower pattern's definition in the upper one's, so editing the lower pattern restales the upper (the definition is the cache key), and the lower region is resolved once (cached) in the same face frame (both patterns are on faces of one direction, the frame of the face rectangle). A pocket floor that is not a pattern's keeps P1's face rectangle (a general "face of a pocket floor" is later). Stacks of three work the same way (each bounded by the one below).
- **Through (Q126): a through pocket, every cell cleared.** `through: true` makes the owned pocket a **through pocket** (`Pocket.through`, stored only when true, set only by a pattern): its depth is the material below `on` (to the opposite stock face, read fresh from the surface table by the geometry, the plan's reach and its strategy, so a changed stock thickness follows), and it cuts `breakthrough` below that. The pocket's clearing removes each cell wholly, so **no slug is left**: nothing comes loose, no tabs, and the existing loose-piece reasoning of through inside profiles (slugs held by tabs) does not apply. The pocket strategy gains `breakthrough` (default 0.5 mm / 0.02″ as profiles; through pockets only; `plan.workholding.breakthrough` checks it against a fixture plate as for other through cuts). A through pocket's floor is not a face target (`onTarget` false, nothing can stand on it: a pattern stacked on a through pattern is refused by the existing `onSurface` rule) and its removal solid runs from above the face to below the opposite face with no floor.
- **What would come loose is refused:** `through` with `invert` (every island would fall out) is `model.invariant` rule `patternThroughInvert` at `invert`; a through cell that has holes of its own (a named shape with a `subtract` item: its centre would fall out) is `patternThroughIslands` at `cell`.
- **The pattern's `depth`** stays stored while through is on and is used again when it is turned off.
- **Bottom chamfer of through cells (E4b's Side: bottom): later (built in [P5](#implementation-p5)).** The flip mechanism takes through profiles only, and a chamfer added to a pattern's pocket from outside runs the region-wide `chamferMeets` (minutes on hundreds of cells, [P3](#implementation-p3)); a pattern's own bottom chamfer needs the P3 per-lattice measure on the flipped face.
- **Agent API:** `through: boolean` on `design.pattern.add` / `.update`; the stacking needs no argument (the `on` description says it). `breakthrough` joins the pocket's strategy keys (its description names through pockets). `tools/list` 112,880 → **113,063** chars (+0.18 K, 141 tools; `design_pattern_add` 2,870, `design_pattern_update` 1,641), [llm-api.md](../architecture/llm-api.md#implementation-task-310).
- **UI** ([ui.md § Pattern inspector](../conventions/ui.md#pattern-inspector-p1)): on a pattern's floor the Boundary select's face option reads "Pattern 1's cells" with a one-line note; Cut has a **Through** switch, which hides Depth and says "Every cell is cut through the stock and cleared: nothing comes loose. The breakthrough is set in Plan."
- **Exit test** (`plan/pattern-toolpaths.test.ts`, goldens `pattern-lace-stack.nc` and `pattern-through-grille.nc`): cnc-code's lace on a grid: two 30 × 30 R 4 squares 3 mm deep on the 80 × 50 × 12 walnut lid, with a hex lace of Ø 5 circles (gap 1.5, margin 1.5) 1.5 mm deep stacked on their floor: 18 lace cells, all inside the squares less the margin, removed volume = squares × 3 + lace × 1.5 (within 0.2 %), the lace planned after the grid down to Z −4.5. And a through grille of Ø 6 hex circles in a 6 mm sheet-good panel: removed volume = the cells' area × 6 (no slug, no floor), the pocket cut to Z −6.5 (thickness + the 0.5 mm breakthrough), no warning. Both planned with no error, exported for GRBL and streamed through the virtual machine. The P1–P3 goldens are byte-equal.
- **Tests:** `pattern/commands-p4.test.ts` (stacked: the record's `floor`, no cell outside the lower cells less the margin, the same lace on the stock top has more than twice the cells, a lower edit restales the upper and undo restores it, a boundary shape narrows it, an inverted lower pattern bounds it by its web; through: the owned pocket's depth and `through`, the removed volume exactly twice that of the same cells 10 mm deep, stacking on it refused (`onSurface`), `invert` and a ring cell refused, off restores the depth, undo), `e2e/patterns.e2e.ts` (the Through switch hides Depth and shows its note, hidden windows).
- **Follow-ups (2026-11-25, provisional):**
  - **Patterns follow their inputs** (`design.patternFollow`, `pattern/follow.ts`, [commands.md § Document hooks](../architecture/commands.md#document-hooks)): after any document command that changed a part's record or its stock snapshot (a library stock taken in with `design.snapshot.update`, an earlier operation, a lower pattern), every pattern whose owned operations or owned shape record are no longer what it expands to is placed again in the same command (one undo step), in design order (a stacked pattern after the one below it); unchanged records keep their identity. So a thicker stock deepens a through pocket, a longer one widens the face rectangle (more cells), and a lower pattern's new depth moves the through depth of one stacked on it. A boundary shape is named, not copied, by the record: its edits already restale the placement. A pattern that no longer places fails the command, at `features.<id>.<field>`. It runs before `design.splitFollow`, so pieces copy the followed records.
  - **Through pockets after an earlier setup (DF50):** `throughDepths` measures a through pocket over its whole region like a through profile ([plan-v0.2.md § Material removed by earlier setups](plan-v0.2.md#material-removed-by-earlier-setups)): over a bottom relief it cuts the material left + `breakthrough`, in the plan's setup order; the stickout check, `dfm.reach`, the tool fit and `placed.box` read it.
  - **`breakthrough` on a blind pocket is refused** by `plan.operation.update` (`model.invariant`, rule `throughOnly` at `strategy.breakthrough`; clearing it with `null` stays allowed), as DF83 refuses a registration hole's breakthrough rather than ignoring it; the inspector already hides it there. A value stored while the pocket was through stays stored, unused, when Through is turned off.
  - **Tests:** `pattern/follow.test.ts` (thicker stock → through depth, undo restores stock and depth in one step; longer stock → face rectangle and more cells; a rename and an unrelated drilling write nothing of the pattern; a through pattern stacked on a blind one follows its new floor, undo; a split part with a stacked pattern: each piece keeps both owned shapes with clips, its lace within its grid cells less the margin, the halves cover the source's lace, a stock change regenerates the pieces), `geometry/through-depth.test.ts` (through pockets: covered, partly covered, blind, stacked, reach, no bottom band), `plan/through.test.ts` (a through grille over a bottom relief: Z −15.5 and the stickout check in Bottom-first order, Z −20.5 and the reach warning top first, breakthrough taken by the through pocket and refused on the relief). The P1–P4 goldens are byte-equal.
- **Known gaps:** the bottom chamfer (above); `plan.operation.list`'s `throughDepth` for through pockets. Both closed in [P5](#implementation-p5).

- **`alternate: flip` (accepted by delegation).** Every other cell is turned 180° about its centre.
  - **Which cells:** on rows, a node flips when (i + j) is odd, so a cell's four neighbours are turned. On a polar lattice, the odd cells of each ring flip. The origin's node is never flipped.
  - **Spacing:** with `{ gap }`, the pitches are found by bisection (1e-6 mm) so the narrowest web between upright and turned neighbours equals the gap. The pitch along the row is found first, then the pitch between rows. For triangles of side s and height h with gap g, this gives s/2 + 2g/√3 along the rows and h + g between them. With flip, hex rows nest the same way as staggered rows.
  - **Given pitches:** a `{ pitch }` that makes upright and turned cells overlap is refused (`patternOverlap`).
  - **Web and inversion:** the thin-web measure (`dfm.patternThinWeb`, `chamferMeets`) checks each pair with both cells' orientations. The pairs come from `latticePairs` in `web.ts`. With flip off, the pairs are the P2 half-plane offsets in the same order, so the earlier results are unchanged. Invert subtracts the flipped cells too.
  - **Storage:** `alternate: 'flip'` is stored on the feature and on the owned shape record (`PatternRecord.alternate`) only when set; `'none'` is the default.

### Roughing (DF108)

- **Model.** `roughing: boolean` on the feature (stored only when true; off by default). On, the feature also owns **`<id>_roughing`**, before `<id>_pocket`: a pocket with the same `on`, shape, depth and Through as the pattern's pocket and `roughing: true` (set only by a pattern, like `through`). It has its own tool field (A4), shown as **Roughing tool** in the Cut group.
- **What the roughing pocket cuts:** offset clearing of every cell its tool fits, down to the floor, leaving the pocket strategy's `finishAllowance` on the walls, with **no finishing ring**. Cells too small for its tool are skipped (a piece whose tool-centre region is empty has no rings). It removes no material of its own in the part's geometry (its region is the pattern pocket's, which removes the cells), its floor is no face target, and material bands and through depths ignore it.
- **Rest machining by the pattern's pocket** (decided by [plan-v0.3.md § Pocket: offset clearing of a region](plan-v0.3.md) and [s4-offset-clearing.md](../research/s4-offset-clearing.md): rest = region − opening, here by the roughing tool): when the roughing comes earlier in the machining order, the pocket's toolpath input carries `restAfter = { radius, cornerRadius, allowance }` of the roughing's tool and strategy. The generator works out what the roughing cleared, `cleared` = the region shrunk by radius + allowance and grown back by the flat radius (radius − corner radius), and the finishing tool's centres whose disc lies wholly in it, `inside` = `cleared` shrunk by the finishing tool's radius (+ 0.01 mm). A node of the ring tree whose tool-centre region lies in `inside` is skipped with its children (its rings would cut only air). The rest is unchanged: the rings that touch uncleared material (the allowance band and the corners the bigger tool cannot reach), whole cells the roughing tool did not enter, the entries and the finishing ring at full depth. Without an earlier roughing (Roughing off, or the pocket moved before it) the pocket clears every cell as before, so nothing is ever skipped that was not cleared. Existing goldens are byte-equal.
- **Order:** the plan's default and repaired order put a pattern's pocket after its roughing (a dependency like `on`). Both are milled in the same setup; a different tool gives a tool change.
- **Tool fit of the roughing pocket** (`toolFit`): a flat or bull-nose end mill (bull nose with RE = the floor radius, as pockets); it must fit at least one cell (rule `width`), and its Ø must be at most **0.6 × the widest cell's narrowest width** (rule `roughingWidth`): a tool that only just fits clears a thin centre line and saves nothing. No corner rule, and rest material is expected, so `dfm.restMaterial`, `dfm.cornerTooSmall`, `dfm.pocketNoToolFits`, `dfm.shapeHeavy` and `plan.restMaterial` are not reported for it (the pattern's pocket reports them). Its auto choice therefore takes the largest end mill within 0.6 × the cell's width (a Ø 6 mm in a 10 mm hexagon).
- **DFM:** the roughing pocket's own tool findings only (`dfm.toolUnfit` with `width` or `roughingWidth`). **Later:** a note when the roughing tool is not larger than the pocket's (rest machining then skips nothing); a pattern's span findings have no tool to compare.
- **Agent API:** `roughing: boolean` on `design.pattern.add` / `.update`; the roughing pocket is an owned operation, so its tool is set with `design.operation.tool.*` like the chamfer's. Results list it in `operationIds`. `tools/list` 114,188 → **114,374** chars (+0.19 K, 141 tools; `design_pattern_add` 3,175, `design_pattern_update` 1,712), [llm-api.md](../architecture/llm-api.md#implementation-task-310).
- **UI:** the Cut group gains a **Roughing** switch after Depth (Through) with the note "A bigger tool clears the cells first; the pocket's tool then cuts only what it left (corners, small cells) and the walls.", and while on, the **Roughing tool** field. The navigator nests the roughing row under the pattern, first.
- **Time estimate:** the plan's time comes from the toolpaths, so it drops with the skipped rings: [exit test](#exit-test-df108) below.

#### Exit test (DF108)

`plan/pattern-toolpaths.test.ts`, golden `pattern-honeycomb-roughing.nc` (setup program): a honeycomb of hexagons 10 mm across flats (R 1, gap 2) on the 80 × 50 × 12 walnut lid, 3 mm deep, the pocket's tool Ø 2 and the roughing tool Ø 6: the roughing precedes the pocket in the plan with a tool change between them, the removed volume is the cells' area × depth, the program exports for GRBL and streams through the virtual machine to Idle, and the plan's time is lower than the same pattern without roughing. The earlier pattern goldens are byte-equal.

**Measured** (17 cells): without roughing the Ø 2 cuts 8,535 mm in 328 s (4,565 program lines); with roughing the Ø 6 cuts 1,421 mm in 48 s and the Ø 2 then 4,965 mm (58 %) in 213 s: **261 s, −20 %** (2,823 lines). The Ø 2 keeps its outer rings round each cell (the allowance band and the R 1 corners) and the finishing ring, so the saving grows with the cell: in 10 mm cells about a fifth, more in larger ones.

## Decided here (not questions)

- **Feature, not a Clones row:** PT-A. Clones stay for functional repeats.
- **One pocket, one tool:** a pattern with two cell sizes that need two tools is two patterns.
- **Chamfer off by default**, at one width (edge-chamfers' "no automatic chamfers").
- **Web limit 1 mm** for `dfm.patternThinWeb` (a warning, never blocking). A material-dependent limit can come with the material work.
- **Cells keep their orientation on polar lattices** (as Clones, C1). Radial rotation is later.
- **No per-cell skip.** Keep-outs are boundary booleans. Per-cell skips would need stable cell numbers, which a resolved lattice doesn't have.
- **No migration:** a new feature kind and a new item kind, with no `schemaVersion` bump (pre-alpha rule).

## Questions for the user

Numbering continues after [edge-chamfers.md](edge-chamfers.md#questions-for-the-user)'s Q121 and Q122–Q123 (run-machine and llm-api amendments). "Q124 ok" takes the recommendation.

1. **Q124 – What the first version patterns.** (1) **Cells only:** closed shapes cut as recesses or islands. (2) Cells and **grooves:** lines (straight, waves, knurl, grid) cut on the line by a V-bit or flat end mill, as cnc-code's 16 groove patterns. (3) Also **reliefs** (2.5D ripples, egg crate). _Recommendation: (1) now; grooves next as their own slice (they need an `on`-profile per line set and their own DFM); reliefs with the carving work._ Shape support is about cells, and cells are where one pocket per pattern pays off.
2. **Q125 – Presets.** (1) **Presets that are a lattice plus a cell** (honeycomb, staggered holes, squares, diamonds, triangles, slots, grille). (2) Also port cnc-code's **special generators** (Voronoi cells, random bubbles, isogrid with bosses, Truchet, maze, Morse code). (3) No presets: you pick a cell and a lattice. _Recommendation: (1)._ They cover most of cnc-code's cell catalogue with no extra code. Each generator would be its own item kind with its own tests. Ask for any you miss.
3. **Q126 – Through patterns** (perforated sheet, lightening holes cut through). (1) **Later, its own slice:** the pattern's pocket may go down to the stock bottom plus breakthrough, clearing every cell completely, so no slugs come loose. (2) Through cells as inside profiles with tabs: faster for big cells, but hundreds of tabs to snap. (3) Blind only. _Recommendation: (1) in P4._ Clearing small cells leaves nothing loose. Big cells cut through are better drawn as separate inside profiles anyway.
4. **Q127 – Layers** (a fine pattern standing on the ribs of a coarser one, as cnc-code's 3 layers). (1) **Two pattern features:** the second `on` the first's floor with the first's cells as its boundary (PT-G). (2) Layers inside one pattern feature, as cnc-code. _Recommendation: (1)._ It needs no new model: the face target and boundary already express "only where the layer above cleared". It also lets each layer have its own chamfer and tool row in the navigator.
5. **Q128 – Cells at the boundary.** (1) **Whole cells only by default**, with Clip as an option. (2) Clip by default (cnc-code's helper). _Recommendation: (1)._ Whole cells give a clean border and no slivers the tool can't clear. Clip is for textures meant to run off an edge.
6. **Q129 – Structure read-out** (cnc-code's weight, stiffness and strength versus solid, from beam sections). (1) **Later**, when you ask. (2) With the first slices. (3) Never. _Recommendation: (1)._ It is useful for isogrid and lightening work, but it is an L-sized model and view of its own, and the first use is decorative.

# Clones mirror: mirrored copies of the instances across a line

Status: accepted (2026-11-26; hardening [DF126](../plans/hardening.md#intake-user-feedback-goes-here), the user's TG #413 "when creating clones, I'd like a mirror option that mirrors previous instances across a selected reference – typically part's center in X or Y axis, but selecting other feature's center as reference would be useful too."; [Q161–Q166](#questions-for-the-user) take their recommendations, accepted by delegation D78) · Extends: [features.md § Clones](features.md#clones) (rows, numbering, checks) and [§ Clones v2: groups](features.md#clones-v2-groups-df40) · Related: [design-v0.3.md § Placing a shape on a face](design-v0.3.md#placing-a-shape-on-a-face) (the named shape's `mirror` flag), [roughing.md § Implementation (R5)](roughing.md#implementation-r5) (roughing in Clones), [split-parts.md](split-parts.md), [llm-api.md](../architecture/llm-api.md) (`tools/list` budget) · Terms: [glossary.md](../glossary.md)

Clones v1 places only **translated** copies: every instance keeps the source's orientation (D30, [features.md § Properties](features.md#properties) "rotation"). A symmetric part (a pair of handles, a left and a right bracket slot, four corner pockets of a box lid) needs **mirrored** copies, which a translation gives only when the source is itself symmetric. This doc adds a mirror to Clones: one new path row kind, `mirror`, that appends a mirror image of every instance placed so far.

## What "mirror previous instances" means

- **A `mirror` row** in the Clones `rows` takes every instance placed before it (the source and the instances of the rows above, skipped ones excepted) and adds its mirror image across one line. The count doubles: a source plus 3 clones along X, then a mirror row, is 8 instances. Two mirror rows (X, then Y) give the four quadrants: 1 + 3 → 8 → 16.
- **The line** is parallel to a face frame axis ([Q162](#questions-for-the-user)): `flip: 'u'` mirrors across the line u = c (left ↔ right; on the top face X), `flip: 'v'` across v = c (front ↔ back; Y). `c` comes from the reference: the stock face's centre (default), another operation's or feature's centre, or a coordinate ([Reference](#reference)).
- **Mirror rows come last** ([Q166](#questions-for-the-user)): a path row (`grid`, `offset`, `polar`, `arc`, `point`, `along`) after a mirror row is refused (`model.invariant`, rule `clonesMirrorLast`, "Move the mirror rows to the end"). The reference point that path rows walk is not moved by a mirror row. So the rows read as "place, then mirror", with no question of what a later row repeats.
- **Numbering stays stable** (D30): a mirror row has one position per position number before it, in the same order (the mirror of 1, of 2, …), so the source's mirror is the first. The mirror of a skipped position is skipped too and keeps its number; the row's own `skip` skips single mirror positions. Adding a path row above a mirror row renumbers the mirror's positions (as adding positions to any earlier row renumbers later rows today).
- **Limits** are unchanged: a mirror row counts as one of the 20 rows, its positions count toward the 100 instances per Clones (`clonesLimit`), so 1 + 49 clones then a mirror is the most.

Not chosen: a feature-level `mirror` property applied after all rows ((2) in Q161), which says the same as a trailing mirror row but needs its own UI and schema; a separate Mirror feature kind ((3)), which would copy Clones' span, ids, follow and checks.

## Reference

The line's coordinate `c` along the flipped axis, in the Clones' [face frame](design-v0.2.md#face-frame):

| Reference              | Arg              | `c`                                                                                                                                                                                                                                                                                          |
| ---------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stock centre (default) | neither field    | Half the stock face's size along the axis (the face frame's origin is the face's lower-left corner). Follows stock changes as patterns do. With several parts, the part's own stock.                                                                                                         |
| A feature's centre     | `about: '<id>'`  | The centre of the referenced operation's or feature's **footprint bounding box** ([features.md § Checks and DFM](features.md#checks-and-dfm) defines the footprint): a hole's drilling centre, a pocket's shape centre, a Clones' whole span (a bolt circle's centre). Follows edits (Q163). |
| A coordinate           | `at: '<length>'` | The entered length (an expression is allowed, as row fields).                                                                                                                                                                                                                                |

- `about` names an operation or feature on the Clones' face that is not one of this Clones' instances (`clonesMirrorRef`: "… is not on this face" / "… is one of its own clones"). It may be a source operation: mirroring a pocket and its drilling across the drilling's centre is valid. A facing (no footprint) is refused.
- **Following** ([Q163](#questions-for-the-user)): an edit of the referenced operation or feature re-runs this Clones' expansion in the same command (`design.clonesFollow` gains the reference as a dependency beside the source). Removing the referenced operation or feature is refused while a mirror row names it (`clonesMirrorRef`, naming the Clones and the row: "change Clones 1's mirror row first").
- **Implemented (M1):** `about` may also come after the Clones in design order ([Implementation (M1)](#implementation-m1)).
- **Not offered:** the Plan's work zero or a setup datum (Design does not know setups, so a design would change with a plan); a line at any angle (later, M3 below: the transform below generalises, but rotated anchors and the picker are extra work no request needs yet).

## How an instance is mirrored

An instance is a copy of each source operation under a transform. Today it is a translation of the position parameters (`instanceOf` in `src/core/design/clones/clones.ts`, `POSITION`). With mirrors it becomes **a translation followed by up to two flips** (`flipU`, `flipV`; a flip in u and v together is a 180° turn). Per operation:

| Geometry                                                           | Mirrored instance (flip in u across u = c; v likewise)                                                                                                                                                                                     |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Positions (`center`, `shape.center`)                               | u′ = 2c − u.                                                                                                                                                                                                                               |
| Drilling, circle pocket/profile, chamfer, counterbore, countersink | The position only: rotationally symmetric.                                                                                                                                                                                                 |
| Rectangle (also a slot's rounded rectangle, DF119)                 | Rotation θ → −θ (a rectangle is symmetric under a half turn, so this holds for both flips); the anchor's u point swaps (min ↔ max; a v flip swaps v), since `center` is the anchor of the placed box. `round` and the sizes are kept.      |
| Named shape (pocket, profile, Line path)                           | `mirror` toggles; rotation θ → −θ for a u flip, 180° − θ for a v flip (the named placement flips the shape frame's x before rotating: reflection ∘ R(θ) ∘ F = R(−θ) ∘ F² for u). Anchor swapped as for rectangles. `scale` kept.           |
| Profile `side`, depth, slot width, tab `count`/width/thickness     | Unchanged: inside stays inside.                                                                                                                                                                                                            |
| Profile `tabs.positions` (distances along the loop)                | Mapped so each tab sits on the mirror image of its source tab (a mirrored loop runs the other way from the mirrored start point: s → L − s where the resolved loop keeps its winding). The M1 test checks the tab points, not the formula. |
| Pattern feature (owned cell shape)                                 | Its pocket's placed owned shape mirrors as a named shape does; the pattern's own `flip` (P5) is untouched.                                                                                                                                 |
| Facing                                                             | Unchanged (no footprint).                                                                                                                                                                                                                  |

**Cut direction stays climb without a stored "reverse".** The generators derive the ring direction from the cut side and the strategy, not from how a loop was drawn: a profile's rings are clockwise round an outside edge for climb (`profile.ts`: `cw = outside === (direction === 'climb')`), edge chamfers and v0.4 rings likewise ([edge-chamfers.md](edge-chamfers.md)), and closed Lines keep climb as profiles ([engraved-patterns.md](engraved-patterns.md)). A mirrored loop has the opposite winding, which these generators already normalise. M1's done criteria assert it on the toolpath (an outside profile and a pocket of an asymmetric named shape, mirrored: same climb sense as the source) instead of trusting it.

**Engravings and lettering** ([Q164](#questions-for-the-user)): a Line or an engraved pattern is mirrored like every other operation, so SVG lettering in a source reads mirrored on the far side. DFYOM has no text operation yet (single-line fonts are [engraved-patterns.md E5](engraved-patterns.md#slices), later); a label that must read correctly on both sides is two operations, or a later per-row switch (M3).

## Instances on the mirror line

A mirrored copy that lands on its original (its position within 0.001 mm of it, and its geometry symmetric about the line: a hole, a circle, an unrotated rectangle or one at 90°, centred on the line) is **dropped silently**: no warning, it keeps its number, and the read-out counts it ("2 on the line") ([Q165](#questions-for-the-user)). A symmetric centre feature on the axis is the normal case for a symmetric part, so `dfm.cloneDuplicate` would be noise. An asymmetric shape on the line is not a duplicate: its mirror is generated, and if the two overlap by more than touching they get the usual `dfm.cloneOverlap` info note. A copy that lands on another instance (not its own original) is a duplicate as today (`dfm.cloneDuplicate`).

## Clones of Clones, groups, split pieces, roughing

- **Groups (G1).** The whole group is mirrored as one: every member operation gets the instance's transform, and references inside the source map to the same instance's copies (a drilling on a pocket floor lands on the mirrored pocket's floor).
- **Clones of Clones (G2).** A mirror row may sit in the inner or the outer Clones. An outer mirror mirrors the inner instances' copies like any member operation; an inner mirror is repeated by the outer path. Ids are unchanged (`<clonesId>_<n>_<source operation id>`, G3); two levels at most.
- **Split pieces.** Nothing new: a mirrored instance is ordinary operations by the time the split maps them onto pieces ([split-parts.md](split-parts.md); a named shape's `mirror` flag and a rectangle's rotation are already handled there).
- **Roughing (R5).** A roughing operation is a source operation with its owner, so it gets the same transform as its owner's instance; `roughingOf` is mapped as R5 does. The step-major order puts every roughing instance, mirrored ones included, before every owner instance: one tool change.
- **Plan and cut order.** No Clones logic in Plan (D34). Within one source operation the mirrored copies follow the originals in path order (1, 2, …, then the mirror of 1, of 2, …); a shorter travel order stays a later plan optimisation. Program comments name the position as today (`(Clones 1 #5)`).
- **Checks.** `dfm.cloneOutsideStock` and `cloneOverlap` read the mirrored footprints ([`footprint.ts`](../../src/core/design/clones/footprint.ts) gains the transform). A mirror about the stock centre of a source inside the stock stays inside, so the common case raises nothing.

## UI

Layout per [inspector-layout.md § Per-inspector target layout](../conventions/inspector-layout.md#per-inspector-target-layout) (Clones: Group Source · Group Rows, one card per row · Findings); field steps per its [step assignment](../conventions/inspector-layout.md#step-assignment-per-field) (the coordinate is `xy`).

- **Add row menu** gains **Mirror** (icon: two shapes facing across a dashed line). It appends the row at the end, below any mirror rows; dragging a path row below a mirror row is not allowed (the drop target is hidden, the refusal is the agent's only path).
- **The mirror row's card:** "Mirror" segmented control "Left ↔ right" / "Front ↔ back" (the axis names follow the face, as the other rows' u/v labels do; on the top face with "X" / "Y" beside them); "About" select: **Stock centre** (default), **Feature centre**, **Coordinate**. Feature centre shows a select of the operations and features on the face (names as in the operation list) and a **Pick** button that enters a viewport pick ([ui.md § Selection and picking](../conventions/ui.md#selection-and-picking)): hovering an operation draws its centre, a click takes it, Esc cancels. Coordinate shows a length field. One (i) tip: "Adds a mirror image of every instance above, across the line." The card's read-out: "Mirrors 6 · 2 on the line".
- **Instance read-out** (the feature's): "1 + 9 clones = 10 instances · 2 on the line · 1 skipped".
- **Viewport:** selecting the Clones draws the mirror line dashed across the whole face with a small label ("Mirror · stock centre"), the mirrored instances' numbers, and their skipped spots as ghosts (click toggles the skip, as today). While a draft is open the mirrored copies are ghosts until confirmed.
- **When creating clones:** Make Clones… opens the draft with the Add row menu, so "Mirror" is offered as the first row: mirroring a single pocket across the stock centre is Make Clones… → Mirror → Create (two clicks after the menu). An instance's inspector says "Clone 5 of Pocket 2 · mirrored".

## Agent API

No new tool. `design.clones.add`, `.update` and `.preview` take one more row kind in `rows`:

```json
{ "kind": "mirror", "flip": "u", "about": "hole3" }
```

- `flip`: `'u' | 'v'` (the coordinate that changes side), required. `about?`: an operation or feature id; `at?`: a length (a quantity string); at most one of the two (`input.malformed`, rule `oneOf`); neither = the stock face's centre. `skip` as for other rows.
- `design.clones.preview` returns each position's `mirrored: { u?: true, v?: true }` and the dropped on-line positions (`onLine: number[]`), in the output schema (not in `tools/list`).
- Budget: the row kind, its three fields and one description ("Mirror every instance above across u = c or v = c; c = stock centre, about's centre or at") are estimated at **≈ 0.25 K** on the three tools' shared row schema; measured in M1 against 116.7 K of the 120 K ([llm-api.md](../architecture/llm-api.md#implementation-task-310)).
- Persistence: a new value of the stored `rows` union; no format change, no `schemaVersion` bump (pre-alpha).

## Questions for the user

Numbering continues after Q160. "Q161 ok" takes the recommendation; "all ok" takes every one.

1. **Q161 – Mirror as what?** (1) **A `mirror` row kind** that mirrors every instance placed before it. (2) A `mirror` property of the Clones feature, applied after all rows. (3) A separate Mirror feature. _Recommendation: (1)._ It is literally "mirror the previous instances", reuses the row list, skip, numbering and the Add row menu, and two rows give quadrants; (2) says the same with a second UI, (3) duplicates Clones.
2. **Q162 – The reference.** (1) Stock centre only. (2) **Stock centre (default), another operation's or feature's centre, or a coordinate; lines parallel to X or Y.** (3) (2) plus a line at any angle through the reference. _Recommendation: (2)._ It covers your three cases (part centre in X, in Y, another feature's centre) and a typed coordinate for the rest; the angled line is cheap in the transform but needs rotated anchors and a second pick, so it waits for a request (M3).
3. **Q163 – A feature reference: follow or snapshot?** (1) **Follows the referenced operation or feature** (its footprint's bounding-box centre; edits re-run the mirror, removing it is refused while used). (2) Copies its centre as a coordinate when picked. _Recommendation: (1)._ Parametric is the point of Clones (edits flow to instances); a snapshot silently goes stale when the referenced pocket moves.
4. **Q164 – Engravings and lettering.** (1) **Mirror everything,** Lines and engraved patterns included (a true mirror image). (2) Lines and engraved patterns keep their orientation (only their placed box moves to the mirrored place). (3) A per-row switch "Mirror engravings", default on. _Recommendation: (1)._ Decorative engravings on a symmetric part should be symmetric, and DFYOM has no text operation yet; (3) can be added later (≈ 0.05 K) if mirrored lettering comes up.
5. **Q165 – Instances on the mirror line.** (1) **Drop the mirrored copy silently when it equals its original** (position and symmetric geometry), keep its number, count it in the read-out. (2) Drop it with the `dfm.cloneDuplicate` warning. (3) Refuse the row. _Recommendation: (1)._ A hole or pocket on the centre line is normal for a symmetric part; a warning there would always fire. Asymmetric shapes on the line are still mirrored, with the overlap note if they overlap.
6. **Q166 – Rows after a mirror row.** (1) Allowed; they repeat only the source, as rows do today. (2) Allowed; they repeat everything placed so far. (3) **Not allowed: mirror rows come last** (`clonesMirrorLast`). _Recommendation: (3)._ (1) makes a later row ignore the mirrored copies, (2) changes what every row means; with mirrors last the path reads "place, then mirror", and any order of mirrors (X then Y) is still possible.

## Implementation (M1)

Done in DF126 M1. Code: [`clones/mirror.ts`](../../src/core/design/clones/mirror.ts) (references, the flipped rotation, tabs and shape flags), [`clones/path.ts`](../../src/core/design/clones/path.ts) (the mirror row's positions with their flips, `onLine`), [`clones/clones.ts`](../../src/core/design/clones/clones.ts) (`ROW_FIELDS.mirror`, `instanceOf` with the transform, `clonesMirrorLast`), [`clones/footprint.ts`](../../src/core/design/clones/footprint.ts) (`flipFootprint` for the checks). Tests: `clones/mirror.test.ts`, `plan/clones-mirror.test.ts` (climb sense, R5 order), `main/cli/exit-criteria.clones-mirror.test.ts` (headless exit; golden `exit-criteria-clones-mirror-handles.nc`).

Decisions made while implementing (D78 delegation):

- **The transform** is p′ = s·p + t per instance (s = ±1 per axis); a mirror row across u = c maps (s, t) to (−s, 2c − t), so two rows compose without special cases and a flip in u and v is the half turn. Offsets are rounded to 0.001 mm as before.
- **`about` may be before or after the Clones** in design order: its footprint centre is read as a value (the expansion gets the operations after its block, `ExpansionContext.after`, and the expansion caches key on every operation record when a mirror row names a reference). Nothing owned references it, so the design order rules (references point backwards) are not touched. Removal or a move to another face of the reference is refused by the Clones follow (`clonesMirrorRef`, "change Clones 1's mirror row (row 1) first"); its edits re-run the expansion in the same command (one undo step).
- **Outside profiles stay refused as Clones sources** (the v0.4 rule, features.md § Clones); the climb test uses an **inside** profile and a pocket of the asymmetric L instead of an outside profile. Both keep the source's winding sign on the finish passes.
- **Tabs:** `tabs.positions` are mapped onto the mirrored loop (closest point of the mirrored source tab point, its arc length on the resolved loop); count-based tabs (no positions) are left alone, since the generator spaces them evenly on any winding. Mapping needs the 2D layer: without it (the load's consistency check, which compares roles only) positions are kept as an approximation.
- **Line paths** (`paths.N.center`) are now translated by Clones as all other positions; before M1 a Line path's position was not moved (a latent bug no golden exercised). Their rotation and `mirror` flag follow the named shape rule.
- **The mirror of a position that was not placed** (skipped, on its own line, or a duplicate) gets the same kind and keeps its number; the row's own `skip` skips single mirror positions.
- **On the line:** a copy within 0.001 mm of its original is dropped only when the source is symmetric about that axis (circles, holes, a rectangle at 0°/90°/180°, a named shape symmetric in its outline); the preview lists them as `onLine`. Duplicate detection keys on position plus the flips that matter (a symmetric axis is ignored).
- **Limits:** `arrange` skips its instance-count check when mirror rows exist (the expansion counts the doubled positions and refuses with `clonesLimit`); 1 + 49 then a mirror is the most.
- **Viewport:** until M2 the on-line positions have no marker and a mirror row draws no line; the row icon reuses the point row's (both done in [M2](#implementation-m2); on-line positions still get no marker).
- **`tools/list`** measured 116,699 → 116,989 characters (+0.29 K, ≤ 0.3 K): the row kind with `flip`, `about`, `at` and the shortened description "mirror (last rows): flip all before in u|v across at, about centre or stock centre".
- No golden changed; no `schemaVersion` bump (a new value of the stored `rows` union).

Decisions made while implementing (D78 delegation):

- **Axis names** (the user's DF127): the "Mirror in" control names the flipped face axis as the viewport's frame arrows do, "u (+X)" / "v (+Y)" (`frameAxisLabel` of the face frame), instead of "Left ↔ right" / "Front ↔ back": left and right depend on the view, the axis does not. The (i) says what the row adds.
- **Row order:** a path row added while mirror rows exist goes above them (not at the end, which would be refused); a drag or `Alt+↑/↓` that would put a path row below a mirror row is refused before any command (the shake and "Mirror rows come last: …", the list's existing refusal pattern) rather than hiding the drop target. `clonesMirrorLast` from the core (the agent) is shown under the row's head.
- **About → Coordinate** starts at the line's current place (so switching does not move it); **Feature centre** starts at the first item of the list. Its list: top-level operations and features on the same stock face that cut an area, not the Clones itself; for a stored Clones its own source items instead of its unit (mirroring about the source's centre is allowed).
- **Pick:** the existing surface pick (`PickRequestState`): the items' surfaces are eligible and a click takes the item that owns the surface. Hovering draws the surface highlight, not the item's centre (the doc's "draws its centre" is left for later; the label on the line names the item once picked).
- **Read-outs:** "· N on the line" shows (also 0) while the Clones has a mirror row, before "· N skipped"; the card's read-out omits "on the line" when there are none.
- **Make Clones…** keeps its offset first row (the draft opens with Add row next to it); a mirror-only Clones is Add row → Mirror, then remove the offset row. The two-click path of § UI would need a different first row for some sources, which no request asks for.
- **Navigator:** a mirrored instance row shows the `row-mirror` icon after its name instead of the word (the position text already fills the row); its accessible name says "mirrored". An on-line copy reads "On the mirror line" with no Skip button (nothing to skip); its instance inspector says so.
- **The renderer's stored path** (inspector, navigator, viewport) now resolves the mirror lines from the stock and the renderer's 2D port (before M2 it placed them at 0).
- No `schemaVersion` bump, no core change.

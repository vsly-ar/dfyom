# Workholding library: clamps, vises and screws as library items

Status: accepted (hardening DF121, the user's TG #389 "Workholding initially planned to be in the lib too"; [Q133–Q138](#questions-for-the-user) take their recommendations, accepted by delegation D74, 2026-11-26); WL1–WL4 implemented ([§ Implementation (WL1)](#implementation-wl1), [§ Implementation (WL2)](#implementation-wl2), [§ Implementation (WL3)](#implementation-wl3), [§ Implementation (WL4)](#implementation-wl4)) · Plan of record: [plans/hardening.md](../plans/hardening.md) DF121 · Base: [workholding.md](workholding.md) (WH-A, Q37: inline items now, a library later) · Library: [library.md](../architecture/library.md), [persistence.md § Library references](../architecture/persistence.md#library-references) · UI: [ui-library-window.md](../conventions/ui-library-window.md), [inspector-layout.md](../conventions/inspector-layout.md) (S1–S6), [ui.md § Workholding](../conventions/ui.md#workholding) · Agent API: [llm-api.md](../architecture/llm-api.md) · Terms: [glossary.md](../glossary.md)

Today every workholding item is typed into the setup with built-in defaults ([workholding.md § Model](workholding.md#model)): a toe clamp is 30 mm wide, 60 mm long and 25 mm tall unless the user retypes it in every setup of every plan. The [vision](../vision.md) puts workholding in the library beside stock, tools and machines, and Q37 deferred that until the item kinds settled; W5 and W6 settled them. This doc moves **what a device is** (a clamp's strap, a vise's jaws, a screw's head) into the library and leaves **where it sits** (edge, position, centre) in the setup. No check changes: the obstacles, keep-out, collision check and export guard read the same resolved items as today ([WH-B](workholding.md#decisions)).

## Goals

1. **Describe a device once.** The user's own toe clamps, vise and screws are library items with their real sizes, reused by every plan and project.
2. **Same rules as tools.** A plan uses a library item through a [snapshot](../architecture/persistence.md#library-references): opening a project never reads the library; a library change reaches a plan by "Update from library" or, for `draft` plans, the next Apply ([library.md § Snapshots](../architecture/library.md#snapshots)).
3. **Good defaults without setup.** A new user with an empty library still gets today's items: built-in library items carry today's defaults.
4. **The three placement paths use the library:** Add, Copy from… and Arrange automatically.
5. **Small agent surface:** the existing library tool pattern, within the `tools/list` budget ([Agent API](#agent-api)).
6. **Nothing breaks:** inline items (no library item) stay valid forever; no `schemaVersion` bump, new optional fields only ([pre-alpha rule](../conventions/error-handling/migrations.md#pre-alpha-exception-no-data-preservation-yet)).

Not goals: clamping force, tool holders (WH-F), per-machine fixture tables, moving clamps within a setup (WH-G), formulas in item params.

## Item model

A **workholding library item** is a library item (`kind: 'workholding'`, the [common fields](../architecture/library.md#common-fields): `id`, `name`, `notes`, `revision`, `updatedAt`) with `type`, the setup item's kind (`toeClamp`, `vise`, `screw`, `block`, `base`, `surface`), the **library properties** of that type and an optional `default: true` ([Q135](#questions-for-the-user)). Everything that depends on the stock or the setup stays a **placement** field of the setup item. Values are [quantities](../architecture/quantities.md) entered as strings ([library.md § Command input](../architecture/library.md#command-input)).

| Type       | Library properties (built-in default)                                                                                                                                                                                                       | Placement (setup item)                                                   | Derived at placement                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `toeClamp` | `width` strap width (30 mm); `length` strap length, toe to heel end (60 mm); `top` highest point above the stock top (25 mm); `gripMin`, `gripMax` grip range (optional; 5–15 mm); `stud` thread, display only (optional, ≤ 20 chars: "M8") | `edge`, `at`, `grip` (default: the middle of the grip range, else 10 mm) | today's `reach` = `length` − `grip`; today's `width`, `top` |
| `vise`     | `jawWidth` along the jaws (150 mm; today's `jawLength`); `jawThickness` (20 mm); `jawHeight` (optional; drawn, and the gripped depth in the summary); `maxOpening` (optional); `soft` (false)                                               | `axis`, `protrusion`                                                     | today's `jawLength`, `jawThickness`, `soft`                 |
| `screw`    | `headDiameter` (8 mm); `headHeight` above the stock top (0 = flush or countersunk); `thread` display only (optional: "4 × 40 wood", "M5")                                                                                                   | `center`                                                                 | today's `top` = `headHeight`                                |
| `block`    | `length`, `width`, `height` (no built-in: a block is the escape hatch; see [Built-in items](#built-in-items))                                                                                                                               | `center`, `rotation`, `bottom` (default the table, −T)                   | today's `top` = `bottom` + `height`                         |
| `base`     | `type` (`spoilboard` / `fixturePlate`), `sacrificial`, `thickness` (optional, display; a later link to the machine's `spoilboardThickness` is [not in scope](#not-yet))                                                                     | none                                                                     | as today                                                    |
| `surface`  | `type` (`tape` / `vacuum` / `glue`)                                                                                                                                                                                                         | none                                                                     | as today                                                    |

- **Invariants** (`model.invariant`, paths `values.<field>`): sizes > 0 (`headHeight`, `thickness` ≥ 0); `gripMin` ≤ `gripMax` < `length`; a property not of the item's `type` is `notForKind` (the rule `plan.workholding.set` already uses).
- **Range findings, not invariants.** A placed item outside its device's range is the warning `plan.workholding.outOfRange` (params `{ setupId, itemId, rule }`): rule `grip` (grip outside `gripMin`–`gripMax`), `opening` (the stock across the vise's `axis` wider than `maxOpening`). Warnings never block the export; the user may know better (a longer strap, a vise with reversed jaws).
- **Why the split:** a clamp kit's strap, height and stud do not change between jobs; edge, position and grip do. A toe clamp's `top` is above the stock top because the strap sits on the stock: the same clamp on 6 mm plywood and on 20 mm aluminium stands the same height above Z0.

### Setup item

A setup item placed from the library stores its placement and `copyId`, the id of the plan's [library copy](plan-v0.1.md#plans-are-snapshots) of that workholding item ([Q133](#questions-for-the-user)); it does not store the library properties. `setupWorkholding(setup, stock)` ([workholding.md § Implementation notes](workholding.md#implementation-notes-df59)) resolves an item with `copyId` into today's full item (library properties from the copy, derived fields computed) before anything else reads it, so obstacles, keep-out, `checkWorkholding`, W5's held pieces and W6's search see no difference. An item without `copyId` is an **own item**, exactly today's inline item.

- `name` stays per item ("Toe clamp 2"); the summary adds the device: `front X45 grip 10 top Z25 · Strap clamp M8`.
- **Edits to a library property detach** the item ([Q138](#questions-for-the-user)): the inspector or `plan.workholding.set` writes the resolved values inline, drops `copyId` and keeps the placement, one undo step; the copy stays in the plan while another item uses it, and is removed with the last one (as unused tool copies are).

## Built-in items

The library starts empty ([library.md § Recommended presets](../architecture/library.md#recommended-presets): nothing is seeded), so the defaults live as **built-in library items** ([Q134](#questions-for-the-user)): constants in `src/core/library/workholding-builtins.ts`, listed by `library.workholding.list` with `builtIn: true` beside the user's files, never written to disk.

| Id                                 | Name                                  | Values                                                        |
| ---------------------------------- | ------------------------------------- | ------------------------------------------------------------- |
| `builtin-toe-clamp`                | Toe clamp                             | width 30, length 60, top 25, grip 5–15 mm (today's W6-C size) |
| `builtin-vise`                     | Machine vise 150                      | jaw width 150, jaw thickness 20 mm                            |
| `builtin-screw`                    | Screw, flush head                     | head Ø 8 mm, head height 0                                    |
| `builtin-spoilboard`               | Spoilboard                            | `spoilboard`, sacrificial                                     |
| `builtin-fixture-plate`            | Fixture plate                         | `fixturePlate`, not sacrificial                               |
| `builtin-tape`, `-vacuum`, `-glue` | Double-sided tape, Vacuum table, Glue | the surface types                                             |

- **Units:** each built-in has an mm and an inch value set (inch: W6-C's 1.25″, 2.5″, 1″, grip 3/16–5/8″; vise 6″ × 3/4″; head Ø 5/16″); `list` and `get` return the set of the `units` arg (default `mm`), and a snapshot copies the set of the project's unit system, so an inch project's copy reads `1 1/4"` (a mixed number takes a space: `-` means subtraction).
- **Read-only:** `update` and `remove` refuse a built-in (`input.malformed`, rule `builtIn`); the Library window offers Duplicate. A built-in may be the default of its type until a user item claims it.
- **Changing a built-in** in a later app version marks plans' copies "library changed" like any library edit; `draft` plans follow it.
- Blocks have no built-in: a block's sizes are the job's. Add → Block adds an own item, as today.

## Snapshots and persistence

- **Library storage:** `<appData>/library/workholding/<id>.json`, one item per file like the other kinds ([library.md § Storage](../architecture/library.md#storage)); a missing folder means no items. The manifest's `schemaVersion` stays 1.
- **Plan copies:** a plan's library copies gain kind `workholding` (`{ id, kind: 'workholding', libraryItemId, takenAt, values }`, [persistence.md](../architecture/persistence.md#library-references)); a setup item names one by `copyId`. Both are optional additions: a project without them loads unchanged, and no `schemaVersion` changes.
- **Stale and follow:** `plan.stale.list`'s `libraryCopies`, `plan.libraryItem.update` ("Update from library") and the `draft` follow on Apply ([apply.md](../architecture/apply.md#implementation-task-p2)) cover the new kind by their existing rules; nothing new. Updating a copy re-resolves every item that uses it; a region operation's toolpath regenerates as for any workholding change (WH-D).
- **Used chip:** `usedLibraryItemIds` ([`used.ts`](../../src/core/library/used.ts)) already reads every copy's `libraryItemId`, so the Library window marks a used workholding item without change.
- **Removed from the library:** the plan keeps its copy (`libraryRemoved`), as for tools.
- **Export header:** unchanged lines, plus the device after the summary: `(Workholding: Toe clamp 1: front X45 grip 10 top Z25 · Strap clamp M8)` so the operator picks the right clamp ([workholding.md § Program and Run](workholding.md#program-and-run)).

| Path                                                                | Today                                  | With the library                                                                                                                                                                                                                                                                                |

| **Arrange automatically** (`auto: 'toeClamps'`)                     | four clamps of W6-C's fixed size       | four clamps of the **default toe clamp** (Q135), its `width`, `length` and `top` in W6's search, grip the middle of its range; the agent may name another with `autoItemId`. ## Import and export

The library has no import or export bundle yet (the window's `⋯` slot is reserved for imports, [ui-library-window.md Q5](../conventions/ui-library-window.md#questions-for-the-user-answered)). Workholding items are files beside the other kinds, so whatever library export comes carries them with no extra format ([Q137](#questions-for-the-user)); copying `<appData>/library/workholding/` between computers works today. Built-ins are never exported. A project archive carries its plans' copies, so a project opens with its clamps on another computer (persistence rule).

## Questions for the user

Each with a recommendation; "Q133 ok" takes it. Numbering continues after Q132 ([design review U9](../plans/hardening.md#4-ux-and-ax)).

1. **Q133 – How a placed item keeps its library values.** (1) As a **plan library copy** (snapshot) of kind `workholding` that the setup item names by `copyId`, like tools; (2) an inline copy in each item with `libraryItemId` and `takenAt`; (3) no link: the library is only a template, values are copied and forgotten. _Recommendation: (1)._ It reuses "library changed", Update from library, the `draft` follow, the Used chip and the project archive rule with no new machinery; (2) duplicates the snapshot logic per item; (3) loses "the clamp kit changed" for every plan.
2. **Q134 – Built-in defaults.** (1) **Read-only built-in items** in code, listed in the tab, usable and duplicable; (2) seed files written into the user's library on first open; (3) none: the inline defaults stay as today. _Recommendation: (1)._ Nothing is written or migrated, a changed default reaches every plan through the normal stale path, and the user's library stays only what they made.
3. **Q135 – Which item Add and Arrange automatically use.** (1) **One default per type** in the library (`default: true`; else the built-in); (2) a default per machine (the machine lists its workholding); (3) the last one used in the project. _Recommendation: (1)._ You run one machine (Q49); a per-machine kit is a later field on the machine if a second machine comes.
4. **Q136 – Agent API.** (1) **Five tools `library.workholding.{add,update,remove,get,list}`** like the other kinds, plus `libraryItemId` and `autoItemId` on `plan.workholding.set` (≈ 3.2 K); (2) generalize the existing `get`/`list`/`remove` with a `kind` arg (≈ 2.5 K, but it changes nine existing tools); (3) one declarative `library.workholding.set` (≈ 1.7 K, but no revision check per item, unlike the rest of the library). _Recommendation: (1)_, within ≈ 4 K of headroom after it.
5. **Q137 – Import and export.** (1) **No separate format:** workholding files ride along with the library export when it comes (a backlog item for all kinds); (2) build a whole-library export/import bundle now as slice WL5; (3) a workholding-only export. _Recommendation: (1)_; say "Q137 2" to add WL5.
6. **Q138 – Editing a library property on a placed item.** (1) **Detach:** the item becomes an own item with the edited values (one undo step, a note says so); (2) keep per-item overrides beside the copy, like a tool's stickout; (3) read-only in the setup: edit the device in the library. _Recommendation: (1)_: one rule, no hidden override state, and a one-off longer strap does not change the kit.

## Implementation (WL1)

Done 2026-11-26. Code: [`workholding.dto.ts`](../../src/core/library/workholding.dto.ts) (the flat values schema), [`workholding.ts`](../../src/core/library/workholding.ts) (the model and its invariants), [`workholding-builtins.ts`](../../src/core/library/workholding-builtins.ts) (built-ins, the default rule, `lookupWorkholding`), [`commands.ts`](../../src/core/library/commands.ts) (the five tools, on the per-kind pattern), [`fs-storage.ts`](../../src/main/library/fs-storage.ts) (`workholding/` folder). Tests: `workholding.test.ts` (model per type, `notForKind`, `required`, grip range, built-ins, default by `updatedAt`), `workholding-commands.test.ts`, the storage contract (memory and filesystem), `fs-storage.test.ts` (a library from before WL1 gains the folder), `server.test.ts` (MCP add, list, remove).

Decisions made while implementing (recorded here, none changes an answered question):

- **Field names in the flat values.** `type` is the device type, so the base's and the surface's own type are **`baseType`** (`spoilboard` / `fixturePlate`) and **`surfaceType`** (`tape` / `vacuum` / `glue`). The other names are the [Item model](#item-model)'s. `WORKHOLDING_TYPES`, `BASE_TYPES` and `SURFACE_TYPES` live in the library DTO; the setup items' `WORKHOLDING_KINDS` re-uses them.
- **Required and optional per type:** toe clamp `width`, `length`, `top` (optional `gripMin`, `gripMax`, `stud`); vise `jawWidth`, `jawThickness`, `soft` (optional `jawHeight`, `maxOpening`); screw `headDiameter`, `headHeight` (optional `thread`); block `length`, `width`, `height`; base `baseType`, `sacrificial` (optional `thickness`); surface `surfaceType`. A missing required field is rule `required`. The commands fill two type defaults before the model, as `plan.workholding.set` does: `soft: false`, and `sacrificial` true for a spoilboard, false for a fixture plate.
- **Grip range:** `gripMin` and `gripMax` come together (rule `gripRange` on the missing one), `gripMin` ≤ `gripMax` (`gripRange`), `gripMax` < `length` (`lessThanLength`). `headHeight` and `thickness` may be 0 (`nonNegative`); every other size is > 0 (`positive`). `stud` and `thread` are 1–20 characters, checked by the model (rule `length`), not the schema (tools/list).
- **`default`** is stored only when true. Two user items claiming a type: the later `updatedAt` wins, then the larger id (deterministic). The built-in default of `base` is the spoilboard, of `surface` the tape (the first built-in of the type); `block` has none.
- **Built-ins** are `LibraryItem`s with revision 1 and `updatedAt` `BUILTIN_UPDATED_AT` (bump it when a later version changes one; WL2's stale check then sees it). Ids start with `builtin-`, which generated user ids (`workholding-<n>`) never do. The vise's inch name is `Machine vise 6"`; the other names are the same in both sets. Inch sources: `1 1/4"`, `2 1/2"`, `1"`, `3/16"`–`5/8"`, `6"`, `3/4"`, `5/16"`, `0"`.
- **`get` and `list`** return the stored DTO plus `builtIn: true` and `isDefault: true` (the effective default of its type) where they apply, output only. `list` gives the user's items (id order), then the built-ins, filtered by `type`; `units` picks the built-ins' value set. `update` and `remove` refuse a built-in id with `input.malformed`, rule `builtIn`, before reading the library.
- **Storage:** `<appData>/library/workholding/`; opening a library from before WL1 creates the folder, and a missing kind folder lists no items (instead of `persist.io`). The manifest stays `schemaVersion: 1`.
- **Library window:** workholding has no tab until WL3, so the window plumbing (`LibraryContext`, `LibraryTarget`, the renderer store) uses `LibraryTabKind` (stock, tool, machine) and ignores workholding change events; WL3 adds the kind to `LIBRARY_TAB_KINDS`.
- **`tools/list`:** the five tools are 3,229 chars; the `revision` descriptions of every library `update` / `remove` tool moved to one primer line (−469), so the listing grew **+2,760** to 115,577 chars (≤ 3.0 K; [llm-api.md § Implementation](../architecture/llm-api.md#implementation-task-310)). The primer has two new lines (revision; workholding devices and built-ins).
- **For WL2:** `lookupWorkholding(library, id, units)` resolves a built-in or a library file, `defaultWorkholding(items, type, units)` the default; snapshots (`SnapshotDtoSchema`) do not take kind `workholding` yet.

Code: [`devices.ts`](../../src/core/plan/workholding/devices.ts) (placing a device into an item, detach, the plan's copies, re-resolving a copy, `outOfRange`, the device label), [`commands.ts`](../../src/core/plan/workholding/commands.ts) (`libraryItemId`, `autoItemId`), [`snapshot.ts`](../../src/core/library/snapshot.ts) (copy kind `workholding`, `copiedValues`), [`workholding-builtins.ts`](../../src/core/library/workholding-builtins.ts) (`withBuiltinWorkholding`), `plan/commands.ts` (`refreshCopy`), `plan/validity.ts` (the update blocker), `plan/build.ts` (`pruneSnapshots`), [`plan-export.ts`](../../src/core/post/plan-export.ts) (header). Tests: `devices.test.ts` (a library clamp's prisms equal the equal own item's; built-in and refusals; placement edit vs detach in one undo step; Copy from keeps the copy; stale, Update from library and its blocker; the `draft` follow on Apply; both `outOfRange` rules; Arrange with the built-in at X45/X205, the user's default and `autoItemId`; the header line and its split). `user-case.test.ts`, the G-code oracle, every golden and the llm-first exit block (X45/X205) are unchanged.

Decisions made while implementing (none changes an answered question):

- **The item stores the device's values too.** A setup item placed from the library keeps `copyId` **and** the resolved values (today's full item); every writer keeps them equal to the copy: `plan.workholding.set` writes them when it places or edits an item, `plan.libraryItem.update` and the `draft` follow re-write every item of the updated copy (`reresolveCopy`). So `setupWorkholding(setup, stock)` stays a pure reader of the setup, and its 15 callers (renderer, Run, export, links) need no plan copies: obstacles, keep-out, the collision check, W5 and W6 see an ordinary item by construction. This replaces "it does not store the library properties" of [§ Setup item](#setup-item); the copy stays the source of truth for the device (stale, update, name, range).
- **Device parameters of a setup item:** toe clamp `width`, `reach`, `top`; vise `jawLength`, `jawThickness`, `soft`; screw `headDiameter`, `top`; block `length`, `width`, `top`; base `type`, `sacrificial`; surface `type`. The rest is placement. Derived: reach = strap `length` − `grip` (exact), screw top = `headHeight`, block top = `bottom` (else the table, −T, at the time of writing) + `height`, vise `jawLength` = `jawWidth`.
- **Detach (Q138)** happens only when an edit gives a device parameter **with a value different from the device's** (compared exactly); re-sending the device's own value, or editing placement only (grip, edge, at), keeps the link. The UI sends only the changed field, so this is the "first edit" of the doc. Detaching drops `copyId` and keeps the item's values, in the same command (one undo step); the copy is pruned when no item names it (`plan.workholding.set` and `pruneSnapshots`).
- **`libraryItemId`** on an item (new, or an id to re-place it) takes a library device or a built-in of the item's `kind` (`kindMismatch`, `unknownItem` at `items.<n>.libraryItemId`); the placement takes the device's values (a block needs no sizes; a toe clamp's grip defaults to the middle of its range, else 10 mm). One copy per device and values: every item and setup placed from it shares it (a new copy only when the library's values differ from the plan's).
- **The copy leaves out `default`.** Marking a device the default is about the library, not the device, so `takeSnapshot`, `refreshSnapshot` and `snapshotStatus` compare and copy the values without it (`copiedValues`); otherwise toggling the default would mark every plan's copy "library changed".
- **Built-ins in the plan's lookups:** `planStale`, the `draft` follow's pending source and `refreshCopy` look ids up through `withBuiltinWorkholding(lookup, project units)`, so a copy of a built-in is current against the built-in of the project's unit system and needs no library.
- **Update blocker:** an update whose device no longer fits an item's placement (a strap shorter than the grip: negative reach) is `blocked` in `plan.stale.list` and refused by `plan.libraryItem.update` with `model.invariant`, like a stock that no longer fits the part.
- **Arrange automatically** takes `autoItemId` (a toe clamp, else `kindMismatch` / `unknownItem` at `autoItemId`; without `auto` it is `needsAuto`) or the default toe clamp, its width, top and strap length with grip the middle of its range. The built-in gives W6-C's size in mm (grip 10, reach 50), so the exit block's X45/X205 hold; an **inch** project's built-in grips 13/32″ (the middle of 3/16–5/8″) instead of 3/8″. The clamps carry the copy.
- **Device name** (set result's `summary`, program header) only for a device of the user's library: a built-in's name restates the item's kind ("Toe clamp 1: … · Toe clamp"), so programs arranged or placed with built-ins are byte-identical to before. The refusal names the device the same way ("Four Strap clamp M8 do not fit …", "Four toe clamps …" for the built-in). The header sanitizes `·` to `-`; a line longer than GRBL's 70 bytes names the device on the next line (`(Workholding: Toe clamp 1 device: Strap clamp M8)`) instead of being cut.
- **`plan.workholding.outOfRange`** is in `staticWorkholdingFindings` (so `plan.warning.list` and the set result have it; the export guard keeps only errors). Opening: the stock's extent along the vise's `axis` (X for `u`).
- **Reading:** the set result's items carry `libraryItemId`; `plan.get` returns the stored items with `copyId` and the copies in `snapshots` (no per-item `libraryItemId` there: the copy names it).
- **`tools/list`:** `plan.workholding.set` +210 (`libraryItemId`, `autoItemId`, one sentence in the items help), `plan.libraryItem.update` +13 (its summary names workholding): 115,577 → **115,800** chars (+223; WL1 + WL2 +2,983 ≤ 3.2 K; [llm-api.md § Implementation](../architecture/llm-api.md#implementation-task-310)). The primer's workholding line ends "place one with plan_workholding_set items { kind, libraryItemId, …placement }" (the doc's [primer](#agent-api) sentence).

## Implementation (WL3)

Done 2026-11-26. Code: [`WorkholdingFields.tsx`](../../src/renderer/src/library/WorkholdingFields.tsx) (the per-type form), [`WorkholdingDrawing.tsx`](../../src/renderer/src/library/WorkholdingDrawing.tsx) (the device drawing), [`workholding-view.ts`](../../src/renderer/src/library/workholding-view.ts) (type icons, list cells, row flags), and the window's existing parts: `library-store.ts` (listing in the window's units, default handling), `ItemTable.tsx` (groups, chips, filter), `ItemEditor.tsx` (built-in view), `LibraryWindow.tsx` (the New menu), `form.ts` (defaults, clean-up). `LIBRARY_TAB_KINDS` now holds every kind. Tests: `WorkholdingTab.test.tsx` (list and groups, filter, built-in read-only, Duplicate + edit + Default + Save, a built-in made the default, New vise with Range, grip error focus, inch built-ins; axe), `e2e/library.e2e.ts` (hidden: open the tab, duplicate the built-in toe clamp, change a size, make it the default, save; renders `design/features/renders/wl-library-{light,dark}.png` with `DFYOM_RENDERS=1`).

Decisions made while implementing (none changes an answered question):

- **Drawing: plan above side view, not one front view.** The task asked for "plan + side view of the clamp/vise with its sizes"; a front view alone cannot show a strap's width or a vise's jaw width. Both views are schematic (not to scale) with the **values as entered** as dimension labels ("80 mm"), the stock dashed, neutral greys; the focused field's dimension is amber as in the tool drawing, and a legend names each dimension. The toe clamp's grip range is one dimension (`grip`) lit by either grip field. Surface holds show the tape / vacuum / glue pattern without dimensions.
- **List grouped by device type** (WORKHOLDING_TYPES order) under a heading row in the grid, besides the type filter; sorting a column sorts within each group, built-ins stay after the user's items in their list order. The "Type" column is dropped (the group heading and the icon say it); the columns are Name, Size, Details (grip range and stud, soft jaws and max opening, thread, sacrificial). Chips: "Default" (with a check icon, neutral) on the type's effective default (`isDefault` of `list`), "Built-in" (neutral).
- **The type is fixed per item:** "New workholding" is a menu of the six types (with their L1 icons); the form shows the type read-only. A base's spoilboard / fixture plate and a surface's tape / vacuum / glue are selects. A new item starts with the built-in's sizes (a block 50 × 20 × 20 mm / 2 × ¾ × ¾″) and the type's name made unique against the listed names, built-ins included ("Toe clamp (2)").
- **Default switch:** on a user item it is part of the draft (Saved with the other fields, L3). Saving an item with `default: true` clears the flag on the **other user items of its type** (one update each), so the switch and the chip always agree; the default rule's `updatedAt` tie-break stays for agents and two app instances. On a built-in the switch is immediate: switching it on clears the user items' flags (the built-in is never written); a built-in that is the default cannot be switched off (nothing else would be). Duplicate never copies the flag.
- **Built-in view:** every field read-only (`readOnly` on the library `QuantityField`, `NameField`, `NotesField`), the "Built-in" chip in the heading, the note "Built-in: duplicate it to change the sizes.", and only Duplicate in the action bar (no Remove, Revert, Save). Duplicate's copy keeps the built-in's sources ("30 mm") and is saved in the window's unit system.
- **Units:** `library.workholding.list` / `.get` are called with the window's unit system, so the built-ins come in its value set; switching mm / in (or a project in the other system opening the window) reloads the tab and re-shows a selected built-in. The list's size cells show values converted to the window's unit ("1.25 × 2.5, top 1 in").
- **Groups:** Device (sizes beside the drawing, then the Default switch with its muted hint), Range (toe clamp grip, vise max opening; closed while empty with "None" as summary, open when the item has a range, forced open on an error), Details (stud or thread, notes; closed, summary the text and the notes' first line). Steps: lengths `xy`, heights (`top`, jaw height, head height, block height, base thickness) `depth`, head Ø `small`. Soft jaws and Sacrificial are checkboxes.

Decisions made while implementing (none changes an answered question):

- **The Add menu:** an entry places its type's only device directly (built-ins included: Add → Toe clamp places `builtin-toe-clamp`, so a new clamp has a copy from the start and follows a later built-in change); with more than one device it is a submenu: the default, the user's others (list order), the built-in, then **"Own item"** (no `libraryItemId`, today's inline item with the command's defaults). Block has no built-in: without the user's blocks it adds an own item as before; with one or more it is a submenu (their sizes or an own item). Spoilboard / Fixture plate and the three surfaces list devices of their `baseType` / `surfaceType`. The labels carry "(default)" and "(built-in)" (the doc's example); the submenu trigger has no description tooltip (it would cover the submenu). Until `library.workholding.list` answers (or without a library) the entries place the built-ins of the project's units (`builtinWorkholding`), so Add never waits. The list is read again on every library write.
- **Placing:** the placement is today's default (`newItem`) plus `libraryItemId`; a block's own default sizes are left out (sending them would detach it at once).
- **Device line:** under the Name, so the open item reads name → what it is → where it sits. A built-in says "Toe clamp · built-in" (not "from library"), and its "Edit in library" opens the built-in (read-only there, Duplicate). The row's summary adds the device only for the user's devices, as WL2's `deviceLabel` and the program header do.
- **"Edit in library"** sends `{ kind: 'workholding', itemId }` through the existing `LibraryLink`; the window opens its Workholding tab (WL3) on the device. A built-in opens read-only, with Duplicate.
- **Detach note:** the inspector sends only the changed field; when the set result no longer names a device for an item that had a copy, the note "Edited here: no longer follows <device>." replaces the device line. It is component state, shown only while the item has no `copyId`, so Undo (one step, WL2) hides it again. **No undo toast:** Plan mode has no toast region yet (the Design navigator owns `removedToast`); ⌘Z and the toolbar's Undo revert the edit. A toast is a later step if dogfooding misses it.
- **Stale per item:** the item's copy in `plan.stale.list`'s `libraryCopies` (by `copyId`): "Library changed" with "Update from library" (`plan.libraryItem.update { planId, snapshotId }`, every item of that copy follows), a blocked update's reason instead of the button, and removed / unreadable as one muted line. The navigator's plan banner names the kind "workholding device".
- **Range findings:** `plan.workholding.outOfRange` (soft) under "Grip on the stock" (`grip`) or "Jaws close along" (`opening`), beside W5's `inPart` under "Centre X".

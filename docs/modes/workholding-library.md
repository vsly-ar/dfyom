# Workholding library: clamps, vises and screws as library items

Status: accepted (hardening DF121, the user's TG #389 "Workholding initially planned to be in the lib too"; [Q133–Q138](#questions-for-the-user) take their recommendations, accepted by delegation D74, 2026-11-26) · Plan of record: [plans/hardening.md](../plans/hardening.md) DF121 · Base: [workholding.md](workholding.md) (WH-A, Q37: inline items now, a library later) · Library: [library.md](../architecture/library.md), [persistence.md § Library references](../architecture/persistence.md#library-references) · UI: [ui-library-window.md](../conventions/ui-library-window.md), [inspector-layout.md](../conventions/inspector-layout.md) (S1–S6), [ui.md § Workholding](../conventions/ui.md#workholding) · Agent API: [llm-api.md](../architecture/llm-api.md) · Terms: [glossary.md](../glossary.md)

Today every workholding item is typed into the setup with built-in defaults ([workholding.md § Model](workholding.md#model)): a toe clamp is 30 mm wide, 60 mm long and 25 mm tall unless the user retypes it in every setup of every plan. The [vision](../vision.md) puts workholding in the library beside stock, tools and machines, and Q37 deferred that until the item kinds settled; W5 and W6 settled them. This doc moves **what a device is** (a clamp's strap, a vise's jaws, a screw's head) into the library and leaves **where it sits** (edge, position, centre) in the setup. No check changes: the obstacles, keep-out, collision check and export guard read the same resolved items as today ([WH-B](workholding.md#decisions)).

## Goals

1. **Describe a device once.** The user's own toe clamps, vise and screws are library items with their real sizes, reused by every plan and project.
2. **Same rules as tools.** A plan uses a library item through a [snapshot](../architecture/persistence.md#library-references): opening a project never reads the library; a library change reaches a plan by "Update from library" or, for `draft` plans, the next Apply ([library.md § Snapshots](../architecture/library.md#snapshots)).
3. **Good defaults without setup.** A new user with an empty library still gets today's items: built-in library items carry today's defaults.
4. **The three placement paths use the library:** Add, Copy from… and Arrange automatically.
5. **Small agent surface:** the existing library tool pattern, within the `tools/list` budget ([Agent API](#agent-api)).
6. **Nothing breaks:** inline items (no library item) stay valid forever; no `schemaVersion` bump, new optional fields only ([pre-alpha rule](../conventions/error-handling/migrations.md#pre-alpha-exception-no-data-preservation-yet)).

Not goals: clamping force, tool holders (WH-F), per-machine fixture tables, moving clamps within a setup (WH-G), formulas in item params.

## Item model

A **workholding library item** is a library item (`kind: 'workholding'`, the [common fields](../architecture/library.md#common-fields): `id`, `name`, `notes`, `revision`, `updatedAt`) with `type`, the setup item's kind (`toeClamp`, `vise`, `screw`, `block`, `base`, `surface`), the **library properties** of that type and an optional `default: true` ([Q135](#questions-for-the-user)). Everything that depends on the stock or the setup stays a **placement** field of the setup item. Values are [quantities](../architecture/quantities.md) entered as strings ([library.md § Command input](../architecture/library.md#command-input)).

| Type       | Library properties (built-in default)                                                                                                                                                                                                       | Placement (setup item)                                                   | Derived at placement                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `toeClamp` | `width` strap width (30 mm); `length` strap length, toe to heel end (60 mm); `top` highest point above the stock top (25 mm); `gripMin`, `gripMax` grip range (optional; 5–15 mm); `stud` thread, display only (optional, ≤ 20 chars: "M8") | `edge`, `at`, `grip` (default: the middle of the grip range, else 10 mm) | today's `reach` = `length` − `grip`; today's `width`, `top` |
| `vise`     | `jawWidth` along the jaws (150 mm; today's `jawLength`); `jawThickness` (20 mm); `jawHeight` (optional; drawn, and the gripped depth in the summary); `maxOpening` (optional); `soft` (false)                                               | `axis`, `protrusion`                                                     | today's `jawLength`, `jawThickness`, `soft`                 |
| `screw`    | `headDiameter` (8 mm); `headHeight` above the stock top (0 = flush or countersunk); `thread` display only (optional: "4 × 40 wood", "M5")                                                                                                   | `center`                                                                 | today's `top` = `headHeight`                                |
| `block`    | `length`, `width`, `height` (no built-in: a block is the escape hatch; see [Built-in items](#built-in-items))                                                                                                                               | `center`, `rotation`, `bottom` (default the table, −T)                   | today's `top` = `bottom` + `height`                         |
| `base`     | `type` (`spoilboard` / `fixturePlate`), `sacrificial`, `thickness` (optional, display; a later link to the machine's `spoilboardThickness` is [not in scope](#not-yet))                                                                     | none                                                                     | as today                                                    |
| `surface`  | `type` (`tape` / `vacuum` / `glue`)                                                                                                                                                                                                         | none                                                                     | as today                                                    |

- **Invariants** (`model.invariant`, paths `values.<field>`): sizes > 0 (`headHeight`, `thickness` ≥ 0); `gripMin` ≤ `gripMax` < `length`; a property not of the item's `type` is `notForKind` (the rule `plan.workholding.set` already uses).
- **Range findings, not invariants.** A placed item outside its device's range is the warning `plan.workholding.outOfRange` (params `{ setupId, itemId, rule }`): rule `grip` (grip outside `gripMin`–`gripMax`), `opening` (the stock across the vise's `axis` wider than `maxOpening`). Warnings never block the export; the user may know better (a longer strap, a vise with reversed jaws).
- **Why the split:** a clamp kit's strap, height and stud do not change between jobs; edge, position and grip do. A toe clamp's `top` is above the stock top because the strap sits on the stock: the same clamp on 6 mm plywood and on 20 mm aluminium stands the same height above Z0.

### Setup item

A setup item placed from the library stores its placement and `copyId`, the id of the plan's [library copy](plan-v0.1.md#plans-are-snapshots) of that workholding item ([Q133](#questions-for-the-user)); it does not store the library properties. `setupWorkholding(setup, stock)` ([workholding.md § Implementation notes](workholding.md#implementation-notes-df59)) resolves an item with `copyId` into today's full item (library properties from the copy, derived fields computed) before anything else reads it, so obstacles, keep-out, `checkWorkholding`, W5's held pieces and W6's search see no difference. An item without `copyId` is an **own item**, exactly today's inline item.

- `name` stays per item ("Toe clamp 2"); the summary adds the device: `front X45 grip 10 top Z25 · Strap clamp M8`.
- **Edits to a library property detach** the item ([Q138](#questions-for-the-user)): the inspector or `plan.workholding.set` writes the resolved values inline, drops `copyId` and keeps the placement, one undo step; the copy stays in the plan while another item uses it, and is removed with the last one (as unused tool copies are).

## Built-in items

The library starts empty ([library.md § Recommended presets](../architecture/library.md#recommended-presets): nothing is seeded), so the defaults live as **built-in library items** ([Q134](#questions-for-the-user)): constants in `src/core/library/workholding-builtins.ts`, listed by `library.workholding.list` with `builtIn: true` beside the user's files, never written to disk.

| Id                                 | Name                                  | Values                                                        |
| ---------------------------------- | ------------------------------------- | ------------------------------------------------------------- |
| `builtin-toe-clamp`                | Toe clamp                             | width 30, length 60, top 25, grip 5–15 mm (today's W6-C size) |
| `builtin-vise`                     | Machine vise 150                      | jaw width 150, jaw thickness 20 mm                            |
| `builtin-screw`                    | Screw, flush head                     | head Ø 8 mm, head height 0                                    |
| `builtin-spoilboard`               | Spoilboard                            | `spoilboard`, sacrificial                                     |
| `builtin-fixture-plate`            | Fixture plate                         | `fixturePlate`, not sacrificial                               |
| `builtin-tape`, `-vacuum`, `-glue` | Double-sided tape, Vacuum table, Glue | the surface types                                             |

- **Units:** each built-in has an mm and an inch value set (inch: W6-C's 1.25″, 2.5″, 1″, grip 3/16–5/8″; vise 6″ × 3/4″; head Ø 5/16″); `list` and `get` return the set of the `units` arg (default `mm`), and a snapshot copies the set of the project's unit system, so an inch project's copy reads `1-1/4"`.
- **Read-only:** `update` and `remove` refuse a built-in (`input.malformed`, rule `builtIn`); the Library window offers Duplicate. A built-in may be the default of its type until a user item claims it.
- **Changing a built-in** in a later app version marks plans' copies "library changed" like any library edit; `draft` plans follow it.
- Blocks have no built-in: a block's sizes are the job's. Add → Block adds an own item, as today.

## Snapshots and persistence

- **Library storage:** `<appData>/library/workholding/<id>.json`, one item per file like the other kinds ([library.md § Storage](../architecture/library.md#storage)); a missing folder means no items. The manifest's `schemaVersion` stays 1.
- **Plan copies:** a plan's library copies gain kind `workholding` (`{ id, kind: 'workholding', libraryItemId, takenAt, values }`, [persistence.md](../architecture/persistence.md#library-references)); a setup item names one by `copyId`. Both are optional additions: a project without them loads unchanged, and no `schemaVersion` changes.
- **Stale and follow:** `plan.stale.list`'s `libraryCopies`, `plan.libraryItem.update` ("Update from library") and the `draft` follow on Apply ([apply.md](../architecture/apply.md#implementation-task-p2)) cover the new kind by their existing rules; nothing new. Updating a copy re-resolves every item that uses it; a region operation's toolpath regenerates as for any workholding change (WH-D).
- **Used chip:** `usedLibraryItemIds` ([`used.ts`](../../src/core/library/used.ts)) already reads every copy's `libraryItemId`, so the Library window marks a used workholding item without change.
- **Removed from the library:** the plan keeps its copy (`libraryRemoved`), as for tools.
- **Export header:** unchanged lines, plus the device after the summary: `(Workholding: Toe clamp 1: front X45 grip 10 top Z25 · Strap clamp M8)` so the operator picks the right clamp ([workholding.md § Program and Run](workholding.md#program-and-run)).

## Placing items

| Path                                                                | Today                                  | With the library                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Add** (inspector Add menu; agent `items` without `libraryItemId`) | an own item with the built-in defaults | UI: the type's **default library item** (Q135) placed at today's default position; the Add menu's entry for a type with several items opens a submenu ("Toe clamp ▸ Strap clamp M8 (default) · Toe clamp (built-in) · Own item"). Agent: unchanged (own item) unless it passes `libraryItemId`. |
| **Copy from…** (`copyFrom`)                                         | copies items, new ids                  | the copies keep their `copyId` (same plan, same copy), so the flipped setup's clamps stay the same device and follow the library together                                                                                                                                                       |
| **Arrange automatically** (`auto: 'toeClamps'`)                     | four clamps of W6-C's fixed size       | four clamps of the **default toe clamp** (Q135), its `width`, `length` and `top` in W6's search, grip the middle of its range; the agent may name another with `autoItemId`. A refusal's message names the clamp ("Four Strap clamp M8 do not fit …")                                           |

- **Default per type** ([Q135](#questions-for-the-user)): a user item with `default: true`, else the type's built-in. Two user items claiming it (two app instances): the later `updatedAt` wins, so setting a default writes one file only.
- The **project's unit system** picks the built-in value set; a user item keeps its own units (`itemUnitSystem`).

## Library window tab

The reserved fourth tab ([ui-library-window.md § Layout](../conventions/ui-library-window.md#layout)): **Machines | Tools | Stock | Workholding**, same window, list, draft and Save rules (L1–L5), and the [inspector-layout](../conventions/inspector-layout.md) conventions S1–S6 for the editor (groups with the DF110 header style, step kinds per field, (i) tips, title-row click, More rows).

- **List:** the type icon of the L1 set (`toe-clamp`, `vise`, `screw`, `block`, `base`, `surface-hold`, [ui.md § Icons](../conventions/ui.md#icons-workholding-offset-deviation)), name, type, main size (toe clamp "30 × 60, top 25"; vise "jaws 150"; screw "head Ø 8"), a "Default" chip, "Used" and "Built-in" chips; a type filter like the tool list. Built-ins sort after the user's items of their type.
- **Editor:** Name; **Device** group with the type's library properties and a front-view **drawing** (the L1 icon's geometry drawn at size with the focused dimension in amber, as the tool drawing does; legend "Strap width", "Strap length", "Top above the stock"); **Range** group (toe clamp grip range, vise max opening) collapsed with its summary when empty; **Details** collapsed (stud or thread, notes). A "Default for toe clamps" switch at the end of Device. Steps: lengths `xy`, heights `z` (S1's kinds).
- **Actions:** "New workholding" (menu of the six types; amber icon), Duplicate, Remove… (as the other kinds; "Projects keep their copies."). A built-in shows its fields read-only with the note "Built-in: duplicate it to change the sizes." and only Duplicate and the Default switch (which writes nothing to the built-in: it clears the user items' flag).
- **Setup inspector** (amends [ui.md § Workholding](../conventions/ui.md#workholding)): an item from the library shows its device under the name ("Strap clamp M8 · from library", a link button "Edit in library" opening this tab with it selected); its library fields are shown and editable, and the first edit shows the note "Edited here: no longer follows Strap clamp M8." with the undo toast. A stale copy shows the plan's usual "Library changed · Update from library".
- Renders: `design/features/renders/wl-library-{light,dark}.png`, `wl-inspector-{light,dark}.png` (hidden e2e, `DFYOM_RENDERS=1`, never visible windows).

## Import and export

The library has no import or export bundle yet (the window's `⋯` slot is reserved for imports, [ui-library-window.md Q5](../conventions/ui-library-window.md#questions-for-the-user-answered)). Workholding items are files beside the other kinds, so whatever library export comes carries them with no extra format ([Q137](#questions-for-the-user)); copying `<appData>/library/workholding/` between computers works today. Built-ins are never exported. A project archive carries its plans' copies, so a project opens with its clamps on another computer (persistence rule).

## Agent API

The existing per-kind library pattern ([library.md § Storage](../architecture/library.md#storage)), `app` scope, `effect` commands (not undoable), quantity strings with `units` ([Q136](#questions-for-the-user)):

| Tool                                          | Args / result                                                                                              | Estimate             |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------- |
| `library.workholding.add`                     | `{ values: { type, name, notes?, default?, …one flat object of every type's properties }, units? }` → item | ≈ 1.5 K              |
| `library.workholding.update`                  | `{ id, revision, values, units? }`, `values` a listed sketch "As library.workholding.add values"           | ≈ 0.5 K              |
| `library.workholding.remove`, `.get`, `.list` | as the other kinds (`list { type? }`; built-ins with `builtIn: true`)                                      | ≈ 0.5 + 0.2 + 0.25 K |
| `plan.workholding.set` (existing)             | items take `libraryItemId` (placement args only; library properties detach); `autoItemId` beside `auto`    | ≈ 0.2 K              |

- **Estimate:** from today's measured sizes (`library_stock_add` 1.3 K, `library_stock_remove` 0.52 K, `get`/`list` 0.23 K each, `plan_workholding_set`'s flat item 2.3 K for the whole tool) **≈ 3.2 K**: `tools/list` 112.8 K → ≈ 116.0 K of the 120 K budget (`TOOLS_LIST_BUDGET_CHARS`), ≈ 4 K headroom left. Target ≤ 3.2 K, measured in WL1 and WL2 and logged in [llm-api.md § Implementation](../architecture/llm-api.md#implementation-task-310). Levers if over: one flat `values` schema with a refinement per type (as the pattern cell, P1), property descriptions only where the name does not say it, the type list in one primer line.
- **Reading:** `plan.get` returns resolved items with `libraryItemId` and `copyId`; no new plan query.
- **Primer:** one sentence: "Workholding devices live in the library (`library.workholding.*`, built-ins included); place one with `plan.workholding.set` items `{ libraryItemId, edge, at }`."

## Questions for the user

Each with a recommendation; "Q133 ok" takes it. Numbering continues after Q132 ([design review U9](../plans/hardening.md#4-ux-and-ax)).

1. **Q133 – How a placed item keeps its library values.** (1) As a **plan library copy** (snapshot) of kind `workholding` that the setup item names by `copyId`, like tools; (2) an inline copy in each item with `libraryItemId` and `takenAt`; (3) no link: the library is only a template, values are copied and forgotten. _Recommendation: (1)._ It reuses "library changed", Update from library, the `draft` follow, the Used chip and the project archive rule with no new machinery; (2) duplicates the snapshot logic per item; (3) loses "the clamp kit changed" for every plan.
2. **Q134 – Built-in defaults.** (1) **Read-only built-in items** in code, listed in the tab, usable and duplicable; (2) seed files written into the user's library on first open; (3) none: the inline defaults stay as today. _Recommendation: (1)._ Nothing is written or migrated, a changed default reaches every plan through the normal stale path, and the user's library stays only what they made.
3. **Q135 – Which item Add and Arrange automatically use.** (1) **One default per type** in the library (`default: true`; else the built-in); (2) a default per machine (the machine lists its workholding); (3) the last one used in the project. _Recommendation: (1)._ You run one machine (Q49); a per-machine kit is a later field on the machine if a second machine comes.
4. **Q136 – Agent API.** (1) **Five tools `library.workholding.{add,update,remove,get,list}`** like the other kinds, plus `libraryItemId` and `autoItemId` on `plan.workholding.set` (≈ 3.2 K); (2) generalize the existing `get`/`list`/`remove` with a `kind` arg (≈ 2.5 K, but it changes nine existing tools); (3) one declarative `library.workholding.set` (≈ 1.7 K, but no revision check per item, unlike the rest of the library). _Recommendation: (1)_, within ≈ 4 K of headroom after it.
5. **Q137 – Import and export.** (1) **No separate format:** workholding files ride along with the library export when it comes (a backlog item for all kinds); (2) build a whole-library export/import bundle now as slice WL5; (3) a workholding-only export. _Recommendation: (1)_; say "Q137 2" to add WL5.
6. **Q138 – Editing a library property on a placed item.** (1) **Detach:** the item becomes an own item with the edited values (one undo step, a note says so); (2) keep per-item overrides beside the copy, like a tool's stickout; (3) read-only in the setup: edit the device in the library. _Recommendation: (1)_: one rule, no hidden override state, and a one-off longer strap does not change the kit.

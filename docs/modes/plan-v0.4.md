Status: accepted (D34, 2026-11-22: the user took every recommendation of [Q28–Q35](../plans/v0.4.md#questions-for-the-user); proposed 2026-11-22 with [plans/v0.4.md](../plans/v0.4.md)) · Design: [design-v0.4.md](design-v0.4.md) · Concept: [features.md § Plan](features.md#plan) · v0.1 strategies and generators: [plan-v0.1.md](plan-v0.1.md#pass-strategies-v01) · v0.3 generators: [plan-v0.3.md](plan-v0.3.md) · Feeds: [feeds-speeds.md](../architecture/feeds-speeds.md) · Post: [grbl.md](../architecture/grbl.md) · Tasks: [plans/v0.4.md](../plans/v0.4.md) · Terms: [glossary.md](../glossary.md)

Plan sees **operations only**: hole and Clones features expand to drillings, circular pockets and chamfers, so v0.4 adds exactly one generator (the chamfer) and one tool type to the checks. Counterbores are v0.1 circular pockets and holes are v0.1 drillings (drill or [helical boring](plan-v0.1.md#toolpath-generators-task-210)); nothing new is needed for them.

## Chamfer toolpath

Input: the chamfer's axis point (the edge centre in the face frame), the edge diameter d, the chamfer diameter D, the included angle α, the face Z; the tool's DC, tip diameter dt and angle. A V-bit's cutting cone of half-angle α/2 touches the chamfer cone along its whole slant only when the angles match (the fit rule, [design-v0.4.md § Chamfer operation](design-v0.4.md#chamfer-operation-v04-circular-edges)).

- **Plunge** (DC ≥ D and dt ≤ d): rapid to the centre at the clearance height, feed down at `plungeRate` to the Z where the tool's cone has diameter D at the face (tip Z = face − (D − dt) / 2 / tan(α / 2)), short dwell optional (strategy `dwell`, default 0), rapid out. The hole below lets the tip pass through the edge diameter without cutting.
- **Contour** (DC < D): the tool axis runs one circle of radius r so the cutting cone meets the chamfer from d to D. With slant height s = (D − d) / 2 / sin(α / 2) and usable cutting length l of the tool's cone, the fit rule guarantees s ≤ l, so one ring at full depth cuts it (several rings would be stepped clearing, later). Entry: a ramp along the first circle from the hole side (inside the edge diameter, which is already cut), climb direction, arcs as `G2`/`G3` ([plan-v0.3.md T-B](plan-v0.3.md#decisions)); exit: lift on a tangent arc into the hole.
- **Order checks:** a chamfer must cut after its `edgeOf` operation in the same setup ([order checks](plan-v0.1.md#plan-operations-and-order)); `plan.order` blocks the reverse.
- **Strategy parameters:** `entry` (`plunge`, `contour`, `auto` = P-C), `dwell`, `rampAngle` (contour); nothing else. A finishing pass is not offered (one ring cuts to size). As built ([Implementation (T1)](#implementation-t1)): `auto` is the default (no stored value), `dwell` is later.

### Stepped chamfer (F7)

A chamfer with a `stepdown` (the stepped countersink, [design-v0.4.md § Stepped countersink](design-v0.4.md#stepped-countersink-f7-d41), D41) is cut by a **flat end mill** as terraces; Plan resolves its `entry` to `stepped` (a stored `plunge` or `contour` is `strategy.entry` `stepped`), and `rampAngle` applies.

- **Terraces:** N = ⌈h / stepdown⌉ of height t = h / N (h the chamfer depth), terrace k a circle of radius r<sub>k</sub> = D / 2 − (k − 1)·t·tan(α / 2) at depth k·t, top to bottom, so every top step corner lies on the cone.
- **Rings per terrace** (tool radius R): the outermost has its axis at r<sub>k</sub> − R; inner rings (spacing ≤ DC / 2, equal) until the innermost, at most d / 2 + 0.4·DC, reaches into the hole. Usually one ring: an end mill that bores the hole has DC > d / 2.
- **Moves:** rapid to the first terrace's innermost ring start (−90°) at clearance and retract, feed down to the face at `plungeRate` (inside the hole); per terrace a **ramp along the innermost ring** from the level above to k·t (whole turns, at most `rampAngle`, never descending faster than `plungeRate`; a straight plunge below r = 0.1 mm), one full ring at k·t, then each outer ring after a radial feed outward; then a radial feed back in to the next terrace's innermost ring (cleared). After the last terrace, feed to the centre (the hole) and rapid out. Climb (counter-clockwise inside the hole), one pass of kind `rough`.
- **Checks:** tool type `flatEndMill`, DC < d (`plan.check` `diameter`), reach to h; the generator re-checks type, size and the terrace count (≤ 1000).
- **Feeds:** the end mill's helical-boring engagement `helix { ap }` with ap = t (the hole's helix uses the same tool), drilling's field list.
- **One tool:** the drilling and the chamfer get the same design tool ([design-v0.4.md § Stepped countersink](design-v0.4.md#stepped-countersink-f7-d41)), so a plan holding only them changes tools once; the default order (drillings, pockets, chamfers) can put another tool between them in a larger part (reorder, or use the same end mill there).

## Implementation (T1)

The generator is `generateChamfer` (`src/core/toolpath/chamfer.ts`), request kind `chamfer` (one input per chamfer in nearest-neighbour order, joined as drilling holes are). Plan side: `strategy.ts` (`chamferCuts`, entry resolution), `checks.ts`, `order.ts`, `evaluate.ts` (F10 depth).

| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contour ring   | The tool axis on the ring of radius **r = (d − dt) / 2**, tip at the chamfer depth `(D − d) / 2 / tan(α / 2)` below the face: the tip's edge sits on the edge Ø and the cone lies on the chamfer from d to D (equal angles); the fit rule (DC − dt ≥ D − d) makes its top reach D. The tip never leaves the hole.                                                                                                                                                                                                 |
| Contour moves  | Rapid to the ring start (−90°) at clearance and retract, feed down to the face at `plungeRate` (inside the hole, nothing cut), a ramp along the ring in whole turns (each at most `rampAngle`, never descending faster than `plungeRate`, as helical boring), one full ring at depth at `feedRate`, then a **tangent half circle of radius r / 2 to the centre** at depth (the cone leaves the wall at once), rapid out. Climb = counter-clockwise inside a hole; below r = 0.1 mm the ramp is a straight plunge. |
| Plunge         | Rapid to the centre, feed to the tip Z `face − (D − dt) / 2 / tan(α / 2)` at `plungeRate`, rapid out. One pass of kind `finish` for both entries.                                                                                                                                                                                                                                                                                                                                                                 |

## Implementation (F7)

The stepped chamfer ([§ Stepped chamfer](#stepped-chamfer-f7)): `generateChamfer` hands an input with entry `stepped` (or a `stepdown`) to `generateSteppedChamfer` (`src/core/toolpath/chamfer.ts`; `terraceRings`, the ramp shared with the contour as `rampRing`). Plan: `strategy.ts` resolves `stepped` (rule `strategy.entry` `stepped` for a stored entry; `cutDepth` = the terrace height), `checks.ts` (tool type `flatEndMill`, `chamferFit` with the stepdown), `feeds.ts` (`helix { ap }` for an end mill on a chamfer), `toolpath/inputs.ts` (entry per chamfer). Tests: `stepped-chamfer.test.ts` (heightmap oracle: top corners on the cone, no stock inside it, nothing below the terraces or more than one terrace past the cone, nothing outside D; path rules; rings; refusals; golden `chamfer-stepped.txt`), GRBL golden `countersink-stepped.nc` (helical hole + terraces, one tool, streamed through the virtual machine), `plan/stepped-countersink.test.ts` (one end mill, no tool change in the export).

## Plan side

How it is built: [Implementation (P1)](#implementation-p1).

- **Grouping:** P-B plus the existing hole grouping; Clones need nothing else ([features.md § Plan and cut order](features.md#plan-and-cut-order)).
- **Plan-only edits** work per owned operation, as [features.md § Plan](features.md#plan) says; a rebuild discards them as today.

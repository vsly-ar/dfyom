# Run: Go to coordinates

Status: accepted, implemented ([§ Implementation (GT1)](#implementation-gt1), [§ Implementation (GT2)](#implementation-gt2)) (2026-11-27; hardening [DF128](../plans/hardening.md#intake-user-feedback-goes-here), the user's TG #413: "Run mode: when clicking work or machine coordinates, open a "GO TO" dialog that allows entering coordinates to move to in the selected frame of reference (ignore jog hotkeys while this dialog is open)"; [Q154–Q157](#questions-for-the-user) take their recommendations, accepted by delegation D79) · Base: [run.md § Machine frame and manual control](run.md#machine-frame-and-manual-control-hardening-df31df35), [run-machine.md § Machine readiness](run-machine.md#machine-readiness-m3) (jog, DRO) · UI: [ui.md § Jog, position and probing](../conventions/ui.md#jog-position-and-probing-df88), [§ Jog hotkeys](../conventions/ui.md#jog-hotkeys) · Safety: [run.md § Safety](run.md#safety) · GRBL facts: [grbl.md](../architecture/grbl.md#homing-and-machine-coordinates) · Terms: [glossary.md](../glossary.md)

Clicking a coordinate in the Run inspector's Position table (the DRO) opens a **Go to** dialog: type where the spindle should go, in work or machine coordinates, see the move before it happens, press Enter. It replaces "jog 10, jog 10, jog 1, jog 0.1 …" for the common moves: back to the work zero, above a feature, to a measured point, to the front of the table to change a bit.

## What the user does

1. **Click a value** in the Position table: a work coordinate ("Work X 120.400") opens the dialog in the **work** frame, a machine coordinate in the **machine** frame, with that axis's field focused and its text selected. Each value is a button (accessible name "Go to: X 120.400 work"; the per-axis "0" zero buttons stay where they are, [ui.md DF88](../conventions/ui.md#jog-position-and-probing-df88)).
2. **Type** the target. The X, Y and Z fields start at the current position in the chosen frame, so an axis left as it is does not move. Fields are quantity fields in the project unit and take expressions (`120.4 + 3/8in`, [quantities.md](../architecture/quantities.md)).
3. **Check the preview** (below): the steps, the path drawn in the 3D view, the time.
4. **Enter** (in any field) or **"Go"** starts the move. The dialog stays open while the machine moves, showing the step it is on, and closes itself on arrival.

| Control                   | Behaviour                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Frame**                 | Segmented control "Work (G54)" / "Machine (G53)". Switching converts the fields' values (through the live work offset), so the target point stays the same.                                                                                                                                                                                                                 |
| **Absolute / Relative**   | Absolute (default): the fields are the target. Relative: the fields start at 0 and are the distance to move; the frame does not matter then (the work offset is a translation), so the frame control is disabled with "Relative moves are the same in both frames."                                                                                                         |
| **Shortcuts**             | Small buttons under the fields that fill them (nothing moves until Go): "Work zero XY" (X 0, Y 0, Z unchanged, work frame), "Work zero" (X 0, Y 0, Z = the safe height above the zero, [Q154](#questions-for-the-user)), "Machine top Z" (machine Z −pull-off, the highest point Z can reach without touching its switch).                                                  |
| **Lift to the top first** | Checkbox: raise Z to the machine top before any X/Y move, whatever the target. Off by default, remembered per window ([Q154](#questions-for-the-user)).                                                                                                                                                                                                                     |
| **Go**                    | The primary button, enabled when every field is valid and the move passes the checks below; Enter in a field is the same.                                                                                                                                                                                                                                                   |
| **Stop** (while moving)   | Replaces Go: the jog cancel (`0x85`), which stops with GRBL's deceleration and drops the remaining steps; the dialog then says "Stopped at X … Y … Z …" and offers Go again. `Escape` does the same and closes the dialog (`Escape` already stops a jog and closes the top overlay, [ui.md § Jog hotkeys](../conventions/ui.md#jog-hotkeys)). The toolbar's Stop works too. |

## The move: safe order

A go-to never drags the tool sideways lower than it has to be. The steps (each one straight line):

1. **Up first** when the target Z is higher than the current Z: Z alone to the target Z.
2. **Lift for X/Y** when X or Y changes and the tool is below the **safe height** (the work zero Z plus the clearance of the chosen plan's setup, else 5 mm; capped at the machine top): Z alone up to the safe height. After a stopped run the tool can sit in the stock; this keeps it from cutting a trench on its way out. "Lift to the top first" raises to the machine top instead.
3. **X and Y together** to the target, at the Z reached so far.
4. **Down last** when the target Z is lower than the Z reached: Z alone to the target.

So a move that only lowers Z is one step, a move from inside the stock to the work zero is three (up, across, down), and nothing moves X/Y below `max(current Z, target Z, safe height)`, except a pure X/Y move already above the safe height. The order is computed again from the live position when Go is pressed (the machine may have moved since the dialog opened).

**Feed:** X/Y at the jog feed slider's value, Z at the lower of it and the machine's Z max rate, as the jog pad ([ui.md DF88](../conventions/ui.md#jog-position-and-probing-df88); [Q155](#questions-for-the-user)). The dialog shows it ("at 2000 mm/min").

## Preview

- **Steps list** in the dialog, one line per step in the dialog's frame and the project unit: "1 · Up to Z 15.000", "2 · To X 0.000 Y 0.000", "3 · Down to Z 1.000", each with its length, and the total time at the jog feed (trapezoid-free estimate, rounded up to the second: "about 6 s").
- **3D view:** while the dialog is open the run scene draws the path as a dashed polyline from the tool marker through each step's end to a target marker (accent colour, the one accent of the view; eased in with `--motion-fast`, instant under reduced motion), and updates it as the fields change. The dialog has no dark scrim and sits at the bottom of the window's end edge, over the inspector's lower groups, so the view and the Position table stay visible; focus is held in the dialog like any modal ([GT2](#implementation-gt2)).
- **Screen readers:** the steps list is the preview's text equivalent (`aria-describedby` of Go).

## Checks

Checked in the dialog on every change, with each finding next to its field and Go disabled; the host checks again ([run.md DF33](run.md#machine-coordinates-and-the-homing-corner-df33)).

| Check                                   | Refusal (dialog wording)                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Inside the travel**, every step's end | "X would leave the travel: the target is at machine 12.000, the travel is −800 to 0 mm." Checked against the controller's travel (`RunStatus.envelope`, from `$130–$132`) whether soft limits are on or not; the host's check (soft limits on) and GRBL's `error:15` stay.                                                                                                                                         |
| **Position known**                      | Not homed ("—" in the DRO, [run.md DF46](run.md#run-mode-presentation-df46)): the coordinate buttons are disabled with "Home the machine first: the position is unknown." No go-to from an unknown position, unlocked or not.                                                                                                                                                                                      |
| **Nothing else moving or running**      | Only with no run job (not at a tool-change or pause wait either: those dialogs have their own jog pad and "Move to touch-off spot", [z-reference.md](z-reference.md#implementation-notes-df69)) and in `Idle`. In `Jog` the dialog opens but Go waits for Idle ("The machine is still jogging."). Alarm, Hold, Door, Home, Check, not connected: disabled with the state's reason, the same texts as the jog gate. |
| **Spindle off**                         | The status reports a running spindle (`FS` rpm > 0): "Stop the spindle first." (rule `spindleOn`, as `run.align.goto`). A hand-switched router reports nothing; the dialog's footer says "Make sure the spindle is off." on a real machine.                                                                                                                                                                        |
| **Something to do**                     | The target equals the position (within 0.001 mm): Go disabled, "Already there."                                                                                                                                                                                                                                                                                                                                    |

**Workholding guard** (hardening DF133 RW4, [run-workholding.md § Go to and the touch-off spot](run-workholding.md#go-to-and-the-touch-off-spot)): while the guard is on (homed, G54 set, a plan setup with items), every step runs through it on each change; a step that would come within the margin of an item is a finding under the steps with Go disabled, the path red from the contact on, and "Go anyway (the clamps are not where the plan says)" for that move; "Jog past once" covers the next Go to. Guard not on: exactly as above.

A real connection follows the jog rules: no confirmation beyond the dialog itself (the steps list and Go are the confirmation, [run.md § 3](run.md#3-confirmations-before-motion)), UI only ([run.md § 2](run.md#2-who-may-command-a-real-connection-q50)).

## Keyboard

- **Jog hotkeys are off while the dialog is open**, wherever the focus is (the user's request): the hotkey hook is inactive while the run store's `goToOpen` is set, not only when focus is in a text field. So `Space` (Z+ in the WASD style) types nothing and jogs nothing, and `Shift` while typing never jogs Z−.
- `G` (focus not in a text field, no dialog or menu open, connected, homed, no run job) opens the dialog in the work frame with X focused, as the jog section's "Go to…" menu item does ([Q157](#questions-for-the-user)).
- `Enter` in a field: Go (after the field commits its expression). `Escape`: while idle closes the dialog; while moving stops (jog cancel) and closes. `Tab` order: frame, absolute/relative, X, Y, Z, shortcuts, lift checkbox, Go, Cancel.
- A field holding an invalid value keeps Go disabled; `Escape` inside the field first restores its value (quantity field rule), a second `Escape` closes.

## G-code

Every step is one GRBL jog with an **absolute machine target**, whatever frame the user typed in:

```
$J=G21 G53 G90 X-412.300 Y-233.000 Z-1.000 F2000
```

- **Why `$J=` and not `G0`/`G53 G0`:** a jog is cancellable at once with `0x85` (a `G0` needs a feed hold and a reset to drop), refused with `error:15` instead of `ALARM:2` when it would leave the travel, leaves the program's modal state alone, and runs only in Idle/Jog, so it can never sneak into a run. GRBL queues several `$J=` lines and runs them in order, so the steps follow each other without stopping between them; one `0x85` cancels them all.
- **Why machine targets:** the dialog converts a work target with the work offset of the last status report (`WCO`, which also contains any `G92` a file left), so the travel check is exact and the controller's active work coordinate system (G54 in DFYOM, [run.md DF93](run.md#run-an-external-g-code-file-df93)) cannot surprise. The existing `run.machine.jog { to }` already sends exactly this line (`src/core/run/host/host.ts`) and checks it against the travel; "Move to touch-off spot" and the alignment pointer use it the same way ([alignment.md](alignment.md)).
- Units: always `G21` (commands take mm; the dialog converts inch input).

## Agent API

None new ([Q156](#questions-for-the-user)). The dialog is a UI composition of `run.machine.jog { to, feed }`, one call per step (the run store's `moveTo`, as `TouchOffButton`), which agents already have: on the virtual machine an agent goes to a point with the same tool; on a real machine motion stays UI only (Q50). The step order lives in a headless function (`goToMoves`, below), so a later agent tool could reuse it; `tools/list` is unchanged.

## Questions for the user

Numbering continues after [tapered-ball-nose.md](tapered-ball-nose.md#questions-for-the-user)'s Q153. "Q154 ok" takes the recommendation; "all ok" takes every one.

1. **Q154 – Order and safe height.** (1) **Z up first unless going down, plus a lift to the safe height (work Z0 + setup clearance, else 5 mm) before any X/Y move made below it; "Lift to the top first" as an opt-in checkbox.** (2) Only "Z up first unless going down" (X/Y at the current Z when going down). (3) Always via the machine top for any X/Y move. _Recommendation: (1)._ (2) drags a tool that stopped inside the stock through the material; (3) is safest but turns every small reposition into a long trip to the top and back.
2. **Q155 – Feed.** (1) **The jog feed slider (Z capped at the Z max rate), shown in the dialog.** (2) The machine's max rates, like a rapid. (3) A feed field in the dialog. _Recommendation: (1)._ It is the speed the user already chose for moving by hand, and a jog cannot rapid anyway (`$J=` needs `F`); (3) adds a field to every move for a rare need: the slider is one control away.
3. **Q156 – Agent API.** (1) **None: the dialog sends `run.machine.jog { to }` per step, which agents already have.** (2) A `run.machine.goTo { target, frame }` tool that applies the safe order. _Recommendation: (1)._ The tool list is near its budget (≈ 116.9 K of 120 K) and no agent may move a real machine; an agent on the virtual machine can already send the steps.
4. **Q157 – Where the dialog opens from.** (1) **The DRO values only (the user's request), plus a "Go to…" item in the jog section's menu for keyboard users (`G` while no field has focus).** (2) DRO only. (3) Also from the 3D view: double-click a point to go above it. _Recommendation: (1)._ (3) is attractive but needs picking on the run scene and a Z rule for a clicked surface; it can follow once the dialog exists.

## Implementation (GT1)

Status: GT1 implemented (2026-11-27); GT2 followed ([below](#implementation-gt2)).

- **Core** (`src/core/run/goto.ts`, pure, `goto.test.ts`): `goToMoves({ from, wco, target, frame, mode, safeZ, liftToTop, envelope })` → `Ok(GoToStep[])` (empty = already there, 0.001 mm per axis) or `Err(run.travel)` with `{ axis, target, min, max, step }` for the first step end outside `[−travel, 0]`. One **Z-up** step goes to `max(current Z, target Z, lift)` where the lift is the safe height (or the machine top with "Lift to the top first") only when X or Y changes; then X/Y together; then Z down if the target is lower. So the doc's steps 1 and 2 merge into one Z move (both are Z alone, the same line). `goToSafeZ` takes the **stock top** of the current work zero (`WCO Z − zeroLevel`, as "Move to touch-off spot", DF69), so a Z zero set on a lower surface does not lower the safe height; plus the chosen plan's setup clearance, else 5 mm; capped at `machineTopZ` (−pull-off; 0 without an envelope). `goToTarget` converts work → machine with `WCO = MPos − WPos` (G54 and any G92). `goToLengths`/`goToSeconds` give the steps list's lengths and the "about N s" estimate (no acceleration, rounded up).
- **Gates** (`machine-state.ts`): `goToOpenGate` disables the DRO buttons (not connected; not homed: "Home the machine first: the position is unknown."; a run job, tool-change and pause waits included). `goToGate` adds the jog gate's reasons (alarm → "Home the machine first.", hold, door, homing …), "The machine is still jogging." and "Stop the spindle first." (`FS` rpm > 0). On a real connection the status line says "Make sure the spindle is off." while nothing else is wrong.
- **DRO** (`Dro.tsx`): each work and machine value is a ghost button inside its cell (the cells keep their names "Work position X" …), accessible name "Go to: X -40.000 work"; a disabled one keeps the value's colour (the DRO stays readable during a run) and is described by the gate.
- **Dialog** (`GoToDialog.tsx`, mounted in `RunDialogs`): `goTo { frame, axis }` in the run store opens it (`openGoTo`/`closeGoTo`); "Lift to the top first" is `goToLiftTop` per window. A fresh form per opening, fields at the position of that moment, the clicked axis focused with its text selected. Fields are the app's `Field` + `FieldInput`, one per row, parsed with the quantity grammar (`quantityFromSource`: `12.5`, `100 - 2`, `3/8in`) in the project unit, **not** the full `QuantityInput` (no adjust panel or steps: a position is typed, not tuned; decided here). Frame and mode switches keep the target point (absolute → relative fills 0; relative → absolute fills position + distance). Shortcuts switch to absolute (and the work frame for the two work-zero ones); "Machine top Z" keeps the frame.
- **Go / following the move:** Go (or Enter in a field) recomputes the steps from the live status and sends them with the run store's `moveTo` (`run.machine.jog { to, feed }` each; X/Y at the jog feed, Z at `min(jog feed, machine Z max)`). The dialog follows the status: the step under way is the last whose segment passes within 0.01 mm of the position (reports may skip a step end); `Idle` at the last end closes the dialog; `Idle` short of it after jogging, a refusal or any other state shows "Stopped at X … Y … Z …" and Go again.
- **Stop while moving:** the footer's run Stop (the convention of every run dialog, [ui.md](../conventions/ui.md#run-mode-safety-ui); without a run job it is the jog cancel) instead of Go turning into a second "Stop" button; Escape and Cancel stop (jog cancel) and close. Escape in a field whose text differs from what was filled restores it first.
- **Presentation (GT1):** the standard modal `Dialog` with its scrim and the run dialog footer; the no-scrim placement over the inspector comes with the 3D path in GT2. Focus returns to the DRO value that opened it.
- **Jog hotkeys:** `JogHotkeys` passes `active = false` while `goTo` is set, so no key jogs whatever the focus; `Escape` still cancels a running jog.
- **Tests:** `goto.test.ts` (order up/down/inside the stock/lift to top/pure Z/pure X/Y, frames with a non-zero WCO, relative, every travel edge, already there, safe height, lengths and time), `machine-state.test.ts` (`goToGate`), `GoToDialog.test.tsx` (DRO buttons and their gate, opens on the clicked frame and axis, Enter sends the safe order and arrival closes, Stop → "Stopped at", Escape restores / stops / closes, WASD/Space/Shift do nothing while open, frame/mode/shortcuts, travel/invalid/spindle/jogging/alarm gates; axe), `e2e/run-goto.e2e.ts` (virtual machine: open from Work X, jog keys ignored, from inside the stock to work (0, 0, 2) with X/Y never below the safe height, arrival closes; `df128-goto` light/dark with `DFYOM_RENDERS=1`).

## Implementation (GT2)

Status: implemented (2026-11-27). DF128 is done.

- **Path in the 3D view** (`viewport/GoToPath.tsx`, drawn by `RunLayer` as `RunScene.goTo`): the dialog publishes the steps it lists as `goToPreview { from, points }` (machine coordinates) in the run store, by value, so a status report that moved nothing republishes nothing; `useRunScene` turns them into work coordinates as it does the tool marker (`− WCO`, plus the Z zero level of DF69) and the layer draws a dashed polyline (drei `Line`, 2 px, dash 3 / gap 2 mm) from the tool tip through each step's end, and at the target a ring with a crosshair and a small chip "Go to target", all in `--vp-selected` (the view's accent) and without depth test, so a path inside the stock stays visible. It fades in over `--motion-fast` (none under reduced motion). Live: every field, frame, mode, shortcut or lift change redraws it; an invalid field, a travel finding or "Already there" draws none; while moving it shows the steps being run (from where the move started); closing clears it. The tool marker itself is unchanged (it follows the status).
- **Time estimate:** the steps' header reads "about N s", from a minute on "about 2 min 5 s" (`goToSeconds`, no acceleration, rounded up; decided here).
- **Placement** (`Dialog placement="end"`): still a modal Radix dialog (focus trapped, Escape closes, outside click closes, the rest of the window hidden from assistive technology), but the overlay is transparent and the dialog sits at the **bottom of the end edge** (12 px from the edge, 40 px above the window bottom), sliding in from the end over `--motion-slow`. Decided here, against the design's "over the inspector" at the top: at the bottom it leaves the Position table (the DRO the dialog was opened from, which counts while the machine moves) and the main toolbar's Stop in view, and covers only the inspector's lower groups and the view's lower right corner. Clicking outside still closes it (and stops a move, as Escape), as any modal; orbiting the view while it is open is not possible (the clear scrim takes the pointer).
- **"Go to…" in the jog section** (Q157): the navigator's Jog section title has a menu button "Jog options" (the `more` icon) with one item "Go to…", shortcut `G`, described "Type coordinates to move to, in work or machine coordinates"; disabled with the DRO buttons' reason (`goToOpenGate`: not connected, position unknown, a run job). It opens the dialog in the work frame with X focused, once the menu has closed (`Menu`'s new `onCloseAutoFocus`, prevented, so the menu does not focus its button and take the focus back from the field); focus returns to the menu button when the dialog closes (`GoToRequest.opener`).
- **`G`** (`useGoToHotkey` in `useJogHotkeys.ts`, mounted with the jog hotkeys in Run mode, `goToKeyOpens`): the plain key (no Ctrl, Cmd, Alt or Shift, no auto-repeat), never while typing (`isEditableTarget`), never while a dialog, alert or menu is open, and only through `goToOpenGate` (so never during a run job, tool-change or pause wait, unconnected or not homed). Listed in the Keyboard shortcuts dialog's "Run: jog" group as "Go to coordinates…".
- **Tests:** `GoToDialog.test.tsx` GT2 block (the published preview follows the fields and clears on close; the end placement over a clear scrim, still modal; `G` opens it, not in a text field, not with Cmd/Ctrl, not during a run job, and is text inside the dialog; the jog menu item disabled with why, then opening with X focused and focus back on the menu button; axe; the minute format), `e2e/run-goto.e2e.ts` (`G` and the menu open it; the target chip `[data-goto-target]` shows and is not under the dialog; the go as in GT1; the footer's Stop mid-move at a low jog feed leaves "Stopped at …"; `df128-goto` light/dark).

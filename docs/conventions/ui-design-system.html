dfyom design system

Task 1.16, approved 2026-11-20; changes since approval are badged and listed in the changelog. Every colour, size and timing the app uses comes from the tokens on this page; components never pick values of their own. Specimens render in both themes side by side.

Accent: Amber #f5b700

Principles

A desktop toolNative title bar with the document name only. Toolbars, panels and a status bar. No branding inside the window.
Colour is a signalNeutral by default. Amber marks what is on, selected, active or being cut. Never a large fill.
Running is amberA running machine is the most dangerous state and needs attention, so it takes the accent. Red, orange and blue machine states stay reserved.
Highly graphicalFields carry an illustration of what they measure; the measured part turns amber while you edit it.
Dense, not cramped13 px text, 28 px controls on a 4 px grid. Beginners get clarity through labels, terms and hints, not fewer controls.
Motion explainsIndicators slide, toolpaths draw in, selections pulse. Every animation has a reason and turns off with reduced motion.

Amber is used for
  • Active states: switch, checkbox, radio, the selected segment, slider fill, progress, current mode underline.
  • One detail of the active tool's icon, and of the focused field's illustration.
  • Running: the machine state while the machine moves, and the cut in the viewport.
  • A suggested fix: the field's pencil turns amber.
  • Selection: a pale tint behind normal text; the selected shape and toolpath in the viewport.
  • The suggested action in a panel: calm tint, amber-brown label.
  • Focus ring.
Amber is never used for
  • Window chrome, panel or toolbar backgrounds, body text.
  • Solid button fills, including the suggested action.
  • Warnings, Feed hold, Alarm or Tool change (orange, red and blue).
  • Decoration: dividers, headings, logos, illustrations.

In the light theme, pure amber is too pale for thin lines and text on Ghost White (1.7:1). Icon details stay saturated (--accent-icon, pure amber) with a slightly heavier stroke and a faint dark edge; text uses --text-accent (5:1); solid amber fills get a 1 px deeper edge. The viewport keeps a clean amber line (2.5 px) and gets its edge from a soft dark halo instead of a darker colour. The dark theme uses pure amber throughout.

Icons

Lucide for generic actions; own CNC icons on the same 24 px grid with a 1.35 px stroke at 16 px. Own tool icons have one accent detail (corner handles, the dashed offset of a profile, the drill's crosshair) that turns amber only while the tool is active. Generic Lucide icons stay monochrome. Field illustrations (28 px, thinner 1.4 px lines) draw the feature in grey and make the measured edge itself the amber line: the wall for depth, the riser for stepdown, the arc for a corner radius, the face for a chamfer. No dimension arrows.

Changes to earlier decisions

This proposal changes things recorded in the UI guidelines. Approving the design system approves these too:

  1. Denser UI (you chose it): base text 13 px instead of 14 px, default controls 28 px instead of 32 px (decisions 8 and 9). Run mode keeps 44 px.
  2. Warnings and Feed hold are orange (you chose it), with the triangle and the striped pause-bar shapes.
  3. Running is amber, not green: play icon and a dot circling the badge edge; a static outline under reduced motion. This departs from the IEC 60204-1 green-for-normal convention on purpose.
  4. No coloured primary button. Primary keeps the neutral surface and is set apart by a semibold label, a stronger outline and an amber icon; Stop is the only filled control.
  5. Mode switcher is its own component, separate from ordinary tabs. Where it sits is left to the window layout work.
  6. Three severities, not two. Soft warning (neutral, dismissible; stays as a small marker), hard warning (orange, can't be dismissed), error (red, impossible value, blocks Generate). Orange moves slightly towards yellow to separate from red.
  7. Field component grows: illustration icon, a lock just before the input, a tinted pencil inside it (adjust popover with steps .001–100 and the recommended value), and one support group under it (echo, highest-severity status with its fix, collapsed extra notes).

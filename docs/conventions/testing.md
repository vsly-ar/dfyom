## Layers

| Layer           | Tool                                                                                                        | Scope                                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Unit            | Vitest project `node` (`vitest.config.mts`)                                                                 | `src/core`, `src/shared`, `src/main`, `scripts`, renderer logic. Colocated `*.test.ts` next to the code.                       |
| Component / UI  | Vitest project `ui` (jsdom, Testing Library, axe-core), [ui.md](ui.md#testing)                              | Renderer components (`src/renderer/**/*.test.tsx`), tooltips, previews.                                                        |
| End-to-end      | Vitest, spawned bundled CLI (headless); Playwright for Electron (`e2e/*.e2e.ts`, `npm run e2e`) for the app | Whole app, driven like a user **and** like an agent ([llm-api.md](../architecture/llm-api.md)); see [End-to-end](#end-to-end). |
| Virtual machine | GRBL emulator ([ADR 0013](../decisions/0013-grbl-first-controller.md))                                      | Simulated CNC controller + simulated devices; run-mode tests without hardware ([modes/run.md](../modes/run.md)).               |
| Real machine    | _TBD_                                                                                                       | LLM-controlled runs on real hardware with minimal developer involvement; opt-in only.                                          |
| Performance     | Vitest, `*.perf.ts` (`vitest.perf.config.mts`, `npm run perf`)                                              | Benchmarks for heavy operations with budgets; not in `npm run check` (flaky timings).                                          |

## Commands

- `npm test` – all unit tests once; `npm run test:watch` – watch mode; `npm run perf` – performance budgets (e.g. [geometry](../architecture/geometry.md#performance-budgets-v01)).
- `npm run lint` – ESLint incl. layer import boundaries ([ADR 0015](../decisions/0015-eslint-with-typescript6-api.md)); `npm run lint:fix` applies safe fixes.
- `npm run format` / `npm run format:check` – Prettier (owns formatting; ESLint does not).
- `npm run check` – `typecheck` + `lint` + `format:check` + `test`. Run before committing.
- `npm run e2e` – builds the app (`electron-vite build`) and runs the Playwright-for-Electron tests ([app tests](#app-playwright-for-electron)); not part of `check` or CI. Run it after changes to main, preload, the renderer entry, workers or the build.
- **CI** ([`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)) runs `npm ci` + `npm run check` on every push and pull request to `main`, with Node from `.nvmrc`.

## End-to-end

The [v0.1 exit criteria](../plans/v0.1.md#exit-criteria) as tests (task 3.11). **Headless (done):** `src/main/cli/exit-criteria.fixture.ts` holds the flow once, with an assertion per criterion; two transports run it against the bundled CLI (`node_modules/.cache`, built by the Vitest global setup) with a temp `--data-dir`:

- `exit-criteria.mcp.test.ts`: an MCP SDK client spawns `dfyom mcp` over stdio; also checks the run's MCP progress notifications, and that CI runs `npm run check` (the third criterion).
- `exit-criteria.batch.test.ts`: `dfyom batch`, one JSON line per call, answered line by line (so tool changes can be continued).

| Criterion step                                                            | Asserted                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project with a rectangular stock                                          | `project.create`; the part's stock copy is a 100 × 60 × 20 block.                                                                                                                                                                                                                                    |
| Facing, pocket (corner radius, floor fillet), drilling, profile with tabs | The part's operations in order with their corner radius, floor radius and tab count; evaluation `done`.                                                                                                                                                                                              |
| Plan one setup                                                            | One setup; every design operation machined exactly once; toolpaths generated for every plan operation.                                                                                                                                                                                               |
| Export GRBL gCode                                                         | `plan.export` at the virtual machine's G54: soft-limit check ran, no warnings; the file equals the golden file `src/main/cli/__golden__/exit-criteria-bracket.nc` byte for byte; line count.                                                                                                         |
| Run on the virtual machine with progress shown                            | `run.job.start` at `max`: each tool change (marker + `M0`) and spindle pause waited for once and continued; the progress label names the tool change while waiting; progress `total` = program lines, never going back, ends complete; ends `Idle`, homed, no alarm, at the program's last position. |
| Save, close and reopen                                                    | Saved and not dirty; closed (project tools then fail); reopened (`alreadyOpen: false`) with the part and plan equal; re-export gives the same bytes.                                                                                                                                                 |

- **Golden file.** After an intended change to the post or a generator, update it with `npx vitest run src/main/cli/exit-criteria -u` and review the diff with the change. Under `CI=true` a missing golden file fails instead of being written.
- **Deterministic and fast.** No wall-clock assertions: the virtual machine runs at `max`, and `job.wait` is polled with a short timeout only to continue tool changes promptly. Each variant takes about 1 s, so both run in `npm test` (and CI); no separate script.
- **UI flow (done, 3.11):** the same criteria in the app via Playwright for Electron, `e2e/exit-criteria.e2e.ts` ([below](#app-playwright-for-electron)).

### App (Playwright for Electron)

`@playwright/test` with its `_electron` launcher drives the built app (`out/main/index.js`); no browsers are downloaded. Config: `playwright.config.ts` (tests `e2e/**/*.e2e.ts`, one worker, artifacts in `node_modules/.cache/playwright`). Vitest does not pick these files up (its globs are `src/**/*.test.*` and `scripts/**`); `tsconfig.node.json` type-checks them and ESLint lints them as usual.

- **Fixture** (`e2e/app.fixture.ts`): launches the app with a fresh temp `--data-dir`, which in the app also moves Electron's `userData` (Chromium profile) and the log folder ([persistence.md](../architecture/persistence.md#files-and-folders)), so a run never touches the developer's projects, library or logs; collects console errors and uncaught exceptions of every window from creation on; stubs the native message boxes (they would show on screen and cannot be driven), which answer the quit questions with their quit button unless a test picks another (`answerMessageBoxes`, `askedMessageBoxes`); closes the app (normal quit path) and deletes the folder.
- **Hidden windows.** The fixture sets `DFYOM_HIDE_WINDOWS=1`: the app never shows its windows (no background throttling, no Dock icon or focus on macOS), so a test run does not cover the screen; the app ignores it when packaged. `DFYOM_E2E_SHOW=1 npm run e2e` shows the windows for debugging. Tests drive the hidden window through Playwright as usual.
- **Smoke test, task 0.9** (`e2e/smoke.e2e.ts`): the first window opens and is shown, its title is `DFYOM`, `#root` has rendered content, no renderer errors, `userData` and the logs are in the temp folder; and, through the window's preload bridge (`window.dfyom.call`, as the UI calls it), a part with a pocket evaluates to `done`, which runs the production worker chunk (`out/main`) in the packaged layout. Selectors rely only on the title, `#root` and the bridge, so they survive UI rewrites; later UI tests query by role and label ([ui.md](ui.md#testing)). Extended with the UI shell (3.3b): the three modes switch (click and shortcuts), the theme setting applies (`data-theme`, body colour) and persists (`settings.json`), and closing an edited project's last window asks first.
- **Exit criteria, task 3.11** (`e2e/exit-criteria.e2e.ts`, joins the design flow of 3.6, the plan UI of 3.7 and the run flow of 3.12): everything through the UI only (roles and labels), starting from the empty library of a fresh install: New project, a new 100 × 60 × 20 block, facing, pocket (corner radius, floor fillet), drilling, profile with tabs, "Part up to date" from the geometry worker; Plan: the machine added with "New machine…" from the empty state, Create plan (machining order checked), the tools added with "New tool…" per operation (flat, bull nose with the floor fillet's corner radius, drill) and assigned, the profile's tool picked in the tool picker, the drill's feeds entered as overrides, Generate toolpaths, Export gCode… (save dialog) with "No machine warnings." and the file's line count; Run: connect to the virtual machine at Max, home, jog to the middle of the table, set the work zero, start through the pre-flight dialog (tools in order), confirm every tool change and program pause, "Run complete" with lines done = total = the exported file's lines; `Ctrl/Cmd+S` (Save as), then the app is closed and launched again on the same data dir (`launchApp`) and the file opened: same operations and values, evaluated, the plan with its tools and the drill's feeds. The native file dialogs are stubbed in the main process (`app.evaluate` replaces `dialog.showSaveDialog` / `showOpenDialog`; the export dialog is told apart by its title). Fields are filled, committed with Enter and left (`blur`) before the next click, since a field's echo collapses on blur and would move the click target.
- **Electron binary.** Electron 45 has no install script: `require('electron')` downloads the binary on first use (`npm run dev`, `npm run e2e`), so `allowScripts` needs no entry for it.
- **Not in CI (yet).** CI sets `ELECTRON_SKIP_BINARY_DOWNLOAD` and runs only `check`; launching Electron on the Linux runner needs a display (`xvfb-run`) and Chromium sandbox setup that is not verified yet. About 5 s locally (build included); run before merging changes to the app process wiring. Tracked in the [v0.1 plan](../plans/v0.1.md#known-issues-and-risks).

## Docs lint

`scripts/docs-lint.test.mjs` (part of `npm test`) enforces [documentation.md](documentation.md): every doc is reachable from the [index](../README.md) (directly, via a folder link such as `decisions/`, or via an indexed folder README), has a valid `Status:` line in its first lines and the same status as in the index map, and every relative link and `#anchor` resolves (GitHub heading slugs).

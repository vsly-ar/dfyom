# Packaging and local install

Status: implemented

How the app is packaged as `DFYOM.app` and installed for the developer. Local installs only: no code signing, no notarization, no installer image or auto-update yet. Config: [`electron-builder.config.mjs`](../../electron-builder.config.mjs).

## Commands

| Command                  | Does                                                                                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run package`        | `electron-vite build`, the [third-party notices](#third-party-notices), then electron-builder `--dir`: an unpacked `release/mac-arm64/DFYOM.app` (`release/` is gitignored) |
| `npm run notices`        | Only the [third-party notices](#third-party-notices), from the current `out/` (run after `npm run build`)                                                                   |
| `npm run install:local`  | `package`, then [`scripts/install-local.mjs`](../../scripts/install-local.mjs) copies the app to `~/Applications/DFYOM.app` (no sudo)                                       |
| `npm run smoke:packaged` | The [smoke tests](testing.md#app-playwright-for-electron) on the packaged executable, windows hidden; run after `package`                                                   |

`smoke:packaged` is optional, not part of `npm run check` or CI. **When a milestone is reached** (a plan in [plans/](../plans/) closes), run `npm run install:local`, then `npm run smoke:packaged`, so the installed app is that milestone's version (`package.json` `version`, shown in the window title and Finder's Get Info). Package from a real `node_modules`: with a **symlinked** `node_modules` (a worktree sharing the main checkout's) electron-builder cannot resolve the transitive dependencies ("cannot find path for dependency") and ships an app without them (pino's `sonic-boom`, serialport's parsers and binding) that does not start; an APFS clone (`cp -c -R`) works.

## Install

- The installed copy is replaced only while it is not running: `pgrep -f ~/Applications/DFYOM.app` finds a process → the script refuses with a message and exits 1; quit DFYOM and run it again.
- It copies with `ditto` to `~/Applications/.DFYOM.app.installing`, then swaps it in, so a failed copy keeps the old app.
- App data (projects, library, settings, logs) lives in the user's app data folder ([persistence.md](../architecture/persistence.md#files-and-folders)), not in the bundle, so it survives reinstalling.

## Configuration

- **`appId` `app.dfyom`** (reverse DNS of the product name; no domain is registered, and it only has to be unique on the machine). It is the macOS bundle identifier; changing it later makes macOS treat the app as a different one (permissions, Dock).
- **`productName` `DFYOM`:** the bundle and menu name; the dev-only bundle rename ([ui.md](ui.md#app-name-and-icon)) is not needed.
- **Target** `dir`, `arm64` (the developer's Mac). A `dmg` or `zip` target is one more entry in `mac.target` when wanted.
- **asar:** on. The main process reads `manifold.wasm` and the vendored `cavalier_contours.wasm` with `fs` from inside the asar; only the native serial binding is unpacked ([native modules](#native-modules)).
- **Signing:** `identity: null`, `notarize: false`. The binaries keep Electron's ad hoc linker signature, enough for Apple Silicon; the bundle is not sealed, so Gatekeeper would refuse a copy downloaded from the internet (quarantined), not a local build.
- **Icon:** `build/icon.icns` (with `icon.ico`, `icon.png`) in `buildResources`, generated by `npm run icon` and committed ([ui.md § App name and icon](ui.md#app-name-and-icon), B21, approved in L3, D33); electron-builder copies it to `DFYOM.app/Contents/Resources/icon.icns` and sets `CFBundleIconFile`.
- **Fuses** are left at Electron's defaults (`runAsNode` on, which the future `dfyom` launcher needs, [llm-api.md](../architecture/llm-api.md#processes-and-hosting)).

## What goes in

- `out/**` (main, preload, renderer, worker and machine-host chunks, `cavalier_contours.wasm` via `?asset`) and `package.json`; no source maps, fixtures or vendor sources.
- **Production dependencies:** only the packages the main process `require`s at run time (`MAIN_EXTERNALS` in the config) and their dependencies. Renderer libraries are bundled by Vite and left out; `manifold-3d` ships only `manifold.js` and `manifold.wasm` (its own dependencies serve its CLI). A new `require` of a dependency in `src/main` must be added to `MAIN_EXTERNALS`.
- **Licence texts** in `DFYOM.app/Contents/Resources`: `LICENSE.txt` (the app, GPL-3.0-or-later) and the generated `THIRD_PARTY_NOTICES.txt` ([below](#third-party-notices)); Electron adds its own `LICENSE.electron.txt` and `LICENSES.chromium.html`.

## Native modules

`serialport` (MIT, with `@serialport/bindings-cpp`; hardening M1, [run-machine.md](../modes/run-machine.md#serial-transport)) is the only native dependency. Its licences are all MIT, so it is GPL-3.0-or-later compatible ([ADR 0014](../decisions/0014-gpl-3-or-later-license.md)); the [notices](#third-party-notices) list it with the other main-process packages.

- **Prebuilt, no rebuild:** `@serialport/bindings-cpp` ships N-API prebuilds (`prebuilds/darwin-x64+arm64/…node`, loaded by `node-gyp-build`). N-API is ABI-stable across Node and Electron, so the same binary loads in Node (tests, CLI), in Electron's utility process and in a `worker_threads` worker; `npmRebuild` stays `false` and no compiler is needed.
- **Unpacked from the asar:** a `.node` file cannot be loaded from inside an asar, so the config sets `asarUnpack` for `@serialport/bindings-cpp`'s `prebuilds` and `node-gyp-build` finds the binary in `app.asar.unpacked` (Electron redirects the path).
- **Loaded only in the machine host** and only when a serial port is listed or opened (lazy `import('serialport')`), so a broken binary never stops the app or a virtual connection; it fails the serial connect with `machine.connection`.
- Only the macOS arm64/x64 prebuild is used today; others are not removed (a few hundred KB).

## Third-party notices

[`scripts/third-party-notices.mjs`](../../scripts/third-party-notices.mjs) writes `out/THIRD_PARTY_NOTICES.txt` after `electron-vite build`; electron-builder copies it to `Contents/Resources` (kept out of the asar). **Help → Open-source licences** opens it in a read-only window ([`src/main/licences-window.ts`](../../src/main/licences-window.ts): plain text, no preload or project session, never shown in hidden runs; menu items it receives go to a project window). In development it shows `out/THIRD_PARTY_NOTICES.txt` once `npm run notices` ran, else a hint.

What it covers, each with its licence, where it is used, its source and its licence and NOTICE files:

- **Bundled packages:** every `node_modules` package Rolldown put into `out/**/*.js` (today the renderer's: React, Radix, three.js, drei, …; the icons are DFYOM's own, [ui.md § Icons](ui.md#icons)), read from the `// <module path>` comment above each module. A file without these comments (a minified build) fails the script, so the list cannot silently empty.
- **Main-process runtime packages:** `MAIN_EXTERNALS` and their dependencies, the same closure electron-builder ships ([What goes in](#what-goes-in); `runtimeClosureDirs` in the config).
- **Vendored assets** (`VENDORED` in the script): `cavalier_contours.wasm` with its crate notices (`vendor/cavalier-contours/THIRD-PARTY-NOTICES.txt`). Every directory under `vendor/` and every font file under `src/` or `vendor/` must be listed; a test ([`third-party-notices.test.mjs`](../../scripts/third-party-notices.test.mjs)) checks it. No fonts are shipped: the UI uses system font stacks.
- **Libraries compiled into a package's binary** (`EMBEDDED`): Clipper2 (BSL-1.0) and the Emscripten runtime (MIT) in `manifold.wasm`.
- **Packages without a licence file in their npm tarball** (`MISSING_LICENCE_FILES`): the copyright line of their repository's LICENSE, used only while `package.json` names the same licence (today `@react-three/fiber`, `react-remove-scroll-bar`).

The script **fails** when a package has no licence text or a licence expression that cannot be met with GPL-3.0-or-later compatible licences (`ALLOWED`: permissive licences, MPL-2.0, LGPL, GPL-2.0-or-later and GPL-3.0; not GPL-2.0-only, SSPL, proprietary or `SEE LICENSE IN`), and prints a summary by licence. A dependency that fails needs a decision ([ADR 0014](../decisions/0014-gpl-3-or-later-license.md)), not an entry in `ALLOWED`.

## Smoke test

`DFYOM_E2E_APP=<executable>` makes the e2e fixture launch that executable instead of `out/main/index.js`. `DFYOM_HIDE_WINDOWS=1` is honoured by packaged builds too, so the packaged run shows no window. On a packaged app the first smoke test also checks `app.isPackaged`, the name `DFYOM`, the asar app path and the licence texts (`LICENSE.txt`, `THIRD_PARTY_NOTICES.txt`). A smoke test opens Help → Open-source licences (on a packaged app it must show the generated notices).

A dependency missing from the asar makes the packaged app stop at start with Electron's main-process error box (hidden in a test run, so the test just times out). To find it, require the externals inside the app with `ELECTRON_RUN_AS_NODE=1 DFYOM.app/Contents/MacOS/DFYOM -e "require('module').createRequire('<app.asar>/out/main/index.js')('<pkg>')"`.

## Dependency

`electron-builder` (dev dependency, MIT, so GPL-3.0-or-later compatible per [ADR 0014](../decisions/0014-gpl-3-or-later-license.md)); it is a build tool and is not shipped in the app.

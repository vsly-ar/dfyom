# Feeds-and-speeds calculator

Status: implemented (locked inputs and final-value check: task 3.14; chamfer mills F10: v0.4 task C1; tapered ball end mills F11: hardening DF124 T2; hobby metal cutting: hardening DF131; recommended presets on the plan machine: hardening DF139; plunged chamfers F12: hardening DF141) · Code: [`src/core/feeds-speeds/`](../../src/core/feeds-speeds/suggest.ts) · Used by: [plan-v0.1.md](../modes/plan-v0.1.md#feeds-and-speeds) · Presets: [library.md](library.md#feeds-and-speeds-presets) · Values: [quantities.md](quantities.md) · Terms: [glossary.md](../glossary.md) · Task: [v0.1 plan](../plans/v0.1.md) 1.15 (code: 2.12)

The calculator recommends the feeds of a plan operation in [auto mode](../modes/plan-v0.1.md#locks-and-auto-mode) (entered value → **calculator** → strategy fallback; outside auto mode a tool preset gives fixed values). It suggests `spindleSpeed`, `feedRate`, `plungeRate`, `stepdown` and `stepover` for one plan operation from the tool, the stock's material class, the strategy's engagement and the machine, and explains every number ([principles §5](../principles.md#5-user-friendly-beginner-friendly-highly-graphical)).

## Formulas

Symbols follow Sandvik Coromant (ISO): `vc` surface speed, `D` tool diameter, `z` flutes (NOF), `fz` chip load, `n` spindle speed, `vf` feed rate, `ae` radial engagement (stepover), `ap` axial engagement (stepdown), `fn` feed per revolution, `Q` material removal rate, `u` unit power. Metric shown; inch input is converted by the quantity layer.

| #   | Quantity                      | Formula                                                                                                                                               | Source                                                                                         |
| --- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| F1  | Spindle speed                 | `n = vc·1000 / (π·Dcalc)`; `Dcalc` = `D`, or `De` (F4); router rows give `n` directly                                                                 | [S1], [MH], [AM1]                                                                              |
| F2  | Feed rate                     | `vf = n · z · fz_prog`                                                                                                                                | [S1], [MH]                                                                                     |
| F3  | Radial chip thinning (RCTF)   | `ae < D/2`: `fz_prog = fz / (2·√((ae/D)(1 − ae/D)))`; otherwise `fz_prog = fz`                                                                        | [MD], [S1] (`hex`)                                                                             |
| F4  | Effective diameter            | `ap < RE`: `De = D − 2·RE + 2·√(ap(2·RE − ap))`; ball: `RE = D/2` gives `De = 2√(ap(D−ap))`                                                           | [K1], [HT1]                                                                                    |
| F5  | Axial chip thinning (ACTF)    | `ap < RE`: `fz_prog = fz / sin κ`, `cos κ = (RE − ap)/RE`; flat end mill: none (`κ = 90°`)                                                            | [S1] (`hex = fz·sin κ`)                                                                        |
| F6  | Material removal rate         | `Q = ae · ap · vf` (mm³/min)                                                                                                                          | [S1], [MH]                                                                                     |
| F7  | Cutting power                 | `Pc = Q · u / 60 000` (kW, `u` in W·s/mm³); `u = Kp · 2.73` from unit horsepower `Kp`; metals × `C·W` ([DF131](#hobby-metal-cutting-hardening-df131)) | [S1] (`kc`), [MMS], [AD], [MH]                                                                 |
| F8  | Drilling feed                 | `vf = fn · n`; `fn` from the data table per material × diameter band                                                                                  | [S2]                                                                                           |
| F9  | Plunge rate (end mill)        | `plungeRate = kPlunge · vf` (data: 0.5 wood/plastic, 0.25 metals); drills use F8                                                                      | [AM1] ramp-down, estimated                                                                     |
| F10 | Chamfer mill diameter (v0.4)  | `De = dt + 2·depth·tan(α/2)`, ≤ `DC`; `dt` tip diameter, `α` included angle, `depth` below the tip                                                    | cone geometry; [SC4] ([below](#chamfer-mills-v04))                                             |
| F11 | Tapered ball diameter (DF124) | `De` = the groove width at the Line's depth: ball, then the tangent cone, ≤ `DC`                                                                      | ball-and-cone geometry ([below](#tapered-ball-end-mills-hardening-df124))                      |
| F12 | Plunged chamfer (DF141)       | `Q = π/4 · (De² − d²) · vp` (`d` the edge Ø, `vp` the plunge rate); chip `h = vp / (n·z) · sin(α/2)`                                                  | [S2] (enlarging a pre-drilled hole), [S1] (`hex`) ([below](#plunged-chamfers-hardening-df141)) |

- F3 and F5 multiply when both apply. Both are capped at ×3 to avoid runaway feeds at tiny engagement ([MD]).
- **Adaptive/HSM:** large chip-thinning gains with deep `ap` and small constant `ae` assume constant tool engagement ([glossary: adaptive clearing](../glossary.md)). v0.1 offset pocketing has full-width engagement in its first ring and in corners, so it gets **no RCTF credit** (see [Engagement](#engagement-per-strategy)).
- Ramps and helices feed at `feedRate` ([plan rule](../modes/plan-v0.1.md#feeds-and-speeds)); Sandvik recommends ~75 % for circular ramping [S3]; v0.1 keeps the cutting feed and relies on the slot engagement below.

**Order:** locked values are inputs, everything else is recommended around them ([Locked inputs](#locked-inputs)); entered (unlocked) values are not inputs, and the [final-value check](#final-value-check) sees them. (Until task 3.14 every resolved stepdown/stepover override fed the calculator.)

**Output** `CuttingSuggestion`: each of the five fields is `Option<{ value, derivation }>`; `derivation` lists formula id, inputs and result per step (rendered as formulas and tooltips in the UI, returned verbatim to agents). Derived display values: `vc` actual, `fz` actual, `Q`, `Pc`, spindle load %. Plus `warnings[]`.

| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |

### Chamfer mills (v0.4)

Amendment from [plan-v0.4.md § Feeds for chamfer mills](../modes/plan-v0.4.md#feeds-for-chamfer-mills) (decision P-D), task C1. A `chamferMill` ([library.md](library.md#tool)) cuts with a cone, so its cutting diameter grows with depth. The engagement `chamfer { depth }` (mm below the tool's tip, at the deepest point of the cut) gives the **effective diameter** `De` (F10), capped at `DC` where the cone ends. The calculator then treats the tool as a **flat end mill of diameter `De`**: the diameter band (chip load `fz`), F1 (`n` from `vc` and `De`), F2 with the tool's flutes, F9 for the plunge, and `ae = De`, `ap = depth` for F6/F7 (an upper bound: a cone removes less than that rectangle). The stepdown is fixed (one pass at the chamfer depth), so it is not suggested; a power excess lowers the feed as with a helix. A **plunged** chamfer cuts at the plunge rate instead: F12, [below](#plunged-chamfers-hardening-df141) (DF141). The derivation shows an `F10` step before F1 (with a chart rpm, before the chip load). A chamfer engagement needs a chamfer mill and a chamfer mill a chamfer engagement, else `feeds.noData`. Recommended presets use the full cone (`depth` where `De = DC`).

**Small chamfers (De < 3.175 mm).** The ≤ 3 mm band is empty for end mills (below), but a chamfer's `De` is often 1–3 mm (the default edge + 1 mm with a pointed mill contours at De = 1 mm). Below the smallest charted diameter (1/8″ = 3.175 mm, the ≤ 6 mm band's representative) a chamfer engagement takes that band's `fz` range **× De / 3.175** (derivation step `fzScale` after the `data` step); speed still comes from `De` (F1, clamped to the spindle). Reasons: (1) chamfer-cutter makers compute speeds and feeds from an **effective cutter diameter** where the cone actually cuts, not the head diameter (Harvey Tool takes the average of the tip and largest contact diameters [SC5]; DFYOM keeps P-D's deepest-point `De`), so chip load is a function of that diameter; (2) chip load is proportional to the diameter in the cited end-mill charts (Harvey 13900 slotting: .00151/.00303/.00605″ at 1/8, 1/4, 1/2″) or grows more slowly (Onsrud, Amana router rows), so scaling down linearly from 1/8″ never feeds more than those charts' trend; (3) the band is empty for end mills because slender sub-millimetre tools break, which does not apply to a chamfer mill whose cone tip is backed by its full body. The factor is 1 at 3.175 mm, so the rule is continuous with the ≤ 6 mm band. Code: `suggest.ts` (`CHART_MIN_DIAMETER`). **Sharp engraving V-bits (DF123, 10°–30°).** The same rule holds: De is small at engraving depths (15° at 1 mm: 0.26 mm), so `n` from F1 hits the spindle's maximum and the scaled chip load keeps the feed light (15° Ø 1/8″, 1 mm deep in plywood on an 18,000 rpm router: ≈ 190 mm/min); with `n` clamped, the feed is in proportion to De, so it never exceeds a wider bit's at the same depth. Without a machine `n` is unclamped (a plan always has one).

F10 is the cone's geometry (the diameter of a cone of included angle α at a height above its tip), the speed-by-depth rule of the earlier cnc-code V-bit calculator (D30 Q12). It is not re-sourced from a published chart yet (known gap); Sandvik's chamfer-milling guidance [SC4] confirms the light engagement of chamfers, so the slot-rule power check is conservative. Choosing the speed at the deepest point is conservative for the surface speed (the largest diameter in contact sets `n`).

### Plunged chamfers (hardening DF141)

**Problem.** A chamfer whose tool covers it is **plunged** ([plan-v0.4.md P-C](../modes/plan-v0.4.md#chamfer-toolpath)): the tool feeds straight down its axis at `plungeRate` into the edge (the hole) and leaves; `feedRate` is never used. F6/F7 with `ae = De`, `ap = depth` at `feedRate` judged a feed the cut does not use, with a rectangle the cut does not remove, and left the plunge rate, the feed that does cut, unchecked. The X3 countersink (Chamfer 82, DC 6.35, plunged to Ø4.861 on a Ø2.447 hole, hardwood, 500 W at 18,000 rpm: 0.3 kW) was flagged at 0.427 kW with its feed lowered 4572 → 2744 mm/min to the chip-load floor ([DF139 A4](#implementation-df139)), a feed the plunge never runs.

**Model (F12).** A cone of included angle α fed `vp` along its axis into an edge of Ø `d` removes, per mm of feed, the annulus between `d` and the cone's Ø at the face `De` (F10 at the plunge depth, which is the chamfer Ø D): `Q = π/4 · (De² − d²) · vp`. It is the largest rate of the plunge (it grows as the cone enters and is greatest at the bottom), so the check is at the worst instant. It is Sandvik's drilling removal rate for enlarging a pre-drilled hole [S2] (`Q = vc · ap · fn · (DC − ap) / DC` with `ap = (DC − d) / 2`, the same annulus; `d = 0` gives solid drilling's `vc · DC · fn / 4`), and power follows as for every cut, F7 `Pc = Q · u / 60 000` (Sandvik's `Pc = Q · kc / (60·10⁶ · η)` with `u = kc / η` per mm³). The chip (for the metal rows' feed factor `C`) is `h = vp / (n · z) · sin(α/2)`: the cutting edge lies at α/2 to the feed ([S1] `hex = fz · sin κr`). `d = 0` for a plunge into solid material (a witness mark, [alignment aids](../modes/alignment.md#alignment-aids)); a group of equal chamfers takes its smallest edge.

**Where it applies.** The engagement `chamfer { depth, plunge: { edgeDiameter } }` is set by plan mode when the chamfer's resolved `entry` is `plunge` with a chamfer mill (`evaluate.ts`); `plan.operation.feeds.get` shows it as `inputs.engagement.plungeEdgeDiameter`. Then:

- the [final-value check](#final-value-check) computes F12 at the final plunge rate and puts `feeds.powerExceeded` on `plungeRate` ("reduce the plunge rate"); the chip-load check stays on `feedRate`, as for every chamfer;
- the calculator keeps F9 and the Z clamp for the plunge rate, then checks F12 and lowers the plunge rate to fit (derivation steps `F12`, `power`; "suggested plunge rate reduced to fit"); the feed is not lowered for power;
- a [recommended preset's](#recommended-presets-on-the-plan-machine-hardening-df139) power step lowers the plunge rate, not the feed. No chip-load floor: plunge rates sit below the feed's chip by convention (F9's `kPlunge`) and have no chip-load check, so a lower plunge is only slower, like the Z max clamp; it stops at one rounding step.

**Contours, edge chamfers and V-bit Lines keep F6** (`ae = De`, `ap = depth` at `feedRate`): it is an upper bound, not an error. A cone moved sideways sweeps at most its silhouette, the trapezoid `(dt + De)/2 · depth`, which a V-bit Line's groove fills (the rectangle is ≤ 2 × it); a contoured countersink or an [edge chamfer](../modes/edge-chamfers.md) removes only the chamfer's triangle, `w · h / 2` (w its width, h its depth), at most a quarter of the rectangle. Tightening those would raise feeds on hobby machines for no measured need, so they stay conservative.

**X3 (the A4 recheck).** F12 at the adapted plunge 1500 mm/min (Z max): π/4 · (4.861² − 2.447²) = 13.856 mm² → 20,783 mm³/min → **0.236 kW** of 0.3 kW (hardwood `u` = 0.6825 W·s/mm³): no warning, and the feed stays 4572 mm/min. At the rerun's own plunge 2286 mm/min it is 0.360 kW, so that warning stays real (on `plungeRate`); a recommended preset on a machine whose Z max allows more is fitted to 1901 mm/min. Tests: `formulas.test.ts` (F12 by hand, Sandvik's form), `adapt.test.ts` (the X3 countersink), `suggest.test.ts` (calculator, check, display), [`feeds-adapted.test.ts`](../../src/core/plan/feeds-adapted.test.ts) § X3 recheck, `chamfer-toolpaths.test.ts` (plan wiring).

### Tapered ball end mills (hardening DF124)

Amendment from [tapered-ball-nose.md § Feeds and speeds](../modes/tapered-ball-nose.md#feeds-and-speeds), slice T2. A `taperedBallEndMill` ([library.md](library.md#tool)) cuts a Line with a ball tip under a cone of θ per side, so its cutting diameter grows with depth like a chamfer mill's. The engagement `taper { depth }` (the Line's deepest depth) gives the **effective diameter** `De` (F11): the groove width there, `2·√(d·(dt − d))` on the ball (d ≤ h_t = r (1 − sin θ)), else `dt / cos θ + 2·(d − r)·tan θ`, capped at `DC` (`taperedGrooveWidth` in `src/core/library/tool.ts`, shared with the Line's width read-out). The calculator then treats the tool as a **flat end mill of diameter `De`**, exactly as F10: diameter band, F1, F2, F9, `ae = De`, RE = 0 (the ball is already in `De`, so no F4 or F5 on it), and the [small-De rule](#chamfer-mills-v04) (`fzScale` from the 1/8″ chip load × De / 3.175) for the same reason: the small tip is backed by the cone, not a slender shank. With a router row's chart rpm, R0.25 at 3.6° in hardwood 1 mm deep (De 0.60 mm) takes 18,000 rpm and ≈ 600 mm/min with two flutes (golden `src/core/feeds-speeds/__golden__/tapered-ball-hardwood.json`); with a `vc` row, F1 at De hits the spindle's top speed.

- **Stepdown suggested** (unlike a chamfer, a Line goes down in passes): the largest `ap` with `ap ≤ apSlot × apFactor × De(ap)`, closed form on each piece of De (the large end, the cone where De is linear in ap, the ball), at most `fluteLength` (`taperedStepdown` in `formulas.ts`; derivation step `taperAp`). R0.25, 3.6°, k = apSlot × apFactor = 1: 0.54 mm; hobby (0.5): 0.25 mm. `ap` then sets F6/F7 with `ae = De` at the deepest depth (an upper bound).
- A taper engagement needs a tapered ball and a tapered ball a taper engagement, else `feeds.noData` (never a flat end mill of the large end Ø, whose chip load would break the tip). Recommended presets use depth = 1 mm (a typical carving depth), not the full cone.

Stepdown suggestion: `ap = apSlot(material) × D × rigidityFactor`, ≤ `fluteLength` (none when the stepdown is locked); stepover suggestion is left to the strategy fallback in v0.1 (the strategies fix engagement, not the calculator).

### Material data (v0.1)

**Scope: carbide end mills only** (flat, bull-nose, ball; one row per material class applies to all three). There are **no HSS rows and no drill `fn` bands** yet: those calls return `feeds.noData` and plan mode falls back to the tool preset or the strategy fallback ([resolution order](../modes/plan-v0.1.md#feeds-and-speeds)). Every value is in [`data.ts`](../../src/core/feeds-speeds/data.ts) with its source and the exact table in the row's `sources`.

**Rules used to turn charts into rows:**

- **Conservative envelope.** Where several sources (or several printed grades of one class) give values, the row range is `[lowest printed minimum, lowest printed maximum]`; a single printed value counts as `min = max`. This is the "take the conservative value" rule; it makes some ranges a single point.
- **Representative diameter per band.** Charts print values per nominal inch diameter. Each band uses the smallest chart diameter inside it: ≤ 6 mm ← 1/8″ (3.175 mm), ≤ 12 mm ← 1/4″ (6.35 mm), ≤ 25 mm ← 1/2″ (12.7 mm). Chip load grows with `D`, so larger tools in the band get a lower-than-printed chip load; tools from 6 to 6.35 mm get the 1/4″ value (≤ 6 % larger diameter). The **≤ 3 mm band** was empty in v0.1; since hardening DF39 the router rows (wood, sheet goods, plastic) fill it from [AM1]'s 1/16″ column (1.5875 mm), and end mills under 1/16″ scale it down ([Small end mills](#small-end-mills-hardening-df39)). Metal rows keep it empty (`feeds.noData`); chamfer engagements below 3.175 mm keep scaling the 1/8″ value ([Chamfer mills](#chamfer-mills-v04)).
- **Speed: `vc` or `n`.** Machining charts (Harvey Tool) give a surface speed, so metal rows have `vc` and use F1. Router-bit charts give no surface speed but a fixed spindle speed (Amana: "CNC Operating Spindle Speed: 18,000 RPM"), so wood, sheet-good and plastic rows set `n` instead and skip F1 (F4 then only affects the actual `vc` shown). The row type allows exactly one of the two; the data lint checks it.
- Chart units are inch: chip load in IPT (× 25.4 → mm), speed in SFM (× 0.3048 → m/min).

**Where each number comes from:**

- **Wood and sheet goods:** chip loads from the Onsrud 52-200/57-200 rows (2-flute up/down spiral, the general-purpose series the charts recommend for single pass) and the Amana 2-flute spiral ball nose chart; both agree at 1/8″, 1/4″ and 1/2″ except softwood 1/8″ (Onsrud .006–.008, Amana .005–.007 → .005–.007). MDF, soft plywood and hard plywood print the same 52-200 values. `apSlot = 1`: both charts state "Depth of cut 1 x D" for the printed chip load. `n`: [AM1].
- **Plastic** (soft and hard): Onsrud 52-200B/BL rows of both plastic charts and the Amana charts. At 1/4″ the Amana plastics ball nose chart prints .003–.005 against .004–.006 elsewhere → .003–.005. Harvey's general table lists much lower chip loads for plastics at 200–600 SFM; that is a machining-centre regime, and this doc assigns plastics to router-bit charts, so it is not used. Onsrud warns that too low a chip load in plastic causes rewelding; raise the feed (preset) if chips melt.
- **Aluminium, brass, steel:** [HT3] (general table, 1/8″, 1/4″, 1/2″) and [HT4] (2-flute square end mill product chart, "Slotting" rows at 0.125″, 0.250″, 0.500″). Per diameter the lower printed chip load wins: [HT3] everywhere except steel 1/8″ ([HT4] .00048 < .0005). `vc`: aluminium rows 500–1000 (castings 440/356/380) / 800–1500 SFM [HT3] and 1000 (wrought), 750/700/650 (castings up to 12 % Si) SFM [HT4] → 500–650 until DF131, now 500–1000 ([why](#hobby-metal-cutting-hardening-df131)); brass 600–1000 / 800–1500 [HT3] and 500 [HT4] → 500; steel 100–300 (10XX/11XX/13XX) and 100–150 (23XX/31XX) [HT3] and 600 / 200 [HT4] → 100–150. `apSlot = 0.5`: [HT4] slotting axial depth ".50 x Dia" (Onsrud's aluminium router chart allows 1 x D; the lower value wins). Aluminium castings with more than 12 % Si ([HT4] 475 SFM) are not covered.
- **Steel scope:** the steel row uses Harvey's carbon and low-alloy rows only (10xx–15xx, 2xxx–9xxx alloy steels). Stainless, tool and high-strength steels have much lower chip loads in [HT3] and are **not** covered: choose material class `other` for them (known issue in the [v0.1 plan](../plans/v0.1.md)).
- **Unit power `u` (metals):** Machinery's Handbook `Kp` tables are not freely available, so `u` comes from [MMS] Table I "Unit Horsepower" (horsepower at the machine per in³/min, so it already includes losses and is ≥ the handbook's cutter `Kp`; F7 then also applies `η`, so `Pc` is overestimated, never under). Aluminium 0.25; brass "Hard" 0.50 (higher than "Soft" 0.33); steel 2.00 ("400 BHN", the first printed value at or above the 279–344 HBn hardness of [HT4]'s steel rows).

**Estimates (`estimated`):**

- **`u` for wood, sheet goods and plastic = 0.25 × 2.73 = 0.6825 W·s/mm³**, the [MMS] aluminium value. No public chart gives unit power for these materials; wood, MDF and thermoplastics are far weaker than aluminium alloys, so aluminium's unit power is an upper bound and the power check errs towards a shallower stepdown.
- **`kPlunge`:** Amana's charts give "Ramp Down: Feed Rate IPM / # of flutes", i.e. `plungeRate = vf / z`. One row cannot hold `z`, so router rows use 0.5 (the rule for the 2-flute bits the chip loads are printed for; a 1-flute bit gets half the Amana value) and metal rows 0.25 (the rule for 4 flutes; conservative for `z ≤ 4`). Tools with more flutes than that plunge faster than the Amana rule (known issue; F9 could use `1/z` later).

**Gaps:** HSS end mills (all classes), drills (`fn` and drill `vc`), end mills ≤ 3 mm in metal and end mills under 1 mm in any material ([Small end mills](#small-end-mills-hardening-df39); chamfer mills at De < 3.175 mm scale the 1/8″ value) and tools > 25 mm, stainless/tool steels, high-silicon aluminium castings and material class `other` → `feeds.noData`.

### Small end mills (hardening DF39)

Source: the X2 agent run ([research note](../research/2026-11-23-x2-agent-variant.md) F2): a Ø3 flat end mill in birch plywood had no data, so every plan operation of the v0.4 lid's Flat 3 (clearance holes, counterbores, vents) was blocked until a preset was entered.

- **Data:** the ≤ 3 mm band of the router rows takes [AM1]'s **1/16″ column**, the chart already cited for these rows (2-flute spiral ball nose, 18,000 rpm, depth of cut 1 x D): softwood .003–.005″, hardwood .002–.004″, MDF .003–.005″ (the sheetGood row: Onsrud prints no 1/16″ values, and its MDF and plywood rows agree at every printed diameter, so MDF stands for the class), soft and hard plastic .002–.004″ ([AM2] prints no 1/16″ value). One source, so the envelope is the printed range. At 1/8″ the same chart prints .005–.007″ (softwood, MDF) and .003–.005″ (hardwood), the existing ≤ 6 mm values, so the bands stay monotonic.
- **Representative diameter** 1/16″, as for the other bands the smallest chart diameter inside the band: a 2 or 3 mm tool gets the 1/16″ chip load, lower than the trend at its own diameter.
- **Under 1/16″:** an end mill of diameter `D` from 1 mm to 1.5875 mm takes the 1/16″ range **× D / 1.5875** (the `fzScale` step of the [chamfer rule](#chamfer-mills-v04), with the chart diameter 1.5875 mm and `D`): chip load is proportional to the diameter or grows more slowly in every cited chart, so scaling down linearly never feeds more than their trend. **End mills under 1 mm** stay `feeds.noData` ("end mills under 1 mm need entered values"): slender sub-millimetre tools break, and no cited chart covers them.
- **Metal rows** keep the band empty: [HT3] and [HT4] print nothing below 1/8″ in the cited tables.
- **Chamfer mills** keep their rule (1/8″ × De / 3.175 below 3.175 mm): it predates the band and is close to it (sheet goods at De = 2 mm: .0031–.0044″ against .003–.005″); folding the two rules together would change the v0.4 goldens' countersink feeds for no measured gain.
- **Goldens:** DF39 itself changed no golden program: the v0.4 lid's Flat 3 has an entered plywood preset, which wins over the calculator ([resolution order](../modes/plan-v0.1.md#feeds-and-speeds)), and the post goldens take their feeds as given. Its preset then was 1200 mm/min at 18,000 rpm, 2 flutes (fz 0.033 mm), below the new band's minimum (.003″ = 0.076 mm), so the final-value check warned `feeds.rubbing` on every Flat 3 operation (true: a 3 mm bit at that feed rubs in plywood). **Q57** raised the preset to the band's middle: 3600 mm/min (fz 0.1 mm, .004″ = 0.1016 mm rounded down; plunge 300 mm/min unchanged), which changed only the Flat 3 `F` words of `exit-criteria-lid.nc`; the lid's plan now has no findings.
- **Agents:** the findings an unresolved feed leaves say what to do next ([llm-api.md § DF38, DF39, DF41](llm-api.md#amendment-hardening-df38-df39-df41-x2-agent-friction)).

## Locked inputs

Accepted 2026-11-21, implemented in task 3.14. [plan-v0.1.md § Locks and auto mode](../modes/plan-v0.1.md#locks-and-auto-mode) owns when locks exist and what an entered value is; this section is how the calculator uses locked values.

A **locked** value is a fixed input: the calculator recommends every unlocked field around it, so locking the spindle speed makes the feed follow it. An **entered** (typed, unlocked) value is not an input: it replaces only its own field's value, and the recommendation of the other fields stays what it would be without it. The [final-value check](#final-value-check) still sees it.

`CuttingInput` has `locked?: { n?, vf?, ap?, ae? }` (canonical numbers). `engagement` then carries only the kind and the strategy's `ae` (no `ap`); a locked stepdown is `locked.ap`, a locked facing stepover `locked.ae`. `plungeRate` is never an input (nothing depends on it), so it has no lock.

| Locked        | Unlocked fields are recommended as                                                                                                                                                                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| none          | As today: `n` from F1 or the chart, clamped; `vf` from F2, clamped (`n` lowered to keep `fz`); `ap` = `apSlot·D·apFactor`, reduced to fit the power; plunge F9.                                                                                                                      |
| `n`           | `n` replaces F1/the chart and the rpm clamp (derivation step `locked`). `vf = n·z·fz_prog` (F2); above `maxFeedXY` it is clamped and `fz` drops (`n` stays): `feeds.feedClamped`, maybe `feeds.rubbing`. `ap` fits the power at this `n` (`Pavail` depends on `n`).                  |
| `vf`          | `n = vf / (z·fz_prog)`: the data chip load is the anchor (router rows: replaces the chart `n`), clamped to `[minSpeed, maxSpeed]`; when clamped, `fz` follows from `vf`: `feeds.rubbing` below the data range, **`feeds.chipLoadHigh`** (new warning) above it. `ap` fits the power. |
| `n` + `vf`    | Chip load is derived, `fz = vf / (n·z·k)`, with `feeds.rubbing` / `feeds.chipLoadHigh` outside the data range. `ap` fits the power.                                                                                                                                                  |
| `ap`          | `n`, `vf` as for the other locks. Power exceeded: an unlocked `vf` is reduced to fit (`n` kept, `fz` drops, maybe `feeds.rubbing`); a locked `vf` only warns (`feeds.powerExceeded`). Replaces today's "given `ap` only warns".                                                      |
| `ae` (facing) | The facing engagement uses it (F3, F6). Pocket and profile engage as a slot whatever the stepover, so their stepover has no lock.                                                                                                                                                    |
| drilling      | `n` locked: `vf = fn·n` (F8), clamped to `maxFeedRate.z`. `vf` locked: `n = vf / fn`, clamped to the spindle range (then `fn` follows: `feeds.rubbing` / `feeds.chipLoadHigh`). `plungeRate = vf`.                                                                                   |

Power fit order with several unlocked fields: `ap` first (keep chip load, reduce depth: [rigidity](#hobby-machine-realism)), then `vf`. The helix pitch (a strategy value) counts as a fixed `ap`. With a locked `vf` and an unlocked `n`, `n` follows the data chip load and is clamped without the `feeds.rpm*Machine` warnings (the chip load warnings say what the clamp did); a locked `n` replaces the rpm clamp (derivation step `locked`), and an over-limit feed is clamped with `n` kept.

### Impossible locks

A lock is **unavailable** (the plan refuses it; the UI shows the lock disabled with the reason) when the value breaks a hard limit or leaves the locked set no way to meet one:

| Rule                | When                                                                                                                         | Reason shown (example)                                                         |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `invalid`           | No valid value: the input has an error, or the field has no value                                                            | "Enter a valid value to lock it."                                              |
| `spindleRange`      | `n` outside `[spindle.minSpeed, spindle.maxSpeed]` of the plan's machine copy                                                | "24 000 rpm is above this machine's 18 000 rpm."                               |
| `feedLimit`         | `vf > min(maxFeedRate.x, .y)` (drilling: `> maxFeedRate.z`)                                                                  | "6 000 mm/min is above this machine's 5 000 mm/min (X/Y)."                     |
| `toolLength`        | `ap > fluteLength` or `ap > stickout`                                                                                        | "Stepdown 30 mm is deeper than the flute length (22 mm)."                      |
| `stepoverAboveTool` | facing `ae > D`                                                                                                              | "A stepover above the tool diameter leaves ridges."                            |
| `power`             | With this lock every input of F7 is locked (`n`, `vf`, `ap`, facing `ae`) and `Pc > Pavail`: no unlocked field can absorb it | "With spindle speed, feed and stepdown locked the cut needs 1.4 kW of 0.8 kW." |

- Combinations of individually valid locks are otherwise **allowed**: they can only move the chip load or the power, which are recommendations, not limits, so they warn (`feeds.rubbing`, `feeds.chipLoadHigh`, `feeds.powerExceeded`). Without `spindle.power` the `power` rule is skipped; without a machine only `invalid`, `toolLength` and `stepoverAboveTool` apply.
- A stored lock that later breaks a rule (other tool, machine, stock or stickout) stays stored but is **inactive**: the recommendation ignores it, and `plan.warning.list` reports `feeds.lockInactive` (warning) on the field, rule = the lock rule, with the same reason; the UI offers "Unlock". The `power` rule only refuses new locks (a stored set has no single lock to blame; the final-value check warns).
- Code: `lockIssue` (single-lock rules) and `powerLockIssue` in [`locks.ts`](../../src/core/feeds-speeds/locks.ts); plan mode applies them in `src/core/plan/feeds.ts`.

### Final-value check

Because entered values are not inputs, the calculator's own warnings describe its recommendation, not what will run. After resolution `checkCutting(input, final values)` re-runs the coupling checks on the values that will be used: chip load against the data range at the final engagement (`feeds.rubbing`, `feeds.chipLoadHigh`, `field: feedRate`) and power at the final `ae`, `ap`, `vf` (`feeds.powerExceeded`, `field: stepdown`; helix: `feedRate`). It runs in auto and preset mode whenever there is data. These warnings replace the calculator's `feeds.rubbing`, `feeds.chipLoadHigh` and `feeds.powerExceeded` in `plan.warning.list`; the calculator's warnings stay in its derivation. Spindle range and feed limits of the final values are plan mode's existing machine checks (`plan.machine`), not repeated here. `cuttingAt(input, final values)` derives the display values (`dCalc`, `vc`, `fz` after chip thinning, `chipThinning`, `Q`, `Pc`, `spindleLoad`) at the same values, for the plan's [feeds explanation](../modes/plan-v0.1.md#feeds-explanation-v02).

**Rounding slack (hardening DF138 F5, the X3 agent rerun):** the chip load range is compared with 0.1 % slack each way (`ROUNDING` in `suggest.ts`), in the calculator and in the final-value check: values rounded to whole rpm and mm/min sit on the range's edge, and a recommended hardwood feed of 2,743 mm/min gave 0.076194 mm against the minimum 0.0762 and a `feeds.rubbing` on every operation. **Not yet** (deferred in DF138): a recommended preset does not honour the plan machine's spindle power (`feeds.powerExceeded`) or Z max feed (the `plan.machine` plunge warning), because library presets are machine-free and resolve without the plan machine; that needs a decision on where the machine enters the preset resolution: proposed in [Recommended presets on the plan machine](#recommended-presets-on-the-plan-machine-hardening-df139) (draft, DF139).

### Feed clamp and chip load (hardening DF56)

The rule (since task 2.12, [warnings table](#inputs-and-outputs)): when the machine's max feed caps the calculated feed, the calculator keeps the chip load by lowering the spindle speed with the feed, `n = vf_max / (z·fz_prog)` (drilling: `vf_max / fn`), but not below `spindle.minSpeed`. A **locked** spindle speed stays, and so does an **entered** one (it replaces only its own field, [Locked inputs](#locked-inputs)); then the chip load drops, and the [final-value check](#final-value-check) warns `feeds.rubbing` when it falls below the data range.

The agent test of 2026-11-23 (TG #232) read the old `feeds.feedClamped` warning ("Feed rate limited to the machine maximum (X/Y).", params `suggested` 6400.8, `spindleSpeed` 8436) as "the speed stayed, the chip load fell 53 %": `spindleSpeed` was already the lowered speed (from 18,000 rpm), and the chip load was kept. So DF56 changes only what the warning says:

- **Message** (unit-free, like every calculator message) says what happened to the speed and the chip load, in one of three forms:
  - lowered: "Feed rate limited to the machine maximum (X/Y); spindle speed lowered with it, so the chip load stays."
  - at the floor: "…; the spindle speed stops at the machine minimum, so the chip load drops by 23 %."
  - locked: "…; the spindle speed is locked, so the chip load drops by 53 %."
    Drilling says "Drilling feed limited to the machine maximum (Z)" with the same endings (feed per revolution instead of chip load).
- **Params:** `suggested` (the unclamped feed) and `maxFeedRate` as before; `spindleSpeed` is the speed used, `suggestedSpindleSpeed` the speed before the clamp, `chipLoad` and `suggestedChipLoad` the programmed chip load (`vf / (n·z)`, mm per tooth; drilling `vf / n`, mm per revolution) after and before, `chipLoadDrop` the drop in % (0 when kept).
- The plunge clamp (`maxFeedRate.z`) changes no speed and keeps its message.
- Presets and entered feeds are not calculated, so they are never clamped: a feed above the machine maximum is the `plan.machine` finding `maxFeedRate`.

### Finishing pass feed (hardening DF74)

Source: the first real hardwood cut ([research note](../research/2026-11-24-hardwood-tearout.md) § 1 item 4, gaps G2 and G10). The finishing pass of a pocket or profile removes only `finishAllowance` radially, so its chips are thinner than the roughing slot's (F3): at 0.2 mm on a 6.33 mm tool `RCTF` = 2.86, and the research's cavity pass at the roughing feed (3000 mm/min, 6350 rpm, 3 flutes, 0.157 mm/tooth) cut chips of 0.055 mm, under half the hardwood minimum (0.127 mm), on the surface that is seen. Before DF74 the pass ran at the operation's one `feedRate`, and no check looked at it.

**Decision: the finishing pass gets its own computed feed**, derived and never stored (no new field, no lock, no entered value, no schema change):

- `finishFeed = vf · kf / kr`, at most the machine's `min(maxFeedRate.x, .y)` (metals since DF131: also at most the feed that removes material no faster than the roughing pass, [below](#hobby-metal-cutting-hardening-df131)). `vf` is the feed rate used (entered, preset or calculator: the rule keeps _its_ chip load); `kr` is the chip-thinning factor of the roughing values (`chipThinning` of the [final-value check](#final-value-check): F3 × F5 at the slot and the stepdown used); `kf` = F3 at `ae = finishAllowance` (at most `D`) × F5 at `ap` = the finish stepdown, capped at ×3 as always. So the finishing pass makes the same chip as the roughing pass, unless the machine's feed limit stops it. The spindle speed stays the operation's (one `S` per operation).
- It needs calculator data (as the final-value check); without data, or without a finishing pass (`finishAllowance` 0), the finishing pass runs at `feedRate` as before.
- Toolpaths: `CuttingParams.finishFeedRate` (optional, mm/min) feeds every cutting move of the `finish` passes (leads, rings, links between levels); plunges stay at `plungeRate`. The post writes the `F` words as for any move. Programs with finishing passes therefore change ([Goldens](#goldens-df74)).
- Explanation: `plan.operation.feeds.get` returns `finish` (null without a finishing pass or data): `{ allowance, feedRate, chipThinning, fz, clamped }` (mm, mm/min, mm/tooth), shown in the inspector's "Show calculation" as "Finishing pass".

**Check** (`feeds.rubbing`, rule `finishRubbing`, field `spindleSpeed`): when the finishing feed is held at the machine's limit and its chip `fz = finishFeed / (n · z · kf)` falls below **half** the data minimum (`FINISH_RUBBING_FRACTION` = 0.5). The charts' minimum is for a slot at 1 × D; a light finishing pass between half the minimum and the minimum is left alone, since the finishing feed already does all the machine allows and warning there would flag nearly every wood pocket on a 3000–5000 mm/min hobby machine (the shipped v0.2–v0.4 example plans, at 0.069–0.083 mm against 0.076–0.127 mm, stay quiet). The research case, 0.055 mm against 0.127 mm ("under half the hardwood minimum"), warns. Without the clamp the finishing chip equals the roughing chip, which the final-value check already reports, so this warns only when the feed limit is what makes the finish rub. The message names the fixes that work, computed at the values used:

- a finishing allowance of at least `a` (`kf` small enough: `ae/D = (1 − √(1 − 1/k²)) / 2` with `k = vf_max / (n · z · fz_min)`), when that is below `D / 2`;
- a spindle speed of at most `n' = vf_max / (z · kf · fz_min)` (rounded down to 10 rpm), when `n'` ≥ the spindle minimum (locked in auto mode, the roughing feed follows it and keeps its chip load);
- a tool with `z' = ⌊z · fz / fz_min⌋` flutes at this spindle speed (≥ 1 and < `z`): fewer flutes, the usual answer on feed-limited hobby machines (research § 2.3).

Example (the research's cavity, 0.2 mm allowance): "Finishing pass rubs: radial chip thinning at the 0.2 mm finishing allowance leaves 0.055 mm chips, under the 0.127 mm minimum, and the machine's 3000 mm/min feed limit (X/Y) stops a faster finishing feed. A finishing allowance of at least 1.3 mm or a tool with 1 flute at this spindle speed makes a real chip." (The spindle minimum, 6200 rpm, rules out the speed fix there: it would need 2755 rpm.) Params: `chipLoad`, `minimum`, `finishAllowance`, `finishFeedRate`, `maxFeedRate`, and when they apply `allowanceForMinimum` (mm), `spindleSpeedForMinimum` (rpm), `flutesForMinimum`.

## Live vs. saved

- Suggestions are **computed live** on every plan evaluation (pure, cheap) and never stored in the plan; the UI and `plan.operation.list` show `source: 'calculator'` per field ([plan rule](../modes/plan-v0.1.md#feeds-and-speeds)).
- **Save as preset** copies the current suggestion into a new `CuttingPreset` (name e.g. "Calculated – aluminum", `materialClass` = stock's) through `library.tool.update`; the plan's tool copy updates per the [snapshot rules](library.md#snapshots). Saved values stop following data-table updates – that is the point of a preset.

## Hobby-machine realism

- **Router rpm floor:** trim routers and VFD spindles often cannot go below 8 000–12 000 rpm (`spindle.minSpeed`). Large tools in metal then run too fast (`feeds.rpmBelowMachine`); the UI suggests a smaller tool or fewer flutes.
- **Available power drops at low rpm:** VFD spindles are constant-torque below rated speed, so `Pavail = spindle.power × η × min(1, n / spindle.maxSpeed)`, `η = 0.8`. Router nameplate power is input power; `η` covers it.
- **Rigidity:** hobby frames deflect; keep chip load (thin chips rub) and reduce depth instead – see [presets](#machine-rigidity-presets).
- `spindle.control: manual`: the suggested rpm is shown as a dial hint; the export already pauses for the user ([library](library.md#machine)).

### Machine rigidity presets

`machine.rigidity` is one of six presets (lowest = default). For the router rows (wood, sheet goods, plastic) `apFactor` multiplies `apSlot` for the suggested stepdown and `rangePos` is the position within the `n`, `fz` and `fn` ranges (0 = low end, 1 = high end). For the machining rows (metals) the columns `metal ap` and `metal fz` replace them and the speed is always the top of the `vc` range ([DF131](#hobby-metal-cutting-hardening-df131)). Calibrating a machine's own factors by test cuts in Run mode is later (not v0.1).

`fixedGantry` (hardening DF36): a fixed gantry removes the cantilevered moving-gantry mass and its racking, and a solid plate frame is far stiffer than extrusions, so its stiffness (`apFactor`) sits close to a converted bench mill: 0.85. Aluminium is about half as stiff as cast iron (E ≈ 70 vs 110–140 GPa) and damps much less, so chatter limits speeds and chip loads earlier than on cast iron: `rangePos` 0.6, a step above `prosumer` (0.5) but short of `benchMill` (0.75). Users with test cuts may still pick `benchMill`.

| Preset        | `apFactor` | `rangePos` | metal ap      | metal fz    | Example                                                                                                                         |
| ------------- | ---------- | ---------- | ------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `extrusion`   | 0.3        | 0          | 0.1 (0.05 D)  | 0 (0.5×)    | 2020 aluminium-extrusion frame, printed plastic parts, belts or leadscrews.                                                     |
| `hobby`       | 0.5        | 0.25       | 0.12 (0.06 D) | 0.1 (0.55×) | Aluminium-plate gantry on heavier extrusions, V-wheels or small rails, belts.                                                   |
| `prosumer`    | 0.75       | 0.5        | 0.16 (0.08 D) | 0.2 (0.6×)  | Steel or thick-plate router frame, linear rails, ball screws.                                                                   |
| `fixedGantry` | 0.85       | 0.6        | 0.16 (0.08 D) | 0.2 (0.6×)  | Fixed gantry (moving table) on a solid aluminium plate or block frame, no extrusions, linear rails and ball screws on all axes. |
| `benchMill`   | 0.9        | 0.75       | 0.5 (0.25 D)  | 0.5 (0.75×) | Converted cast-iron benchtop mill (column and knee or bed type), ball screws.                                                   |
| `rigidMill`   | 1.0        | 1.0        | 1.0 (0.5 D)   | 1 (1×)      | Industrial cast-iron or steel mill / VMC; vendor data apply unscaled.                                                           |

`metal ap` multiplies the metal rows' `apSlot` (0.5, [HT4] slotting) and is shown with the stepdown it gives as × D; `metal fz` is the position within the metal chip-load range `[0.5 × printed, printed]` and is shown as the share of the printed value. A cheap 3020/3040/6040 router is `extrusion` or `hobby` whatever its gantry type; `fixedGantry` takes the router-frame metal values (`prosumer`) since DF131, because the user's 3020 at `fixedGantry` chattered at a stepdown of 0.17 D.

### Hobby metal cutting (hardening DF131)

Source: the first aluminium cut (TG #425, [hardening DF131](../plans/hardening.md)): a Ø6.33 mm 3-flute carbide flat end mill, a 7 mm pocket in 6061-T6, a 3020 with an 800 W spindle (6200–29 300 rpm, 3000 mm/min) set to `fixedGantry`. Both runs were stopped ("tearing metal instead of cutting it", chatter, the spindle bogging down), also after lowering the stepdown to 1.089 mm and after switching the machine to `extrusion`. Until DF131 the calculator said 9043 rpm, 1378 mm/min, 0.0508 mm/tooth and a stepdown of 1.99 mm (the power-fitted 2.69 mm) at 99.9 % spindle load (`fixedGantry`), and 7664 rpm, 1168 mm/min, 0.0508 mm/tooth, 0.95 mm (`extrusion`). The user's earlier cnc-code app (rpm from 150–300 m/min, the chip load of a 1/8″ chart × 0.6 for a hobby machine, scaled with Ø, stepdown 0.05–0.1 × D in aluminium, a warning for 3+ flutes) recommends ≈ 11 300 rpm, 0.045 mm/tooth, 1525 mm/min and 0.47 mm for the same tool.

**Root causes** (all in the metal rows, which come from machining-centre charts):

1. **Speed too low.** The conservative-envelope rule took the lowest printed `vc` maximum, 650 SFM, from [HT4]'s high-silicon castings, and `rangePos` tied the speed to the machine class, so a weaker machine got a _lower_ speed (`extrusion`: 500 SFM → 7664 rpm; `fixedGantry`: 590 SFM → 9043 rpm, the bottom third of the spindle). A low speed is not the safe side in aluminium on a router spindle: the spindle is constant-torque below its rated speed, so its power falls with the speed; at a given feed every chip is thicker (more force per tooth, more deflection); and slow carbide in aluminium builds up an edge. Hobby practice runs small tools in aluminium near the top of the spindle (16 000–24 000 rpm for Ø6 mm, [HB1], [HB2]).
2. **Chip load too high.** The metal rows had single-point chip loads (Harvey's printed value), so the class's `rangePos` changed nothing: 0.0508 mm/tooth at Ø6.33, a machining-centre value, on every machine. Hobby guidance for 1/8–1/4″ carbide in aluminium on a router is ≈ 0.02–0.05 mm/tooth ([HB1], [HB2]; cnc-code used × 0.6).
3. **Stepdown too deep.** `apSlot` 0.5 × D ([HT4], a VMC) × the class's `apFactor`, which was calibrated for router-chart wood rows (1 × D × 0.3–1): `fixedGantry` 0.425 D = 2.69 mm, `extrusion` 0.15 D = 0.95 mm. Aluminium needs ≈ 4–5 × the cutting force of wood per mm³ ([MMS]), so the same factor is far deeper in force terms. Hobby slotting guidance in aluminium is 0.05–0.25 D ([HB1], [HB2]; cnc-code 0.05–0.1 D for a 3020).
4. **The power check let the spindle run at 100 %, and under-counted.** The stepdown was fitted to exactly `Pavail` (no margin), with [MMS]'s unit power, which holds for thick chips: Machinery's Handbook's feed factor `C` is 1.6 at .001″ per tooth [MH] (Sandvik: `kc = kc1 · hm^−mc` [S1]), and a used cutter takes 1.1–1.3 × more (`W` [MH]). At the old values the real load was ≈ 1.8 × the computed one.
5. **The finishing pass was the hardest cut.** DF74's finishing feed keeps the chip, so at a 0.2 mm allowance it runs ×2.86 the roughing feed (here clamped at 3000 mm/min) over the full 7 mm wall: 0.2 × 7 × 3000 = 4200 mm³/min against the roughing slot's 2340, with 22 × the axial engagement.
6. **Three flutes in an aluminium slot** pack with chips on a router without coolant (cnc-code warned; Harvey's charts are for 2-flute tools). Not a calculator number, but a cause.

The DF56 feed clamp was not involved (1378 < 3000 mm/min). The tool's 31.7 mm stickout (5 × D) adds deflection: that is [DF130](../plans/hardening.md)'s stickout read-out.

**Rules (machining rows: aluminium, brass, steel; `MaterialRow.chart = 'machining'`).** Router rows (wood, sheet goods, plastic) are unchanged: their charts are already for routers, their `u` is aluminium's (a several-fold upper bound), and the dogfooded wood cuts (DF74) were fine.

- **Speed: the top of the `vc` range** for every machine class (derivation `vc = max (the top of the range)`), then F1 and the spindle clamp as before. Aluminium's range is 500–1000 SFM: [HT3]'s castings row (500–1000) and [HT4]'s wrought 1000 SFM; the castings' 650–750 SFM [HT4] limit tool life, not safety. Ø6.33 → 15 327 rpm; Ø3.175 → 30 560, clamped to the spindle; Ø12 → 8085 rpm.
- **Chip load: `[0.5 × printed, printed]`** (`HOBBY_FZ_SHARE`): Harvey's value is the rigid-machine top; half of it is the hobby bottom (1/8″ aluminium: 0.0127 mm, the ≈ 0.013 mm minimum chip of [HB1]). The class picks the position (`metal fz`): the four router classes 0–0.2 (0.5–0.6 × printed), `benchMill` 0.75 ×, `rigidMill` 1 ×. Rubbing / chip-load-high warnings use the new range.
- **Stepdown: `apSlot · D · metal ap`**: 0.05 D (`extrusion`), 0.06 D (`hobby`), 0.08 D (`prosumer`, `fixedGantry`), 0.25 D (`benchMill`), 0.5 D (`rigidMill`, [HT4] unscaled). Then the flute length and the power fit as before.
- **Power (F7):** `Pc = Q · u · C · W / 60 000` with `C = (0.3048 / fz)^0.19` (fit to [MH]'s feed factors: 1.60 at .001″, 1.40 at .002″, 1.0 at .012″; at least 1, at most 2; `fz` the chip after thinning) and `W = 1.25` ([MH] tool wear, 1.1–1.3). The calculator fits the stepdown (or an unlocked feed) to **`Pc ≤ 0.8 · Pavail`** (`MACHINING_LOAD_LIMIT`), and the final-value check warns above it ("Cutting power exceeds 80 % of the spindle's power: …", params `cuttingPower`, `availablePower` = the 80 % budget, `loadLimit` 0.8). The displayed spindle load stays `Pc / Pavail`.
- **Finishing pass:** `finishFeed ≤ Q_rough / (allowance · finishAp)`, with `Q_rough = ae · ap · vf` of the roughing values used: the finishing pass's mean cutting force (`u · Q / vc`) and power stay those of the roughing pass. The user's pocket: 1672 mm/min instead of 3000. The `finishRubbing` check keeps looking only at the machine's feed limit.
- **`feeds.manyFlutes`** (warning, calculator): aluminium, ≥ 3 flutes, a slot (or a facing stepover ≥ D/2) on `extrusion`, `hobby`, `prosumer` or `fixedGantry`: "A 3-flute end mill clogs with aluminium chips in a slot on this machine: use a 1 or 2 flute end mill, with air or a drop of cutting fluid." (params `flutes`).

## Recommended presets on the plan machine (hardening DF139)

Status: implemented (hardening DF139 A1–A4; accepted by delegation D87, [Q211–Q215](#questions-for-the-user-df139) take their recommendations) · Plan: [hardening DF139](../plans/hardening.md) · Finding: [X3 F5](../research/2026-11-27-x3-agent-rerun.md#f5-s3-feeds-recommended-presets-trip-their-own-checks)

**Problem.** A [recommended preset](library.md#recommended-presets) stores the calculator's values for **no particular machine** (lowest rigidity, no spindle, feed or power limit), because a library tool serves every machine. In a plan, plan mode's machine checks and the [final-value check](#final-value-check) then judge those values against the plan machine, and the plan's own recommendation warns: in the X3 rerun every hardwood operation on a 500 W spindle had `feeds.powerExceeded` (0.34–0.71 kW against 0.3 kW available), and the chamfer mill's plunge of 2,286 mm/min tripped the `plan.machine` Z max (1,500). A plan built only from the app's recommendations is never clean, and an agent cannot tell this noise from real warnings. The user's first aluminium cut ([DF131](#hobby-metal-cutting-hardening-df131)) showed why the answer must lower values and never raise them: on a weak router, too much is what breaks the cut.

### Proposal: adapt down at plan time

The library preset stays machine-free; plan mode **adapts** a recommended preset's values to the plan machine whenever it resolves one ([Q211](#questions-for-the-user-df139)). The adaptation only **lowers** values (or raises the speed into the spindle range); it never takes values from the machine's rigidity, so a preset on a rigid machine stays the conservative library value. Auto mode stays the way to get values that use the machine fully.

- **When:** the operation's cutting preset has `recommended: true` ([Q212](#questions-for-the-user-df139)) and the plan has a machine. Without a plan machine the stored values are used unchanged, as today.
- **Live, not stored:** like the calculator's values ([Live vs. saved](#live-vs-saved)), the adapted values are computed on every plan evaluation from the plan's tool copy and machine copy ([snapshots](library.md#snapshots)). The library preset and the plan's tool copy keep the stored values; a new plan machine re-adapts.
- **Entered values are not inputs** ([Locked inputs](#locked-inputs)): the adaptation runs on the preset's own values; an entered value then replaces its field, and the final-value check and the machine checks warn on it as today.

**Steps** (in this order, on canonical values; `MachineLimits` from `machineLimits`):

1. **Spindle range** ([Q214](#questions-for-the-user-df139)): `n > spindle.maxSpeed` → `n = maxSpeed` and `vf` scaled by the same factor, so the chip load stays ([DF56](#feed-clamp-and-chip-load-hardening-df56)); `n < spindle.minSpeed` → `n = minSpeed`, `vf` kept (the chip gets thinner; the final-value check's `feeds.rubbing` is then a real warning, as in auto mode).
2. **X/Y max feed:** `vf > min(maxFeedRate.x, .y)` → `vf = max`, `n` lowered with it to keep the chip load, not below `minSpeed` (the DF56 rule).
3. **Z max feed:** `plungeRate > maxFeedRate.z` → `plungeRate = maxFeedRate.z`. Nothing depends on the plunge rate, so nothing else moves.
4. **Power** ([Q213](#questions-for-the-user-df139)): with `spindle.power` set, `Pc` (F7, with DF131's `C · W` for metals) at the operation's final engagement (the strategy's stepover, the preset's stepdown) against the budget `loadLimit · Pavail` (1.0 for router rows, 0.8 for machining rows, `Pavail` at the adapted `n`). Above it: the preset's stepdown is reduced to fit, as the calculator fits its own stepdown; without a preset stepdown (single-depth chamfer or taper Lines, drilling has no power check), or when the fitted stepdown would round below 0.01 mm, the feed is reduced at the kept `n` down to the data's minimum chip load. Without `spindle.power` the step is skipped (`feeds.powerSkipped` info, as today).
5. **Round down** to the preset rounding ([library.md](library.md#recommended-presets): whole rpm, whole mm/min, 0.01 mm; inch 0.1 in/min, 0.001 in), so a rounded value never ends above a limit. The spindle speed in step 1 (below min) rounds up.

**Warnings.** An adapted preset trips none of the warnings it adapts for: no `plan.machine` feed, plunge or spindle-range finding and no `feeds.powerExceeded` from its own values. Two cases still warn, because they are real: the chip load after a raised minimum speed or a feed reduced to its floor (`feeds.rubbing`), and power still above the budget at the chip-load floor (`feeds.powerExceeded`, message "Cutting power exceeds the spindle even with the preset adapted: use a smaller tool or a shallower cut."). A value the user entered warns as today. The DF74 finishing pass is computed from the adapted values, so it follows them.

**Inspector.** The feeds fields keep `source: preset` and the preset's name; each adapted field gets a line under the field group, one per field, with the machine's name and the reason (illustrative numbers):

> Adapted for Shapeoko 4: feed 1402 → 1100 mm/min (X/Y max feed) · plunge 2286 → 1500 mm/min (Z max feed) · stepdown 0.51 → 0.38 mm (spindle power)

The tooltip shows the step's derivation (limit, power at the stored and the adapted values). The Library window's recommended-preset note adds "In a plan, adapted down to the plan's machine." Nothing else changes in the UI; "Save as preset" from auto mode is unchanged.

**Agent API** (`tools/list` budget 120,000, now 110,278). No new tool or argument. `plan.operation.list` (and `plan.get`) give an adapted field `adapted: { from, reason }` next to `source: 'preset'` (`reason`: `spindleRange | maxFeedRate | maxFeedRateZ | power`). Output schemas are not listed ([llm-api.md](llm-api.md#decisions)), so `tools/list` grows only by one sentence in `library_tool_add`'s description ("recommended presets are adapted down to the plan machine", ≈ +70 chars, ≈ 110,350). `feedsSpeeds.suggest` is unchanged.

**Code.** `adaptPreset(values, input, machine): { values, adapted }` in [`preset.ts`](../../src/core/feeds-speeds/preset.ts) (pure, headless; reuses `availablePower`, `rowCuttingPower`, `loadLimit` and the calculator's stepdown fit from `suggest.ts`); `src/core/plan/feeds.ts`'s preset branch calls it for a recommended preset (`presetValue` today reads the stored values).

**Goldens.** None expected to change. No golden plan uses a recommended preset: the CLI exit-criteria goldens (`src/main/cli/__golden__/`), the plan goldens (`src/core/plan/__golden__/`) and the toolpath goldens set their feeds by value presets, entries or auto mode, and `src/core/feeds-speeds/__golden__/tapered-ball-hardwood.json` is the machine-free calculator, which stays. `presetRecommendation` (the stored values) is unchanged, so the library tests stay. What changes: plans and exports of user projects that use recommended presets on a machine with lower limits (as intended), and the X3 plan's 5 `feeds.powerExceeded` and the chamfer plunge warning go away (as implemented: 4 of the 5 and the plunge; the countersink kept a power warning, [A4](#implementation-df139), which was the F6 model's: gone with [DF141](#plunged-chamfers-hardening-df141)).

### Questions for the user (DF139)

Numbering continues after [pattern-presets.md](../modes/pattern-presets.md#questions-for-the-user)'s Q210. "Q211 ok" takes the recommendation.

1. **Q211 – Where the machine enters.** (1) **Adapt down at plan time:** the library preset stays machine-free; a plan lowers its values to the plan machine's limits and power, never raises them. (2) Re-run the calculator with the plan machine (the preset then equals auto mode's values; on a rigid machine they go up). (3) Per-machine presets in the library (a machine id on a preset; one preset per tool × class × machine). _Recommendation: (1)._ It is the conservative side DF131 asks for, keeps one library value that the user saw and accepted, and needs no schema change ([pre-alpha: no migrations](../conventions/error-handling/migrations.md#pre-alpha-exception-no-data-preservation-yet)); (2) blurs preset and auto mode, (3) multiplies presets for every machine.
2. **Q212 – Which presets adapt.** (1) **Only `recommended: true` presets.** (2) Every preset. (3) An opt-in flag per preset. _Recommendation: (1)._ A recommended preset is the app's number, so the app owns its fit to the machine; a preset with the user's own values is the user's word, and a warning on it is right.
3. **Q213 – Power: what is reduced first.** (1) **The stepdown, then the feed at the kept speed** down to the data's minimum chip load (the calculator's order). (2) The feed first. (3) The stepdown only; otherwise warn. _Recommendation: (1)._ It keeps the chip load (thin chips rub and heat, DF56), matches auto mode, and the DF131 cut showed depth is the riskier number on a weak router.
4. **Q214 – A speed outside the spindle range.** (1) **Clamp into the range:** above the maximum the feed follows to keep the chip load; below the minimum the feed stays (a thinner chip, warned as rubbing if below the data). (2) Clamp the speed only, keep the feed in both cases. (3) Do not adapt the speed (the `plan.machine` warning stays). _Recommendation: (1)._ GRBL clamps the speed silently anyway; following the feed downwards keeps the chip, and not raising it upwards stays on the safe side.
5. **Q215 – How an adaptation is reported.** (1) **On the field:** `adapted { from, reason }` in `plan.operation.list` and a line in the inspector; no entry in `plan.warning.list`. (2) Also an info finding `feeds.presetAdapted` per operation in `plan.warning.list`. (3) Silently. _Recommendation: (1)._ The warning list should hold what needs action (X3 F5's complaint); the field says what changed and why, and agents read it where they read the value.

### Implementation (DF139)

**(A1) `adaptPreset`** in [`preset.ts`](../../src/core/feeds-speeds/preset.ts), tests in [`adapt.test.ts`](../../src/core/feeds-speeds/adapt.test.ts) (the X3 and DF131 cases, the spindle range both ways, the X/Y and Z limits, no spindle power, the chip-load floor, inch rounding, and a 400-case seeded property test: feed, plunge and stepdown never rise, the speed rises only to the spindle minimum, the spindle load never rises, the result is within every machine limit, and within the power budget unless flagged). Decisions:

- **One model for the check and the adaptation.** The final-value check's chip load and power are now `checkModel` in `suggest.ts` (`checkCutting` uses it); `adaptPreset` fits against the same model, so an adapted value cannot trip the check it adapted for.
- **Rounding keeps the chip.** When speed and feed move together (steps 1 and 2) the feed rounds down first and the speed follows the rounded feed, rounded down to whole rpm (not below the spindle minimum): the chip is never thinner than the stored one, which sits on the data minimum (lowest rigidity, `fz` position 0), so a rounding cannot add a `feeds.rubbing`. A feed reduced for power rounds down, but never below the chip-load floor (it rounds up to it instead, never above the stored feed). The stepdown floor is one rounding step (0.01 mm, 0.001 in).
- **The power step's engagement** is the operation's: the preset's stepdown, or the strategy's fallback stepdown when the preset has none (then the feed absorbs the excess), and the preset's or the strategy's stepover (facing). A drill feeds along Z, so step 2 also caps a drill's feed at the Z max (`maxFeedRateZ`).
- **One reason per field:** the last step that changed it (a feed scaled by the spindle maximum and then reduced for power says `power`). `from` is the stored canonical value; a field whose rounded value equals the stored one is not adapted.
- **The chip-load floor is the plan engagement's**, not the preset's: a chamfer cut shallower than the full cone (a smaller De, maybe another diameter band) has a lower floor, so its feed can drop. The X3 countersink (Chamfer 82 at Ø4.861, De in the ≤ 6 mm band) dropped 4572 → 2744 mm/min and still needed 0.43 kW of 0.3 kW under F6; it is plunged, so since [DF141](#plunged-chamfers-hardening-df141) its power is F12 at the plunge rate (0.24 kW at 1500 mm/min) and the feed stays. Lowering a feed under the data minimum (rubbing) is not an adaptation (Q213).

**(A2) Plan wiring.** `resolveFeeds`'s preset branch (`presetUse` in [`src/core/plan/feeds.ts`](../../src/core/plan/feeds.ts)) adapts a `recommended: true` preset when the plan has a machine (rounding in the plan's units, `FeedsInput.units`); `ResolvedFeed.adapted` carries `{ from, reason }`. Toolpaths, G-code, the time estimate and the DF74 finishing feed read the resolved fields, so they follow without further change. Outputs: `plan.operation.list` and `plan.operation.feeds.get` fields gain `adapted` (absent when not adapted); `plan.get` returns the stored plan record, which has no resolved feeds, so its agent summary (`plan_get`) lists `adapted: { field: { from, reason } }` per operation instead. With the preset's own values still above the budget at the chip-load floor, the final-value check's `feeds.powerExceeded` takes the message "Cutting power exceeds the spindle even with the preset adapted: use a smaller tool or a shallower cut." (machining rows: "… 80 % of the spindle's power …"); when any feeds field is entered the usual message stays. The `recommended` field's description (listed once, in `library_tool_add`) gained "a plan adapts them down to its machine": `tools/list` 110,278 → **110,318** (measured; budget 120,000). Tests: [`feeds-adapted.test.ts`](../../src/core/plan/feeds-adapted.test.ts) (the X3 machine and tools: the Flat 6 stepdown 1.8 → 1.6 mm with no `feeds.powerExceeded`, the chamfer plunge 2286 → 1500 with no `plan.machine` finding, an entered plunge of 2286 still warns, a user preset and an entered stepdown still warn, no machine = stored values; and the commands: `adapted` in `plan.operation.list` and `plan.operation.feeds.get`, no F5 warning from adapted operations in `plan.warning.list`). **Goldens:** every golden is byte-equal (none uses a recommended preset), as expected.

**(A3) Inspector and Library.** [`AdaptedFeeds`](../../src/renderer/src/modes/plan/AdaptedFeeds.tsx) renders one muted line under the feeds fields (above the chip load), one part per adapted field joined by " · " ([ui.md § Plan mode](../conventions/ui.md)); an entered field shows no part (its value is not adapted). Field words follow the doc's example (speed, feed, plunge, stepdown), values in the project units. Each part is focusable (keyboard users reach the tooltip, as `Term`) and its tooltip names the limit from the plan's machine copy: the spindle range, the X/Y max feed (for the speed: "The speed follows the feed, so the chip load stays."), the Z max feed, or for power the spindle's watts and the order (stepdown, then feed, down to the minimum chip load). **Decision:** the tooltip does not repeat the power at the stored and the adapted values; "Show calculation" already gives the cutting power and spindle load at the values used, and the stored values' power is not in `plan.operation.list`. The Library window's note reads "… for no particular machine. In a plan, adapted down to the plan’s machine. Editing a value unticks it." **(A4) X3 recheck.** [`feeds-adapted.test.ts`](../../src/core/plan/feeds-adapted.test.ts) § X3 recheck rebuilds the rerun plan's feeds on the X3 machine (500 W, 8,000–24,000 rpm, Z max 1,500) from recommended hardwood presets: the Bottom facing, the two partial outside profiles, the helix drilling (Flat 2) and the countersinks (Chamfer 82 at Ø4.861), the Top cavity and outline, each through `resolveFeeds` and `feedFindings`. With the preset values as the user's own (the rerun) it reproduces F5: `feeds.powerExceeded` on 5 operations (the four Flat 6 cuts and the countersink) and the countersink's `plan.machine` plunge finding. Adapted: the four Flat 6 cuts' stepdown 1.8 → 1.6 mm (power) and the countersink's plunge 2286 → 1500 mm/min clear their warnings; the facing and the drilling need no change. **Deviation from "no F5 entries" (until DF141):** the countersink kept one `feeds.powerExceeded`, with the adapted message: its feed dropped 4572 → 2744 mm/min to the chip-load floor and still needed 0.43 kW of the 0.3 kW available under F6. The countersink is plunged, so F6 at the feed rate was the wrong model; with [DF141](#plunged-chamfers-hardening-df141) (F12 at the plunge rate) it needs 0.24 kW at 1500 mm/min, the feed stays 4572 and the recheck has **no F5 entries** (the rerun's own plunge of 2286 still warns, on `plungeRate`, at 0.36 kW). The scripted check is the core test rather than an agent rerun: the plan's feeds depend only on these inputs, and the commands test (A2) covers `plan.warning.list`.

## Testing

- **Golden numbers** from published examples, each test citing its source: Kennametal KDMB ball nose D 0.312″, `ap` 0.047″ → `De` 0.223″ [K1]; Sandvik formula sheet examples for `n`, `vf`, `Pc` [S1]; RCTF at `ae/D` = 0.075 → ×1.90 [MD]. The [S1] sheet states formulas only (no worked examples), so those tests check hand-computed values against its formulas, and F7 against its `Pc = ae·ap·vf·kc / (60·10⁶)` form.
- **Properties:** `n` within machine range after clamping; `vf ≤ maxFeedRate`; RCTF = 1 at `ae ≥ D/2` and capped at 3; `De = D` when `ap ≥ RE`; power check monotonic in `ap`.
- **Data lint:** every row has a source, ranges are ordered, bands cover 0–25 mm without gaps, exactly one of `vc` and `n`.
- **Shipped-table golden cases:** 6 mm 2F carbide slotting MDF and 6061 on the `hobby` preset, 1/4″ slotting hardwood on `prosumer`: `fz`, `vc`/`n`, feed and stepdown lie within the cited chart's printed range ([ON], [AM1], [HT3], [HT4]).

## Implementation decisions (task 2.12)

Where this doc was silent, the implementation chose:

- **Material table: carbide only** ([Material data (v0.1)](#material-data-v01)). Each row lists `sources: { ref, fields }[]`; the data lint fails any value no source backs unless the row lists it in `estimated`. Logic tests use a synthetic fixture (`data.fixture.ts`); golden tests check the shipped rows against their cited charts (`suggest.test.ts`).
- **Row speed `vc` or `n`** (type extension): `vc` became optional and `n` (rpm range) was added; exactly one is set. With `n` the speed derivation is a `data` step for `n` instead of F1.
- **Engagement** is a discriminated union: `slot {}`, `stepover { ae }`, `helix { ap }` (pitch), `drill {}`; lengths are mm numbers. A fixed stepdown is `locked.ap` since task 3.14 (it was `ap` on the engagement, with a power excess that only warned; see [Locked inputs](#locked-inputs)). A drill engagement needs a `drill` tool and vice versa, else `feeds.noData`.
- **Chip-thinning cap:** the product RCTF × ACTF is capped at ×3 (so each factor is too). `ae` above `D` counts as `D`.
- **Drills** use the row's `vc` (one `vc` per `materialClass × toolMaterial`), F8 for `feedRate` = `plungeRate`, clamped to `maxFeedRate.z` (rpm lowered to keep `fn` while ≥ `minSpeed`); no power check (F6/F7 are milling formulas).
- **Plunge rate** (F9) is clamped to `maxFeedRate.z` with `feeds.feedClamped`.
- **Power reduction** scales the calculator-owned `ap` by `Pavail / Pc` (× 0.999) until `Pc ≤ Pavail` (≤ 30 iterations; Pc is near-linear in `ap`).
- **Output values** are float64 numbers in canonical units (`rpm`, `mm/min`, `mm`), not quantities: "Save as preset" (with the plan UI) turns them into quantities. Derivation steps are `{ step, formula, inputs, result, unit, sources? }` with `step` = `F1`…`F9`, `data`, `rigidity`, `fluteLength`, `power`, `rpmClamp`, `feedClamp` or `cap`; clamp and cap steps appear only when they apply. Display values: `dCalc`, actual `vc`, actual `fz` (drills: `fn`), `chipThinning`, `Q`, `Pc`, `spindleLoad` (Q/Pc `None` for drills).
- **Query** `feedsSpeeds.suggest` returns `None` as `null`; `feedsSpeeds` is a command-layer area ([commands.md](commands.md#naming)). Without a machine there are no clamps, the lowest rigidity applies and the power check is skipped.
- **Plan integration** (`src/core/plan/feeds.ts`: strategy → engagement, resolution order, `source` per field) lands with the plan model (task 2.13).

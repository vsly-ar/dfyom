## Goal

Setting up a job on the user's router takes the app, not a ruler and guesswork: the spindle can run while jogging, test cuts calibrate the machine and tools on the open stock, X/Y zero and the stock's alignment are found by probing or by touching off with assistance, the real work area and the homing repeatability are known, and uneven stock or a warped bed is probed and compensated in Z. All of it works on the virtual machine first (the emulator models what each needs) and follows [run.md § Safety](../modes/run.md#safety).

## Rules for every item

- **GRBL 1.1 states** ([grbl.md § State machine](../architecture/grbl.md#state-machine)): gCode lines (`M3`/`M5`/`S`, `G10`, `G38.x`) only in Idle: in Jog or Alarm GRBL answers `error:9` (gCode lock; the emulator already does). `$J=` only in Idle or Jog (else `error:8`). Real-time bytes (`?`, `!`, `~`, `0x18`, `0x85`, overrides `0x90–0x9D`) in any state; a feed hold during a jog cancels the jog. The host never sends a line the current state refuses (the sender treats any `error:N` as a failure that resets).
- **Probing** is `G38.2` (toward, alarm on no contact), `G38.3` (toward, no alarm), `G38.4`/`G38.5` (away) as M4 already uses ([run-machine.md § Probing](../modes/run-machine.md#probing-and-re-zero-m4)). Every probe cycle: Idle, homed, spindle reported off, the probe input **open before a toward move** (`Pn:P` absent, else refused before sending: "The probe reads as touching") and closed before an away move; distances bounded (the travel, the work area, the bed: [never into the bed](#never-into-the-bed)); positioning moves below the safe Z inside a cycle are `G38.3`, so an unexpected contact stops them without an alarm and the cycle aborts; `ALARM:4`/`5` keep the position: unlock, retract to the cycle's start, write nothing; Stop is the existing feed hold + reset.
- **Real connections:** every new motion command is `machine: true` and UI only ([run.md § Safety 2](../modes/run.md#2-who-may-command-a-real-connection-q50), Q50); on the virtual machine every source. Every probe cycle and every generated program is confirmed ([run.md § 3](../modes/run.md#3-confirmations-before-motion)); moves pass the [workholding guard](../modes/run-workholding.md#the-guard).
- **No `$x=` writes** stay ([run.md § 7](../modes/run.md#7-what-dfyom-never-does-on-a-real-machine)) unless Q219 says otherwise; DFYOM-side values (work area, probe geometry, maps) live in the library machine or the app's per-machine state.
- **Data:** new optional library machine fields, no `schemaVersion` bump (pre-alpha, [migrations.md](../conventions/error-handling/migrations.md#pre-alpha-exception-no-data-preservation-yet)). Per-machine measurements (bed map, repeatability results) are app state keyed by library machine id (like `jogFeed`, [ui.md § Settings](../conventions/ui.md#settings)), not copied into plans.
- **Agent API:** `tools/list` is ≈ 110.8 K of 120 K after hardening P11; new commands are UI-first and add no agent tool unless Q229 says otherwise (new tools follow [llm-api.md](../architecture/llm-api.md)'s rule for new tools).

### Never into the bed

The lowest Z a probe or compensated move may target is the **floor**: the bed map's surface (when one exists) or the spoilboard top from `noseToTable` and `spoilboardThickness` ([library.md § Machine](../architecture/library.md#machine)) for the tool's stickout, else the travel. A probe distance is cut to stop above the floor by 1 mm; a cycle that cannot reach its search depth says why and does not move.

## 1. Spindle control while jogging

- **Exists:** the spindle only runs inside programs (`M3 S` from the post). Overrides (`run.override.set`, M6) change speed while connected. Go to, the alignment pointer and Probe Z refuse with the spindle on (rule `spindleOn`). Jogs ignore the spindle. A hand-switched router reports nothing.
- **Gap:** no command turns the spindle on or off from Run, so facing a spot, deburring or cleaning a corner by hand needs the router switch or another sender.
- **Approach:** `run.machine.spindle { on: false } | { on: true, rpm, direction?: 'cw' }` (a `job`: `M3 S<rpm>` then the spin-up dwell `G4 P<s>` the post uses; `M5`). Machines with `spindle.control: 'gcode'` only, rpm within `minSpeed`–`maxSpeed`. **On and speed** in Idle only; during a jog the speed changes through the spindle override bytes (allowed in Jog). **Off is always allowed:** in Jog it sends `0x85`, waits for Idle, then `M5`; Stop (reset) also stops it. While it runs: jogs keep the guard (the tip may enter the stock, Q188), the jog feed switches to a separate **cutting jog feed** (Q217), Go to, the alignment step and probing stay refused, a run start sends its own `M3`. The Jog section shows "Spindle on 12 000 rpm" with an Off button; the toolbar's spindle readout turns accent.
- **Virtual machine:** has `M3`/`M5`, `FS`, the gCode lock in Jog and the override bytes; nothing new. Tests: the host never sends `M5` in Jog (cancel first), on while jogging is refused, override during a jog.

## 2. Calibration cuts (with the open stock)

- **Exists:** feeds presets adapted to the machine (DF131, DF139, [feeds-speeds.md](../architecture/feeds-speeds.md#hobby-metal-cutting-hardening-df131)); the in-process stock of the open project (cut marks, C5, [cut-state.md](../modes/cut-state.md)); workholding and the guard; Run streams only plan programs or external files ([run.md § 7](../modes/run.md#7-what-dfyom-never-does-on-a-real-machine)).
- **Gap:** no way to check what the machine and tool really cut (tool diameter, X/Y scale, backlash, Z depth) or whether a feed is too aggressive before the real part, and no place to put the answer.
- **Approach (Q221, Q222):** a "Calibration cut" dialog in Run for the open plan's setup: pick a test, pick a free spot on the stock's top (the Run scene shows the stock with its cut state and items; the spot must avoid the part's operations, cut regions and items), see the program and its time, run it through the normal pre-flight. Tests: **dimension** (a square pocket, a square boss and a slot of nominal sizes with the chosen tool; the user enters caliper readings → effective tool Ø, X/Y scale error as a `$100`/`$101` hint, backlash hint from inside vs outside sizes, depth error), **feed ladder** (short slots at stepped feed or depth around the preset; the user rates each → a preset adjustment offered). Results are suggestions the user applies (tool's measured Ø, the preset), never silent. Programs come from the existing generators and post on the setup's frame ([grbl.md](../architecture/grbl.md#post-processor-task-211)).
- **Virtual machine:** nothing new; the deviation simulation ([deviation.md](../modes/deviation.md#height-map-method)) checks that the test program cuts only the chosen spot.

## 3. A settings section

- **Exists:** app settings with a Run group (jog keys, homing confirmation, auto-reconnect; [ui.md § Settings](../conventions/ui.md#settings)); machine fields in the Library window (plate thickness and size, holder, travel …); the connect-time `$$` check with its diff ([run-machine.md § Settings check](../modes/run-machine.md#settings-check)); no raw `$` lines.
- **Gap:** what the items below need (probe geometry, probing feeds and distances, work-area margins, cutting jog feed, bed map) has no home, and the controller's `$$` is visible only as differences.
- **Approach (Q218, Q219):** a collapsed **Machine** group in the Run inspector for the connected (or chosen) library machine: Probe (kind, plate thickness, XY wall offsets, plate size, 3D probe tip Ø, probe feeds fast/slow, retract), Work area (bounds, margin), Jog (cutting jog feed), Surface (bed map: date, grid, flatness; Re-probe, Clear), Homing repeatability (last result). Edits write the library machine (one `library.machine.update`, undo as in the Library window); per-machine measurements stay app state. A read-only **Controller settings** table: every `$$` line with its name, unit and the machine field it maps to, differences marked.
- **Virtual machine:** `$$` exists; nothing new.

## 4. X/Y probing

- **Exists:** Z probing with a plate (M4, `G38.2`, `[PRB]`, `ALARM:4`/`5` handling, modal restore); the emulator's probe is a horizontal plane only ([grbl.md § Probing](../architecture/grbl.md#probing)); the alignment proposal's phase 2 planned X/Y cycles ([P1–P4](proposal-multi-setup-alignment.md#3-phase-2--probing-as-an-alignment-aid)).
- **Gap:** no edge, corner or hole cycle, no probe model beyond plate thickness, `Pn:P` not read for a probe check.
- **Approach (Q220):** probe kinds as machine fields: `zPlate` (today), `xyzPlate` (corner plate: thickness, X and Y wall offsets), `tool` (the bit itself against an edge or the plate's side, its measured Ø), `3d` (touch probe, tip Ø). Cycles, each a host `job` from one `run.machine.probe { cycle, … }`: **edge** (X±/Y±: fast `G38.2`, back off with `G38.4` until open, slow `G38.2`, retract), **corner** (Z on the plate top, lift, step out with `G38.3`, down, X, lift, Y), **hole or boss centre** (3d only: four directions, then re-centre), **Z surface** (today's Probe Z). Results in machine coordinates with the probe's radius and wall offsets applied; what they write is the next items' choice. A **Test probe** indicator shows `Pn:P` live so the user checks the clip before the first cycle.
- **Virtual machine (RV3):** a **probe scene** replacing the plane: the tool or probe tip as a cylinder (or ball) of radius r, contacts with boxes (stock, rotated by an angle), an XYZ plate on a stock corner, a hole, and a height field; `Pn:P` while closed; a hook for "already touching". Contact latch and deceleration stay as today.

## 5. Explore the real work area after homing

- **Exists:** the travel `[−travel, 0]` from `$130–$132` bounds jogs, Go to and the run's soft-limit check; the scene draws it ([run.md DF33](../modes/run.md#machine-coordinates-and-the-homing-corner-df33)); continuous jogs stop at the travel edge.
- **Gap:** the reachable, useful area is often smaller (the spindle body meets the gantry, a fixture plate ends, a wire) or `$130–$132` is wrong; nothing records it, and margins are fixed at zero.
- **Approach (Q223):** after homing, an **Explore work area** panel: the user jogs slowly to each end of X, Y and Z (the jog pad, the cutting-free feed) and presses "Mark X min" … at the last safe point; DFYOM shows the marks against the travel. Saved as the machine field `workArea` (bounds per axis in machine coordinates) and `workAreaMargin` (default 2 mm, per side editable). Used by continuous jogs (stop at the area minus the margin), Go to, probing distances, the run's soft-limit check and Plan's fit check (stock and toolpaths in the area); GRBL's soft limits stay the outer bound. A mark beyond the travel says "Your machine reaches 412 mm in X; the controller allows 400 ($130). Raise $130 with your controller's tool to use it." (no write, Q219).
- **Virtual machine:** an option `reach` (an obstacle box inside the travel that raises a hard limit, for the "stop before it" e2e); otherwise nothing new.

## 6. Test homing repeatability

- **Exists:** homing on real controllers (DF87), Probe Z with `[PRB]` in machine coordinates.
- **Gap:** no way to know whether homing returns to the same place, which every map, stored work area and repeated zero relies on.
- **Approach (Q224):** a guided test: put the plate (or the XYZ plate, or a 3D probe target) somewhere fixed on the bed, home, probe it once to learn where it is; then N cycles (default 5): `$H`, move above the target, probe Z (and X, Y with an XYZ plate or 3D probe), store the contact MPos. Result per axis: spread (max − min) and standard deviation, pass under 0.02 mm (Q224), stored with the date per machine and shown in the Machine group. A second mode compares before and after a run (lost steps). Every cycle confirmed once for the whole test; Stop ends it.
- **Virtual machine:** homing switch scatter (option `homingScatter: { x, y, z }` mm, seeded) and a `loseSteps(axis, mm)` fault, so the test reports the injected spread.

## 7. Assistance setting the work zero in X/Y

- **Exists:** `run.workZero.set` per axis at the current position (`G10 L20 P1`, "=0"), "Zero on this point" in the alignment step, the free setup zero (Q61: the plan's zero may be anywhere, even off the stock); Go to; the guard.
- **Gap:** the plan knows where its zero is relative to the stock's edges, but the operator still has to put the tool exactly there by eye.
- **Approach (Q225):** a **Set X/Y zero** dialog for the plan's setup: the setup picture with the stock's edges and corners; pick an edge or a corner, pick the method: **probe** (item 4's edge or corner cycle) or **touch** (jog the tool against the edge, a paper or feeler thickness, press "Touching"). DFYOM writes `G10 L20 P1 X<…>` so the edge lands where the plan's setup puts it (edge position in WCS ± the tool or probe radius ± the feeler), whatever the plan's zero is; a corner sets X and Y. Without a plan: "this edge is X = value". The tool's Ø comes from the tool in the spindle (Q189's rule) and is editable (a measured Ø from item 2). A changed G54 clears the alignment ticks as today.
- **Virtual machine:** item 4's probe scene; the touch method needs a contact readout: the scene reports the tool touching the stock box (test hook only; a real operator feels it).

## 8. Checking the stock's alignment in X/Y

- **Exists:** the alignment step (DF78: the spindle as a pointer visiting alignment points at the clearance height, ticks, the confirm gate; [alignment.md § Run](../modes/alignment.md#run-the-alignment-step)) through the guard (RW6); Go to. The user rejected rotating the program (Q65 withdrawn): the stock is moved, not the program; skew compensation stays out.
- **Gap:** a plain stock has no alignment points; checking that it is square to the axes means jogging along its edges by hand.
- **Approach (Q226):** a **Check alignment** panel after the X/Y zero, with patterns built from the setup's stock outline: **corners** (the pointer above each corner, Next/Previous, like the alignment step), **edges** (above both ends of each edge), **perimeter** (a continuous trace of the outline offset outward by a gap, 2 mm default, at a sighting height: just above the top, or beside the edge below the top when the guard allows), and **both**. Moves are jogs (`$J=`), so release, jog cancel and Stop end them; continuous traces run at a slow feed (500 mm/min) and pause at corners. With a probe, **Measure** probes two points on one edge and reports the angle and the nudge ("Back right corner 0.6 mm toward X−"); nothing is rotated or written.
- **Virtual machine:** a rotated stock box in the probe scene (item 4) for Measure; pointer moves need nothing new.

## 9. Surface probing: stock and bed maps

- **Exists:** Probe Z at one spot; the touch-off spot and Z reference (DF69); "height map" as a simulated-cut grid ([deviation.md](../modes/deviation.md#height-map-method)); the post's resume input (`ExportInput.resumeFrom`) as the pattern for a Run-time program variant.
- **Gap:** warped stock or an uneven spoilboard makes engravings, V-carves and through-cuts in thin sheet uneven; nothing measures or compensates it.
- **Approach (Q227, Q228):**
  - **Probe a map:** a rectangle (the program's extent plus a margin by default, or the stock top; the work area for the bed) and a grid (spacing or count, 3 × 3 to 30 × 30, a time estimate). Per point, serpentine order: `G0` to X/Y at the safe height (the previous contact + clearance), `G38.2` down to the [floor](#never-into-the-bed) bound, record, retract. A failed point stops the map and keeps the measured points (Retry from there). The surface must be conductive for a clip on the bit (aluminium, a foil); wood and MDF need a 3D probe (Q220).
  - **Stock map:** per setup and connection, in the work frame; dropped when G54 X/Y changes or the stock is replaced. **Bed map:** per library machine, in machine coordinates, reused across sessions (valid on a homed machine; item 6 says how far to trust it), with its date; re-probe or clear in the Machine group.
  - **Compensation in the post:** `ExportInput.heightMap` makes the post (a) linearise arcs inside the map's area, (b) split every feed move below the clearance height into segments of at most half a cell (and ≤ 2 mm), (c) add the bilinear offset `dz(x, y) = interp(x, y) − interp(x₀, y₀)`, anchored at the Z touch-off spot (x₀, y₀) where Z0 was set, so Z0 stays exact there. Rapids at or above the clearance height are unchanged (the clearance must exceed the map's range). Run re-exports the plan's program with the map before streaming, as resume does, and re-runs the soft-limit and workholding checks; a program outside the map plus one cell is refused; the pre-flight shows the map, its range and max |dz|. Maps with a range over 3 mm warn.
- **Virtual machine:** the probe scene's height field (a tilt plus bumps, seeded); the oracle: the trace's tool tip depth below that surface stays within 0.02 mm of the programmed depth along a compensated engraving.

## Exit criteria

- On the virtual machine, one hidden e2e per slice passes; the emulator's probe scene, scatter and height field are deterministic (seeded) and covered by tests.
- On the user's machine: spindle on while jogging and off from a jog; X/Y zero set on a stock corner by probing or touching within 0.05 mm of the caliper check; a perimeter check; the work area recorded; a homing repeatability result; one engraving on a deliberately shimmed stock with a stock map, its depth even within 0.1 mm.
- No `$x=` write, no agent motion on a real connection, `tools/list` ≤ 120 K.

11. **Q226 – Alignment check.** (1) **Corners, edges, a perimeter trace with a gap (2 mm, above the top by default) and both, as guarded jogs at 500 mm/min with pauses at corners; with a probe, Measure reports the angle and the nudge; never rotates the program (Q65).** (2) Corners only. _Recommendation: (1)._
12. **Q227 – Applying a map.** (1) **In the post at stream time (`ExportInput.heightMap`): segments ≤ half a cell and ≤ 2 mm, arcs linearised, bilinear dz anchored at the Z touch-off spot, rapids above clearance untouched, refused outside the map; plan programs only.** (2) In the sender on any streamed lines, external files too. (3) Measure and report, no compensation. _Recommendation: (1);_ (2) changes text the user exported and cannot run DFYOM's checks on it.
13. **Q228 – Bed map reuse.** (1) **Stored per library machine in machine coordinates with its date; used when you tick "Compensate with the bed map" in the pre-flight (thin sheet on the bed) and always as the floor for probing; re-probe or clear in the Machine group.** (2) Applied to every run automatically. (3) A flatness report only. _Recommendation: (1);_ thick stock does not follow the bed, so automatic use would be wrong more often than right.
14. **Q229 – Agent API.** (1) **No new agent tools: the commands are UI-first (real machines are UI only anyway, Q50); agents read results through `run.status.get`.** (2) One `run.machine.probe` and one `run.machine.spindle` tool, useful on the virtual machine only (≈ 0.8 K of the ≈ 9 K left). _Recommendation: (1);_ on a real machine agents could not call them, and the headroom is better kept for modelling features agents do use.

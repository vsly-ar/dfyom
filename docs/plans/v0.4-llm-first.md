## Source

The black-box test of the installed app 0.3.2 over MCP (2026-11-22; the report is the local research note `.continuous/research/2026-11-22-llm-first-test.md`, not in the repo): an agent with the user docs and the MCP tools planned the user's enclosure base from 250 × 200 × 40 mm hardwood with toe clamps. It got there only with its own scripts: an STL slicer for every depth and hole (F1), a G-code clamp check after the first bottom program **rapided through a clamp at Z1** (F2), an offset script for inset outlines (F6) and a Z-map for the deviation (F4); two toolpaths failed with raw stack traces at specific offsets (F3); results were huge (F5: `plan_toolpath_get` 7.45 MB, every edit returning all DFM warnings twice). This milestone closes those gaps so the same task runs with the app alone.

## Questions for the user

Each with a recommendation; "Q37 ok" takes it. Numbering continues after the v0.4 plan's Q35. Every open one is now settled: answered by the user, or its recommendation **accepted by delegation (D70)** on 2026-11-26 (the user can veto).

0. **Q36 – Slot. Answered** (user, 2026-11-22): after v0.4, before v0.5, as this "v0.4 follow-up". The [v0.4 features plan](v0.4.md) is unchanged (accepted, D34).
1. **Q37 – Workholding lives on the plan setup,** as inline items (toe clamp, vise, screw, block, base, surface) with built-in defaults; a workholding library tab later. _Recommendation: yes._ Why: what holds the stock depends on the setup, not the part; a library adds UI and snapshot work without changing a single check ([workholding.md WH-A](../modes/workholding.md#decisions)). **Answered** (user, 2026-11-24, TG #270, with Q38–Q40); built in hardening DF59.
2. **Q38 – What a keep-out does.** Region operations (pocket, facing) clear around the keep-out zone and report the uncut area; a profile, groove or drilling that would cross one is an error that blocks the export (no automatic skipping or tabs under clamps). _Recommendation: yes._ Skipping part of a profile would leave the part attached in a way nobody chose. **Answered** (2026-11-24).
3. **Q39 – Safe heights.** Links and rapids inside an operation **hop up and over** a clamp; the clearance height defaults to the highest item + margin (2 mm); the retract height stays low. A user clearance below the highest item is an error. _Recommendation: yes._ In the test, raising the retract height everywhere cost +120 s; hops cost seconds. **Answered** (2026-11-24); hops inside an operation wait for [safe-links.md](../modes/safe-links.md) L4, the collision check already blocks the export.
4. **Q40 – Tool envelope for the collision check:** a conservative cylinder of max(cutting Ø, shank Ø) from the tip upward; holders and collet nuts later with a machine holder model. _Recommendation: yes._ **Answered** (2026-11-24).
5. **Q41 – Agent API and `tools/list`.** Three new tools (`plan.workholding.set`, `design.reference.find`, `design.reference.compare`) and union growth in existing ones (`from` on `design.shape.import`, the `offset` item, `scale`, profile `depth`): ≈ 5 K characters, on top of v0.4's raise to 120 K (Q32 → A, D34). Plus result compaction (F5), which matters more than schema size: no stack in results, warnings as a delta with a count, `detail: 'summary'` on `plan.get`, `plan.toolpath.get` and `design.shape.get`. _Recommendation: yes; measure after v0.4 and raise to 130 K only if v0.4 used its headroom._ **Premise changed:** the three tools and compaction shipped in hardening (DF59, DF60, A1); `tools/list` is 111.2 K of 120 K ([llm-api.md](../architecture/llm-api.md#implementation-task-310), after P11 and E4) and the rest here adds ≈ 1 K. **Accepted by delegation (D70):** stay at 120 K, no raise.
6. **Q42 – Async queries.** Reference queries run in the compute worker, but queries are synchronous ([commands.md § Queries](../architecture/commands.md#queries)). Options: **A** an async query kind (no queue, reads the snapshot, may call workers; one call for the agent); **B** make them jobs (two calls: start, `job.wait`). _Recommendation: A_, with an ADR (0021) in the llm-api amendment. **Answered** as hardening Q72 (A, [ADR 0021](../decisions/0021-async-queries.md), built).
7. **Q43 – Deviation check scope:** sources = the evaluated part and the simulated cut (Z-map per setup direction); methods = height map and sections; a job with statistics and up to 20 regions with causes; the viewport colour map later. _Recommendation: yes._ **Accepted by delegation (D70)**, narrowed to the plan source: the part source is [reference-tools.md § Compare](../modes/reference-tools.md#3-compare) (DF60, built).
8. **Q44 – Exit numbers** ([Exit criteria](#exit-criteria)): 0.5 mm cells, p95 |dev| ≤ 0.05 mm and p99 ≤ 0.1 mm outside the edge band, every region over 0.5 mm with a cause; no workholding collision and ≥ 2 mm from every clamp by an independent G-code oracle; ≤ 100 tool calls and no result over 64 KB in the scripted flow. _Recommendation: yes; X0 measures the numbers on the fixture first and may tighten them._ **Accepted by delegation (D70).**
9. **Q45 – Small ones in scope:** partial-depth inside/outside profiles (rabbet), `job.wait` returning at operator waits, frames in the server primer + a WCS line in the program header + `placed` bounds in operation results, DFM checks skipped in waste, region offset robustness without stack traces (F3), the launcher documented and in Help (F11), unknown-arg hints (F13). Out: drilling with several centres (F12), `design.warning.ack`, estimate tuning (F14). _Recommendation: yes._ **Accepted by delegation (D70);** all but DFM in waste already built in hardening (DF53 profiles, B2 offsets, A1–A5).
10. **Q46 – Offset and scale:** offset is a shape item that references another shape and follows its edits (regions only, round corners); `scale` on the `named` placement. _Recommendation: yes_ ([design-llm-first.md](../modes/design-llm-first.md#decisions)). **Accepted by delegation (D70).**

## Exit criteria

The test part is the black-box test's: the user's `enclosure-wood-base.stl` (fixture `src/core/design/__fixtures__/enclosure-wood-base.stl`) from a **250 × 200 × 40 mm hardwood** block, held by **four toe clamps** on both setups: edges `vMin` and `vMax`, at u = 45 and 205, width 30, grip 10, top 25 mm. **No SVG fixture**: every dimension comes from the app.

- **Headless, scripted ([X1](#9-acceptance)):** through `dfyom mcp` and `dfyom batch`, a script that may use only values returned by the tools (the test asserts each design value is read from a `design.reference.find` result or comes in through `design.shape.import { from }`): stock and reference; `levels` from top and bottom; outline and cavity by section → shape; the bottom steps as partial-depth outside profiles of offset items; the four holes from `holes` as countersunk [hole features](../modes/design-v0.4.md#hole-feature) (v0.4) at the detected diameter, depth and mouth; `plan.workholding.set` on both setups (`copyFrom` for the second); plan, generate, no error findings, no `plan.workholding.collision`; export both setups; an **independent G-code oracle** (test code, true arcs) finds every move ≥ 2 mm from every clamp; virtual run of both setups with tool changes through `job.wait` → `run.job.continue` as the result says; `design.reference.compare` with the plan source: the [Q44](#questions-for-the-user) numbers; the same with the part source. Also: ≤ 100 tool calls, no single result over 64 KB, `tools/list` within the budget.
- **In the app ([X2](#9-acceptance)):** hidden windows; the same part through the UI: "Section to shape" in the Shape Editor, "Offset…" on the outline, the clamps added and dragged in the Plan viewport (a deliberately low clearance shows the collision in red and blocks Export until fixed), deviation results shown in the panel; exports byte-equal to X1's goldens.
- **A real agent ([X3](#9-acceptance)):** the black-box test repeated with a fresh agent, the installed app and the MCP tools only, **no outside scripts and no file reads but the STL**: it finishes the task and the app's own deviation check meets Q44's numbers, with zero collision findings. Recorded as a dated research note like the source report; not in CI.
- `npm run check` and the e2e suite green in CI.

**Q44 measured (X0, slice LF4, 2026-11-26)** on the black-box test's saved programs against the STL ([deviation.md § X0](../modes/deviation.md#x0-q44-measured-on-the-black-box-tests-programs)), 0.5 mm cells: p95 |dev| outside the edge band 0.005 mm (top) / 0.001 mm (bottom) against ≤ 0.05; p99 0.005 / 0.001 against ≤ 0.1 (the same at 0.25 mm). **Missed by 8 regions:** every region over 0.5 mm should have a cause, and the four drilled holes do not: the 2.5 mm drill's point passes the 0.241 mm the reference leaves between the hole ends and the cavity floor by 0.374 mm (a pinhole into the cavity at each hole, seen from both faces), a real defect of those programs, not of the check. Thresholds unchanged; X1 measures its own programs.

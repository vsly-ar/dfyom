## Exit criteria

The test part is the user's reference `enclosure-wood-base.stl` ([X1 of v0.2](v0.2.md#6-acceptance)), recreated **with its real outline** instead of rectangles. Measured from the STL: 249.5 × 177 × 39 mm; an oval outline with no straight sides (close to a superellipse of exponent 2.5); an oval cavity 235 × 159.4 mm (walls 7.2 mm at the sides and front, 10.5 mm at the back) down to a 4.2 mm floor; four Ø ≈ 3 mm blind holes ≈ 3.9 mm deep in the bottom at (±88.5, ±44.3) mm from the centre; a ≈ 4 mm bevel round the bottom edge. The bevel needs a chamfer operation (after v0.3, [features.md](../modes/features.md)) and is left out. A test-only SVG of the two sections (`enclosure-sections.svg`, cubic Béziers, generated once from the STL and committed) stands in for the drawing a user would have ([Q27](#decisions-to-settle-first)).

- **In the app** (the golden path, [X2](#7-acceptance)): new project, 255 × 185 × 40 mm board; import the STL reference and fit it; **Import SVG…** the sections: the report shows two shapes, Béziers fitted to arcs and the deviation; snap a point to the reference section and measure the back wall (if Q23 holds); in the Shape Editor build a **cable notch** from an obround and a rectangle (a boolean) and rotate it; operations: facing on top; the cavity as a pocket on the facing floor; the notch as a pocket across the back wall; the outline as an outside profile with four tabs placed along the path and a locked library tool; four drillings on the bottom; an `on` groove along an open path on the bottom (if Q24 holds); Apply. Plan derives two setups (bottom, top); generate; the top program has `G2`/`G3` along the oval; export per setup; run both on the virtual machine. Save, close, reopen: shapes, placements, tabs unchanged.
- **The same flow headless** through MCP and `dfyom batch` ([X1](#7-acceptance)), including `design.shape.import` and `design.shape.add`, with golden programs; and a **deviation check** (test-only): the evaluated part's section at mid-wall height lies within 0.2 mm of the reference's section (outline and cavity).
- ADR 0019 accepted; the spike fixtures run as 2D port regression tests.
- `npm run check` and the e2e suite green in CI.

## Risks and spikes

| Risk                                                                                    | Mitigation                                                                                                                                                                                                           |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| v0.3 is larger than v0.2: a 2D kernel, an importer, two generators, an editor, snapping | Cut line if needed, in this order: U3 (measure and snap) → the blind/open `on` groove → `polygon`/`obround` items; never K1–T3.                                                                                      |
| Offset clearing of arbitrary regions leaves cusps or slow paths                         | S4 first; heightmap oracle in T1/T3; adaptive clearing stays later                                                                                                                                                   |
| Labelled caps with holes too slow or sliver-prone at 2000 elements                      | S3 done: caps are not the cost; crossed-face re-triangulation is → tile stock faces; 2000-element shapes take 47–115 ms (decide: documented limit or coarser chords); slivers gone with float64 part-frame placement |
| CavalierContours' touching-island defect (ADR 0019)                                     | `normalise` before every offset; the spike fixture as a regression test; report upstream                                                                                                                             |
| The renderer cannot compile the WASM synchronously (Chromium 4 KiB limit)               | Instantiate asynchronously at window start ([shapes.md](../architecture/shapes.md#where-the-2d-layer-runs))                                                                                                          |
| `tools/list` budget (100 K): about eight new tools and a large item union               | One `$defs` item union; measure in K2; group by area if needed ([llm-api.md](../architecture/llm-api.md#implementation-task-310))                                                                                    |
| Wall ids of shape operations renumber after edits                                       | Not referenceable by design (S-J); DFM markers carry `[u, v]`, not ids                                                                                                                                               |
| Rest-material checks per candidate tool make Apply slow on big parts                    | Cached per (region hash, tool radius); measured in K4                                                                                                                                                                |
